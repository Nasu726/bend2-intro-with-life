# 第3章補稿・演習の解説（編集用／読者ZIPには含めない）

## 1. filterとfoldl

`small(n) = Nat.is_lt(n, 2n)` とすると、`List.range(4n)` のうち
残るのは `0n` と `1n` だけです。初期値が `0n` のままなら結果は
`1n`、初期値を `5n` に変えれば `6n` です。

大切なのは、`filter` が要素を選び、`foldl` が初期値を含めて
左から演算する、という役割の違いです。

## 2. Array.newの深さ

`Array.new(U32, 2n, 0)` の要素数は `2^2=4` です。
有効な添字は0、1、2、3です。元のコードが使う添字7は範囲外です。
この例の構造がどういう振る舞いをしても、`Array` の低水準処理に
「ゲーム盤面の範囲外を必ず拒否する」責務を与えてはいけません。
ユーザー入力からの更新なら、先に添字を検査する必要があります。

## 3. Array.cloneの独立性

複製した二つの配列を `left` と `right` と呼ぶと、
それぞれへ異なる値を設定した場合、読み出し結果は
**対応する複製に対して設定した値**になります。
同じ内容から始まった配列でも、更新後の状態は独立です。
`Array.fork` に対して同じことを根拠なく期待しないでください。

## 4. Listで盤面を表す場合

`List` の先頭から対象の添字まで辿り、前後の要素を保ちながら
対象位置だけを変更する必要があります。番号で直接位置を指定する
既存の `Array.set` に比べ、更新対象を探す処理が増えます。
盤面の表示を順番に集計する場合には `List` も自然ですが、
クリック位置に応じた状態更新には `Array` が扱いやすいでしょう。

**注**：ここでは設計と予想を解説しています。標準ライブラリの
実際の返り値と数量の指定は利用中のBend 2に合わせ、
`bend base` で確認してください。
