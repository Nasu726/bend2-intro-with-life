# 第21章：CLIリプレイ実習の参考解答

このファイルは編集用・解答確認用であり、読者配布ZIPには含めません。

## 操作の予想と結果

この実習の初期地雷マスクは `33`（番号0と5が地雷）です。
最初に `c0` を実行すると、初手安全のため番号0の地雷は番号1へ移動します。
番号0の周囲には番号1・5の地雷があるので、番号0には `2` が表示されます。

| 操作列 | 期待する結果と理由 |
| --- | --- |
| `c0 f1 f1` | 番号1の旗を付けて外します。盤面の先頭行は `2 . . .` になります |
| `c0 c1 f2` | 番号1の地雷で敗北し `Lost` になります。終了状態では追加の旗操作を受け付けません |
| `c0 c16` | 添字16は盤面外なので無視され、`c0` の表示のままです |
| `c0 r` | リセット後の `Fresh: first click with c0..c15` に戻ります |

`F` を `#` などへ変えるのは `cell_symbol` に閉じた**表示形式だけの変更**です。
`Session.mark` や `Session.click` は `Square` の値を操作し、
`cell_symbol` は最後の表示でその値を文字列へ写します。
したがって地雷の移動、勝利判定、旗の操作規則を変える必要はありません。

## 実装上の限定

`cli_replay.bend` は `IO.args` を読み、一回の実行で引数として渡された操作列を再生するプログラムです。
入力待ちの対話式CLIではありません。予期しない操作・不正な数字を無視する設計であり、
ユーザーにエラーメッセージを出す高度な入力検証は次段階です。
地雷配置は固定で、乱数生成、保存/復元、GUIもこの例には含みません。

## CLI操作履歴の保存と復元

- `save c0 f1 f1` は、初期状態33から番号0を安全に公開し、番号1の旗を立ててから外す履歴です。読み戻すと番号0には2が表示され、番号1は再び隠れています。
- `BEND2-SAVE-1|c0|f1|END` の `END` を消したり、バージョンを変更したりすると `cli_save.bend load` は失敗します。条件を満たさないデータを正しいゲーム状態として扱ってはいけません。
- `File.open` が成功して得た `File` は一度ずつ利用する必要があります。書き込みが失敗した場合も `File.close` を呼び出し、ハンドルが残ったまま次の操作へ進まない設計とします。
- 保存できるのは固定初期盤面の操作履歴です。GUIのゲーム状態を保存する完成版とは混同しません。
