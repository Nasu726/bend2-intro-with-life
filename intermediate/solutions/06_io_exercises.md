# 第6章補稿・演習の解説（編集用／読者ZIPには含めない）

対応原稿：[`IOと失敗を読む`](../manuscript/06_IOと失敗を読む.md)

## 1. 引数の長さは純粋な計算

`IO.args()` は実行環境から引数を取得するため `IO` の処理です。
それが `List<String>` として得られた後は、`List.length`
自体は純粋関数として呼べます。引数を取得する仕事と、
得られたリストの長さを数える仕事を分けています。

## 2. 環境変数が得られない場合

`19_environment.bend` の `env_length` は `Fail` に対し
`0n` を返します。これは「失敗を0として集計する」と設計した
結果です。失敗の理由を上位へ伝えたいなら `Result` を保持して
返す設計が必要です。0が正しい値としても現れる場面では、
数値だけでは失敗と成功を区別できません。

## 3. File.closeを削除すると

書き込みが失敗した場合でも、取得した `File` ハンドルを
適切に後始末する責務が残ります。終了処理を削ると、
アフィンなハンドルの扱いに違反し、型検査で検出される可能性があります。
仮に他のコード経路で型が通っても、ファイルを開いたままにする設計は
リソース管理上問題です。`IO.die` の前に `File.close` を
実行する理由を確認してください。

## 4. 保存データのテストとファイルのテスト

まず盤面を文字列へ変換する純粋関数なら、ファイルシステムなしで
期待する文字列と比較できます。その後、実際に `File.write` で保存し、
`File.read` で読み戻して照合します。前者が成功しても、
後者では権限・存在・ファイル内容などの外部条件で失敗し得ます。
両者を別々に検査することが重要です。

**注**：実際のアクセス権エラーやディスク容量不足については、
現行サンプルのCIは網羅していません。
