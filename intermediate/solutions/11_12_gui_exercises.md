# 第11・12章：ImageとGUIへの接続（編集用・読者ZIPには含めない）

## 第11章：色の移動と四分木の深さ

`31_image_quadrants.bend` の左上を青（255）に変えると返り値は255です。赤い `Pix` を右下へ移し、左上を黒（0）にすると `top_left_color` の返り値は0です。画面を描画していなくても、木の左上経路を読む純粋関数の結果を検査できます。

## 第11章：四分木の深さ

`Qua`を3段重ねると一辺8個の`Pix`領域になります。4×4マスを表すにはさらに2段が必要で、一辺は`4 * 8 = 32`領域です。256画素のウィンドウでは一領域が8×8画素になります。最下層の`Pix`が必ず1画素であるとは限りません。

## 第12章：小さなGUIのイベント

`07_gui_hello.bend` は `Close{}` で `None{}` を返して終了し、それ以外のイベントでは色を増やして続行します。クリックだけに反応する例ではありません。`32_mouse_events.bend` の `main` 内で最初の `Mouse{64,32,0,True{}}` を `False{}` に変えると、押下ではなくなるため `None{}` が返り、合計は0です。

## 第12章：4×4座標とイベント

`gui.bend`は一マス64画素です。添字は`(y / 64) * 4 + (x / 64)`（盤面内のみ）なので、`(63,63) -> 0`、`(64,63) -> 1`、`(0,64) -> 4`、`(255,255) -> 15`、`(256,0) -> None`、`(0,256) -> None`です。右端の`x=256`を有効にすると添字が別のマスへずれる危険があります。

右クリックを左クリックとして扱うと、旗を置くつもりで地雷のあるマスを開き、敗北してしまう可能性があります。未知のボタンを左クリックへフォールバックさせないことが重要です。`down=False`のイベントでも更新すると、一度の操作で複数回の遷移が起きる危険があります。

`Array.clone`は、元の`Array`を次の`Start.Stage`へ戻すための分と、`Array.to_list`へ渡す表示用の分を用意します。複製なしで`Array.to_list`へ消費すると、後続の`tick`が使う配列を保持できません。画像を組み立てる関数は隠れた地雷位置を直接描画してはいけません。

**検証範囲**：`gui_smoke.bend`の13件は入力・座標・状態遷移などのヘッドレス検査です。実機のウィンドウ表示、GUI上での勝敗操作、GUI状態の保存・復元を証明するものではありません。
