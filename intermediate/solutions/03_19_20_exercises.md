# 第3・19・20章の追加演習解説（編集用／学習用ZIPには含めない）

## 第3章：ListとArray
- `40_list_map.bend` の `plus_one` を「2を足す」にすると、入力 `[1,2,3]` は `[3,4,5]` となり、合計は12です。
- `38_list_sort.bend` は `[7,2,4]` を `U32.is_le` で昇順に並べ、先頭2を返します。降順の比較にすれば先頭は7です。比較の意味とソート結果は別々に確認しましょう。
- `39_array_to_list.bend` は深さ2の配列なので4要素です。初期値はすべて1で、最初の要素のみ7に変えてから `List.foldl` で集計するため、結果は10です。
- 4×4の盤面なら長さ16ですから、`Array.new` の深さは4です。長さをそのまま16と指定するわけではありません。
- `List.map` の入力 `[1,2,3]` は数字の型が推論できない場合があるので、例では `{[1,2,3] : List<U32>}` と明記しています。

## 第19章：CPUスレッドとGPU
- `06_parallel.bend` の結果は深さ8の二分木の葉の数で、256です。
- `./leaves --threads 1` と `./leaves --threads 8` の出力が一致しても、性能改善があったことにはなりません。実行時間、実機のCPU、仕事量を比較する必要があります。
- 単一盤面の旗切替に `Array.fork` や原子的操作は不要です。独立候補の大量検査なら並列化を検討できますが、性能は実測します。

## 第20章：モジュールと生成先
- `board_index.bend` の `index(row,col)` は `4*row+col` を返します。`42_module_board.bend` が `Board.index(2,3)` を呼び、結果11です。
- `board_index.bend` は `main` がないモジュールです。ZIPでは、取り込む側の `42_module_board.bend` を実行してください。
- `bend ... -o foo.c` でCのソースが生成されることと、生成後のCコードがコンパイル・実行できたことは別です。さらにブラウザやJSランタイム上での外部呼び出しも別途検査します。
- `--publish` はパッケージを公開する操作であり、練習として実行しません。
