# 第13〜14・21章補稿：初手の安全と勝利を一つのゲームにしましょう

> **TeX本編・PDFには未統合**。ここではN=2〜100の初手安全・一マス公開・旗・勝敗を接続します。**0の連鎖公開はまだありません**。ソルバーやGUIにも接続していません。

## なぜ二つの部品を接続するのでしょうか

前節の`nxn_start.bend`は、初手が地雷なら別の空きマスへ移しますが、勝利状態を管理しません。一方、`nxn_terminal.bend`は勝利・敗北後の入力を止めますが、初手の地雷を避けません。このままでは、どちらか一方だけを使うゲームになってしまいます。初手の処理と二手目以降の処理を一つの入口にまとめましょう。

## Bendコードと実行結果

`minesweeper/nxn_game.bend`では、開始前の`Fresh`と、勝敗を持つ`Terminal.State`を包んだ`Active`を使います。

```bend
type Game is Type:
  Fresh{board: Words.MineWords}
  Active{state: Terminal.State}

def after_relocation(result: Relocate.Relocation, +index: U32) -> Game:
  match result:
    case Relocate.FirstClickRejected{board}:
      Fresh{board}
    case Relocate.FirstClickSafe{board}:
      Active{Terminal.click(Terminal.new(board), index)}
```

右下だけが地雷の2×2盤面で、0、1、2を順にクリックしてみます。

```sh
bend intermediate/minesweeper/nxn_game.bend
# 111
```

表示用の`111`は`Won`を示す100と、添字2の数字1を示す11の和です。実際のGUIの表示値ではありません。最初のクリックだけで唯一の安全マスが開いた場合にも、同じ`Terminal.click`が勝利を判定します。

## 仕組みを追いましょう

開始前のクリックは`Relocate.relocate`へ渡します。盤外や全地雷の盤面なら`Fresh`のままです。成功したら移動後の盤面から`Terminal.new`を作り、そのまま初手を公開します。二手目以降は`Terminal.click`に渡すため、地雷を踏めば`Lost`、安全マスをすべて開けば`Won`となり、その後のクリック・旗操作は無効になります。開始前の旗操作も無視します。

`scripts/test_nxn_game.py`は、地雷をPythonの集合で保持し、数字を座標から独立に数えるオラクルと比較します。N=2・3・4・10・17・100の有限な操作列、初手地雷移動、勝利後・敗北後の入力、10×10の配列余剰添字を検査対象とします。**これは有限ケースの照合であり、任意の操作列の証明ではありません。**
