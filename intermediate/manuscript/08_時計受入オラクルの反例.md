# 第8章補稿：時計テスト自体を検査する

> 2026-11-01の検証候補です。これはリポジトリ側の編集・テスト資料であり、読者PDF・ZIPにはまだ収録しません。配布済みの`55_clock_intervals.bend`と第8章TeXは変更しません。

## 必要性

`IO.sleep(20)`の結果が毎回ちょうど20ミリ秒になると期待すると、正しいプログラムを誤って不合格にする可能性があります。逆に、待機処理が実行されなくなった場合や`IO.now()`が逆行した場合を見逃してもいけません。Bend本体を検査するPython側の判定器にも、正しい入力と誤った入力を与えて確認します。

## 実行できるBendコードと判定器

配布済みの`55_clock_intervals.bend`は、0・20・100ミリ秒の各待機の前後で`IO.now()`の生の値を出力します。実行は従来どおりです。

```sh
python3 intermediate/scripts/test_clock_intervals.py
```

Bendの6行出力は`validate_readings(lines, wall_ms, trial)`へ渡します。この関数はBendコードではなく、**Bendの出力を独立に評価するPythonオラクル**です。Bendがなくてもオラクルの反例を試せます。

```sh
python3 -m unittest discover -s intermediate/tests -p test_clock_validator.py -v
```

## 実行結果と反例

Python単体テスト8件では、待機0・20・100ミリ秒に対して経過時間がそれぞれ`0,10,50`となる境界例を合格させます。`5,31,120`のように要求時間と異なる観測値も合格させます。一方、6行以外、ASCII以外の数字、負数、逆行する時刻、20ミリ秒待機で9ミリ秒、100ミリ秒待機で49ミリ秒、プロセス全体の観測時間と矛盾する値を拒否します。`NaN`や無限大の外側時計値も拒否します。

この8件は**Pythonオラクルの有限な単体検査**です。実Bendの型検査・3試行は、既存の`test_clock_intervals.py`がCIで行う別の受入条件です。単体テスト成功だけで実機の時計精度を保証したり、Bendの実行が成功したと扱ったりしません。

## 仕組み

6つの生時刻`a,b,c,d,e,f`の隣接するすべての値に対して非減少を検査し、待機時間は`b-a`、`d-c`、`f-e`で求めます。`Nat.sub`だけを見ていると逆行が0に丸められる場合があるため、生時刻の順序を先に調べます。20・100ミリ秒の緩い下限は10・50ミリ秒とし、0ミリ秒には正の下限を設けません。外側の`time.monotonic()`と比較する上限には余裕を設けます。これらはLinux CIで待機処理の無視を検出するための受入条件であり、あらゆるOS・負荷条件での時刻保証ではありません。
