# 第21章補稿：初手生成ゲームとGUIの入力・イベント境界（有限検証済み）

## 必要性と責任分離

4×4の旧 `gui.bend` は固定盤面 `Start.new(33)` を起点にする教材です。初手前に地雷位置を保持しない確定仕様の10×10版へ、そのまま置き換えることはできません。まずGUIの座標・マウスボタンをゲームの操作へ変換する**純粋な境界**を作り、表示の実装とは分離して検証します。

新規 `minesweeper/nxn_gui_adapter.bend` は `nxn_lazy_game.bend` の `Fresh{n,count,seed}` をそのまま利用します。初手前に地雷集合を生成しません。画面のクリック位置をセル番号へ変換した後、左ボタンだけ `Lazy.click`、右ボタンだけ `Lazy.mark` に渡します。その他のボタンと画面外座標はゲームを変更しません。右ボタンはFreshの間は無作用です。

## 具体的なBendコード

```bend
def pointer_n(game: Lazy.Game, n: U32, x: U32, y: U32, button: U32) -> Lazy.Game:
  mouse_index(cell_at(n, x, y), game, button)

def pointer(game: Lazy.Game, x: U32, y: U32, button: U32) -> Lazy.Game:
  pointer_n(game, 10, x, y, button)

def reset_gui(seed: U32) -> Lazy.Game:
  reset(10, 10, seed)
```

1マス32×32画素なので10×10画面は320×320画素です。左上(0,0)はセル0、右下(319,319)はセル99、(320,0)は画面外です。任意N（2〜100）について `(y // 32)*N + (x // 32)` を使います。境界外は `Maybe.None` で拒否し、実際のクリック処理へ到達させません。

## 実行結果と仕組み

`scripts/test_nxn_gui_adapter.py` は独立したPython座標オラクルから18件の境界値、固定10×10のラッパー3件、13件のイベント列の期待値を作ります。Bend 2でそれぞれ型検査・実行し、検証PR #87の全CI成功を確認しました（CI #40781258079）。開始前の画面外クリック、右クリック、未知ボタンは `Fresh` を保ち、初手左クリック後は既存のN×N遅延生成・連鎖・終局処理へ進みます。これは有限の入力列についての成功であり、OS上の描画・操作を確認した結果ではありません。

これは**描画用Image、App.run、イベントのOS実配送、実画面での操作テストを実装したものではありません**。旧4×4 GUIの正式置換は別工程です。10×10 GUI実機の合格、一様無作為生成、一般N×N運ゲー無しの保証は主張しません。

## 2026-10-29：イベント配送をゲームに接続する（有限検証済み）

座標変換だけでは、押下・解放・リセット・ウィンドウ終了を区別できません。`nxn_gui_events.bend` ではBendの`Event`を純粋なゲーム状態遷移へ変換します。

```bend
def event(e: Event, game: Lazy.Game, seed: U32) -> Maybe<Lazy.Game>:
  match e:
    case Close{}:
      None{}
    case Key{27, True{}}:
      None{}
    case Key{114, True{}}:
      Some{GUI.reset_gui(seed)}
    case Key{82, True{}}:
      Some{GUI.reset_gui(seed)}
    case Mouse{x, y, button, True{}}:
      Some{GUI.pointer(game, x, y, button)}
    case _:
      Some{game}
```

EscとCloseは`None`、R/rは地雷集合を作らない`Fresh`へ戻し、マウスの押下だけを既存の座標変換へ渡します。例えば、リセット後の`snapshot(...,0)`は`300`、Closeは`None`です。16種類の入力列を独立Python期待値とBend型検査・実行で照合し、検証PR #88の全CI成功を確認しました（CI #40795728371）。

マウスの押下と解放、初手後のリセット、RとEscの違いを試してみましょう。これは`App.run`でOSイベントを受け取った実機試験ではなく、描画用`Image`も未実装です。TeX・PDF・読者ZIPへの反映は別途同一版検証が必要です。

## 次の実装単位：描画とOSイベント接続の検収契約

入力とイベントの有限検証が成功しても、画面が描けるとは限りません。旧4×4 `gui.bend` の `view` は表示用配列を `Array.clone` して画像を組み立てています。10×10版でも、**ゲーム状態を保持したまま公開セルだけを表示する**責任を独立させます。

- `Fresh{n,count,seed}` は全セルを未公開として表示し、描画やマウス移動を理由に `Lazy.generate` を呼びません。地雷配置は最初の有効な左クリックまで存在しません。
- `Active` の表示は公開セルの `Hidden`／`Flag`／`Open{clue}` のみを参照します。地雷真値は描画や推論へ流しません。表示のためにゲームの所有権を消費しないよう、必要な可視配列だけを複製し、状態を返します。
- 入力座標の契約は32画素単位・有効範囲 `0 <= x,y < 320` です。Bend `Image` の四分木表現と実ウィンドウの寸法が一致するかは、描画実装時に検証します。未確認のパディング・拡大率を既定仕様として断定しません。
- 左押下、右押下、R/r、Esc、Closeの状態遷移を実際の `App.run` に接続します。押下・解放、盤外、初手、旗、勝敗、リセットをGUI上で再試験し、`Fresh` への復帰で地雷集合が残らないことを確認します。

既存の有限検証では、座標18件・10×10ラッパー3件・ゲーム操作列13件、イベント列16件が成功しています。**画像のピクセル一致、ウィンドウ生成、OSイベントの配送、10×10実機操作、一般N×N運ゲー無し性は未検証**です。これらの実装・検証後に限り第21章のTeX本編と読者ZIPへ同期します。

演習として、リセット後に全セルが未公開へ戻ることと、初手前の右クリックで盤面が生成されないことを、表示と内部状態の両方で確かめてみましょう。
