# 第21章補稿：初手生成ゲームとGUIの入力・イベント境界（有限検証済み）

## 必要性と責任分離

4×4の旧 `gui.bend` は固定盤面 `Start.new(33)` を起点にする教材です。初手前に地雷位置を保持しない確定仕様の10×10版へ、そのまま置き換えることはできません。まずGUIの座標・マウスボタンをゲームの操作へ変換する**純粋な境界**を作り、表示の実装とは分離して検証します。

新規 `minesweeper/nxn_gui_adapter.bend` は `nxn_lazy_game.bend` の `Fresh{n,count,seed}` をそのまま利用します。初手前に地雷集合を生成しません。画面のクリック位置をセル番号へ変換した後、左ボタンだけ `Lazy.click`、右ボタンだけ `Lazy.mark` に渡します。その他のボタンと画面外座標はゲームを変更しません。右ボタンはFreshの間は無作用です。

## 具体的なBendコード

```bend
def pointer_n(game: Lazy.Game, n: U32, x: U32, y: U32, button: U32) -> Lazy.Game:
  mouse_index(cell_at(n, x, y), game, button)

def pointer(game: Lazy.Game, x: U32, y: U32, button: U32) -> Lazy.Game:
  pointer_n(game, 10, x, y, button)

def reset_gui(seed: U32) -> Lazy.Game:
  reset(10, 10, seed)
```

1マス32×32画素なので10×10画面は320×320画素です。左上(0,0)はセル0、右下(319,319)はセル99、(320,0)は画面外です。任意N（2〜100）について `(y // 32)*N + (x // 32)` を使います。境界外は `Maybe.None` で拒否し、実際のクリック処理へ到達させません。

## 実行結果と仕組み

`scripts/test_nxn_gui_adapter.py` は独立したPython座標オラクルから18件の境界値、固定10×10のラッパー3件、13件のイベント列の期待値を作ります。Bend 2でそれぞれ型検査・実行し、検証PR #87の全CI成功を確認しました（CI #40781258079）。開始前の画面外クリック、右クリック、未知ボタンは `Fresh` を保ち、初手左クリック後は既存のN×N遅延生成・連鎖・終局処理へ進みます。これは有限の入力列についての成功であり、OS上の描画・操作を確認した結果ではありません。

これは**描画用Image、App.run、イベントのOS実配送、実画面での操作テストを実装したものではありません**。旧4×4 GUIの正式置換は別工程です。10×10 GUI実機の合格、一様無作為生成、一般N×N運ゲー無しの保証は主張しません。

## 2026-10-29：イベント配送をゲームに接続する（有限検証済み）

座標変換だけでは、押下・解放・リセット・ウィンドウ終了を区別できません。`nxn_gui_events.bend` ではBendの`Event`を純粋なゲーム状態遷移へ変換します。

```bend
def event(e: Event, game: Lazy.Game, seed: U32) -> Maybe<Lazy.Game>:
  match e:
    case Close{}:
      None{}
    case Key{27, True{}}:
      None{}
    case Key{114, True{}}:
      Some{GUI.reset_gui(seed)}
    case Key{82, True{}}:
      Some{GUI.reset_gui(seed)}
    case Mouse{x, y, button, True{}}:
      Some{GUI.pointer(game, x, y, button)}
    case _:
      Some{game}
```

EscとCloseは`None`、R/rは地雷集合を作らない`Fresh`へ戻し、マウスの押下だけを既存の座標変換へ渡します。例えば、リセット後の`snapshot(...,0)`は`300`、Closeは`None`です。16種類の入力列を独立Python期待値とBend型検査・実行で照合し、検証PR #88の全CI成功を確認しました（CI #40795728371）。

マウスの押下と解放、初手後のリセット、RとEscの違いを試してみましょう。これは`App.run`でOSイベントを受け取った実機試験ではなく、描画用`Image`も未実装です。TeX・PDF・読者ZIPへの反映は別途同一版検証が必要です。

## 次の実装単位：描画とOSイベント接続の検収契約

入力とイベントの有限検証が成功しても、画面が描けるとは限りません。旧4×4 `gui.bend` の `view` は表示用配列を `Array.clone` して画像を組み立てています。10×10版でも、**ゲーム状態を保持したまま公開セルだけを表示する**責任を独立させます。

- `Fresh{n,count,seed}` は全セルを未公開として表示し、描画やマウス移動を理由に `Lazy.generate` を呼びません。地雷配置は最初の有効な左クリックまで存在しません。
- `Active` の表示は公開セルの `Hidden`／`Flag`／`Open{clue}` のみを参照します。地雷真値は描画や推論へ流しません。表示のためにゲームの所有権を消費しないよう、必要な可視配列だけを複製し、状態を返します。
- 入力座標の契約は32画素単位・有効範囲 `0 <= x,y < 320` です。Bend `Image` の四分木表現と実ウィンドウの寸法が一致するかは、描画実装時に検証します。未確認のパディング・拡大率を既定仕様として断定しません。
- 左押下、右押下、R/r、Esc、Closeの状態遷移を実際の `App.run` に接続します。押下・解放、盤外、初手、旗、勝敗、リセットをGUI上で再試験し、`Fresh` への復帰で地雷集合が残らないことを確認します。

既存の有限検証では、座標18件・10×10ラッパー3件・ゲーム操作列13件、イベント列16件が成功しています。**画像のピクセル一致、ウィンドウ生成、OSイベントの配送、10×10実機操作、一般N×N運ゲー無し性は未検証**です。これらの実装・検証後に限り第21章のTeX本編と読者ZIPへ同期します。

演習として、リセット後に全セルが未公開へ戻ることと、初手前の右クリックで盤面が生成されないことを、表示と内部状態の両方で確かめてみましょう。

## 2026-10-29：10×10のImage描画とApp.run入口（検証候補）

### 必要性

入力イベントをゲームへ渡せても、画面に公開情報を描かなければ遊べません。一方で、画面を描くたびに地雷を再生成したり、隠された地雷位置を描画側へ渡したりしてはいけません。そこで、`nxn_gui_render.bend`では`Fresh`の描画を未公開セル100個だけから作り、`Active`では`Array.clone(Game.Square, cells)`で可視セル配列を複製します。地雷を保持する元のゲーム状態はそのまま返します。

### 具体的なBendコード

```bend
def view_session(session: Step.Session) -> Step.Session & Image:
  match session:
    case Step.Session{n, mines, cells, phase}:
      view_cloned(n, mines, phase, Array.clone(Game.Square, cells))

def view(game: Lazy.Game) -> Lazy.Game & Image:
  match game:
    case Lazy.Fresh{n, count, seed}:
      (Lazy.Fresh{n, count, seed}, fresh_picture())
    case Lazy.Active{state}:
      active_view(view_state(state))
    case Lazy.Invalid{}:
      (Lazy.Invalid{}, Pix{0})
```

`nxn_gui_app.bend`では`App.run(~Lazy.Game, ~App{view, tick}, ..., 512, 512, GUI.reset_gui(20261029))`を入口とし、既存の`Events.tick`へイベントを渡します。Imageは2の累乗の四分木なので、16×16タイルを描く128×128のImageを512×512画素へ拡大します。1タイルは32×32画素です。左上10×10タイル（320×320画素）のみ操作可能で、右側・下側の192画素は黒い余白とし、既存の座標変換でクリックを拒否します。各タイルには境界線と数字の7セグメント表示を置きます。

### 実行結果・検証境界

独立Python参照モデルでは、初手前の状態コードは`300`、seed `20261029`で左上を最初に開いたセルのコードは`10`（数字0）です。画素の期待値は、未公開セル内部`8689825`、数字0の背景`15658734`、右下の余白`0`です。13条件をBendのheadless実行で照合し、GUI入口を`--check-only`で型検査するテストを追加しました。**この補稿を作成した時点ではBend実行とApp.run型検査のCI結果は未確認**です。Python静的事前検査は成功しています。

`Image`のピクセル検査は実際のOSウィンドウでの描画やマウス配送の検査ではありません。GUI実機でのクリック、旗、勝敗、リセット、Esc、ウィンドウ終了、表示倍率を確認するまでは正式なGUI完成とは扱いません。旧4×4 GUIは変更せず、配布TeX/PDF/読者ZIPへの統合も別の検収工程とします。

## 2026-10-29：四分木サンプラーの照合順と検証範囲（検証候補）

`Image`をheadlessで検査する際は、`Qua`の四つの子から画素座標に対応する一つを選びます。Bend 2.0.39では、局所変数を定義した後にその変数を`match`する構造は型検査に失敗します。そこで`pixel_at_walk`に上下・左右のBoolを引数として渡し、最初に`match img`、次に`match bottom right`を行ってから座標を更新します。再帰には必ず`Qua`の直接の子を渡し、構造的減少を明確にします。

追加の4条件では、四分木`Qua{Pix{11}, Pix{22}, Pix{33}, Pix{44}}`を使い、2×2の左上・右上・左下・右下でそれぞれ`11, 22, 33, 44`を期待します。従来の13条件と合わせて17件です。**現時点では新しいBend型検査と実行結果は未確認**であり、成功したと断定しません。OSウィンドウの表示・イベント配送は引き続き実機検収が必要です。

演習として、四分木の右上・左下の座標を入れ替えると期待値がどう変わるか、`pixel_at`の引数を変えて確かめてみましょう。

## 2026-10-29：描画境界と二段四分木の追加検収（検証候補）

### 必要性

2×2の四分木だけでは、16×16タイルの境界をまたぐ座標変換を十分に検査できません。たとえば10×10盤面の右端は論理画素`x=79`までで、`x=80`からは黒い余白です。表示領域の外側をゲームのセルと誤認すると、クリック可能範囲の説明と描画が食い違います。

### 具体的なBendコードと期待結果

```bend
RENDER.pixel_at(RENDER.fresh_picture(), 79, 79, 128) # 8689825: 最終セルの内側
RENDER.pixel_at(RENDER.fresh_picture(), 80, 79, 128) # 0: 右側の余白
RENDER.tile_pixel(11, 5, 2)                      # 1578496: 数字1の縦線
RENDER.tile_pixel(11, 2, 2)                      # 15658734: 数字1の背景
```

さらに、4×4の二段`Qua`を16個の異なる`Pix`で構成し、四隅と中央境界付近の計8点を検査します。四分木の子へ直接再帰する`pixel_at_walk`が、最上位の象限だけでなく次の段でも正しく座標を縮小することを確かめます。既存17件に14件を追加し、合計31件のheadless期待値とします。**ここに記した31件は検証ブランチでのCI成功を確認するまで未検証**です。GUI実機操作の保証ではありません。

### 演習

論理画素`(79,79)`を`(80,79)`へ一つだけ動かし、色が変わる理由を説明してみましょう。次に、二段四分木の`(1,2)`と`(2,1)`を読み、上下左右の象限選択が入れ替わらないことを確かめてみましょう。

## 2026-10-29：描画後の可視状態と旗の表示を照合する（検証候補）

### 必要性

Imageの四分木が正しくても、描画のためにゲームの状態を消費したり、旗と未公開セルを取り違えたりすれば遊べません。そこで、初手前・初手後・旗のオン／オフを同じ10×10の可視情報から確認します。描画側へ真の地雷配置を渡さない契約は維持します。

### Bendコードと実行予定の結果

```bend
# 初手左クリック後、右下セル99に旗を立てて描画する
game = GUI.pointer(GUI.pointer(GUI.reset_gui(20261029), 0, 0, 0), 319, 319, 1)
pair = RENDER.view(game)
# pairに含まれるゲームのセル99はFlag（snapshotは1）
```

独立Pythonのゲーム参照モデルでは、このseedの初手は数字0で、右下セル99は未公開のままです。したがって旗を立てた後のsnapshotは`1`、もう一度右クリックして解除すると`0`です。論理Image画素`(76,75)`は旗の赤`14704438`、隣のセル98の`(68,75)`は未公開色`8689825`となることを期待します。初手前の右クリックでは`Fresh`の状態コード`300`を維持します。

この6条件は既存31条件と分けてBendの型検査・実行に掛けます。検証PRのCIが成功するまでは**期待値であって実行成功とは記さない**ことに注意してください。二度描画しても旗が残ることを確認する条件も含みます。OSウィンドウでの描画・イベント配送は依然として未検証です。

### 演習
