# 第21章補稿：初手生成ゲームとGUIの入力境界（検証候補）

## 必要性と責任分離

4×4の旧 `gui.bend` は固定盤面 `Start.new(33)` を起点にする教材です。初手前に地雷位置を保持しない確定仕様の10×10版へ、そのまま置き換えることはできません。まずGUIの座標・マウスボタンをゲームの操作へ変換する**純粋な境界**を作り、表示の実装とは分離して検証します。

新規 `minesweeper/nxn_gui_adapter.bend` は `nxn_lazy_game.bend` の `Fresh{n,count,seed}` をそのまま利用します。初手前に地雷集合を生成しません。画面のクリック位置をセル番号へ変換した後、左ボタンだけ `Lazy.click`、右ボタンだけ `Lazy.mark` に渡します。その他のボタンと画面外座標はゲームを変更しません。右ボタンはFreshの間は無作用です。

## 具体的なBendコード

```bend
def pointer_n(game: Lazy.Game, n: U32, x: U32, y: U32, button: U32) -> Lazy.Game:
  mouse_index(cell_at(n, x, y), game, button)

def pointer(game: Lazy.Game, x: U32, y: U32, button: U32) -> Lazy.Game:
  pointer_n(game, 10, x, y, button)

def reset_gui(seed: U32) -> Lazy.Game:
  reset(10, 10, seed)
```

1マス32×32画素なので10×10画面は320×320画素です。左上(0,0)はセル0、右下(319,319)はセル99、(320,0)は画面外です。任意N（2〜100）について `(y // 32)*N + (x // 32)` を使います。境界外は `Maybe.None` で拒否し、実際のクリック処理へ到達させません。

## 実行結果と仕組み

`scripts/test_nxn_gui_adapter.py` は独立したPython座標オラクルから18件の境界値、固定10×10のラッパー3件、13件のイベント列の期待値を作ります。Bend 2でそれぞれ型検査・実行する検証をCIに追加します。開始前の画面外クリック、右クリック、未知ボタンは `Fresh` を保ち、初手左クリック後は既存のN×N遅延生成・連鎖・終局処理へ進みます。型検査・Bend実行の成功は検証CI完了まで未確認です。

これは**描画用Image、App.run、イベントのOS実配送、実画面での操作テストを実装したものではありません**。旧4×4 GUIの正式置換は別工程です。10×10 GUI実機の合格、一様無作為生成、一般N×N運ゲー無しの保証は主張しません。
