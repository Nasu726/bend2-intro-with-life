# 第13〜14章補稿：N×N盤面の数字をBendで計算する（PDF未統合）

## なぜ、地雷の格納だけでは足りないのでしょうか

N×N盤面の地雷位置は `nxn_mine_words.bend` の32ビット語列で保持できます。しかし、プレイヤーに見せる数字は「クリックしたマスの周囲8マスに地雷が何個あるか」を数えなければ得られません。行の端で反対側のマスを隣接扱いしないこと、10×10のArrayで100〜127番の余剰スロットを読まないことも重要です。

## 実際のBendコード

`intermediate/minesweeper/nxn_clues.bend` は、地雷の真値を保持する `MineWords` を受け取り、調べ終えた盤面と `Maybe<U32>` の数字を組にして返します。まず、ファイル末尾の例を実行してみましょう。

```bend
import Base
import ./nxn_mine_words.bend as Words

# nxn_clues.bend内の実例（抜粋）
def main() -> U32:
  read_count(count_checked(Words.set_checked(Words.new(10), 1, True{}), 0))
```

```sh
bend intermediate/minesweeper/nxn_clues.bend
# 1
```

10×10の0番は左上、1番はその右です。1番に地雷があるので、0番の周囲の地雷数は1になります。ここに示した`1`はコードから計算される値であり、一般サイズのゲームが完成したという意味ではありません。

## 仕組みを追ってみましょう

`count_checked` は、まず `Geo.valid_index` で論理的な添字を検査します。範囲外なら `None` を返します。範囲内なら、3×3の9座標を `Nat` の燃料で順番に調べ、中心を除く有効な近傍だけ `Words.has` で読み取ります。左上の座標で符号なし整数が回り込んでも、`Geo.neighbor` の境界検査を通らないため、配列の不正な読み出しには進みません。

`MineWords` は`Type`の資源なので、読み取りごとに更新後の資源を返し、次の検査へ受け渡します。この関数は**ゲーム内部の数字生成**であり、運ゲー無し推論器に真の地雷配置を渡してはいけません。推論器へ渡せるのは実際に開かれた数字だけです。

## 実行結果と検証の境界

`python3 intermediate/scripts/test_nxn_clues.py` は、Bendでの型検査と実行を行い、別実装のPython座標集合オラクルで計算した期待値と比較します。 CIでは高負荷の510件照合を通常サンプルの検査から分け、専用ステップで型検査と実行を行います。検査が時間切れになった場合は未検証として扱い、数字が正しいと判定しません。N=2、3、4、10、17、100、角・辺・語境界・不正添字などの**510ケース**が、検証ブランチのBend 2.0.39で一致しました（CI #40041376242）。この検査は有限個の実行例であり、任意の盤面についての形式的証明ではありません。
