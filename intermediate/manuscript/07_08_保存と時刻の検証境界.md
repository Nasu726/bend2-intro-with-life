# 第7・8章補稿：保存を壊さず、時計を決めつけない

> 本文統合待ちの編集用補稿です。学習者に配布するPDF・ZIPにはまだ収録しません。
> Bend 2.0.38で検証済みの既存コードを題材とし、今回追加する回帰テストの
> 成否はCIで判定します。実機GUIの保存・一般のファイル形式を保証しません。

## 第7章：書けた「つもり」を避ける

ゲームの保存では、単に書き込みAPIが成功しただけでは十分ではありません。
古い保存データが末尾に残っていたら、次回の読み込み時に別の状態に見えて
しまいます。まず、`examples/12_file_write.bend`を実行してみましょう。

```sh
bend examples/12_file_write.bend
bend examples/13_file_read.bend
```

読み戻しの表示は次の二行です。

```text
board-size=4
mines=1,1
```

`File.open("sample_board.txt", "w")`で書き込み用に開き、
`File.write`の結果から継続用のハンドルを受け取り、
成功・失敗の両方で`File.close`します。読むときも`File.open(..., "r")`
と`File.read`を分け、開けなかった場合は成功扱いにしません。

**確認したい二つの失敗境界**は、長い旧ファイルを上書きしたときの
末尾の残存と、読み込み前にファイルを消したときの誤った成功です。
`scripts/test_examples.py`では、長い旧データを先に置いてから
書き込み・読み戻しを照合し、ファイル削除後の読み込みが
非ゼロ終了することも検査します。前者は`"w"`の切り詰め、
後者は`IO.try`を通る失敗伝播の検査です。

**演習：** 保存先を新しい一時フォルダーに変更し、古いファイルの末尾に
`old-save`が残っていないか確認してみましょう。次にファイルを削除し、
読み込みに失敗することを確かめてみましょう。なぜ「空の盤面を読み込んだ」
ことにしてはいけないか考えてみましょう。

## 第7章：4バイトと4文字は違う

画像などのバイナリデータは文字列として保存する必要がありません。
`examples/45_binary_file.bend`は次のバイト列を書き込みます。

```bend
File.write_bytes(file, [0, 10, 13, 255])
```

```sh
bend examples/45_binary_file.bend
od -An -tx1 sample_bytes.bin
```

最初のコマンドの表示は`4`、次のコマンドで確かめる
実ファイルの内容は`00 0a 0d ff`です。
`File.read_bytes(input, 16)`の`16`は**最大読込量**であって、
「必ず16バイト戻る」という意味ではありません。
また、読込結果の長さが4であっても、値と順序が正しいとは限りません。

`scripts/test_examples.py`は、事前に128バイトの旧データを作り、
実行後に**ちょうど4バイト**だけが残ることと、
値が`00 0A 0D FF`であることを別々に確認します。
同名のディレクトリを置いた場合の`File.open`失敗も確認します。

**演習：** 値を`[255, 13, 10, 0]`に変えて実行し、個数の表示と
`od`の表示を比較してみましょう。4という個数だけでバイトの順序を
保証できない理由を説明してみましょう。

## 第8章：待機時間と実測経過時間を分ける

タイマーを作るには「20ミリ秒待つように要求すること」と
「実際に経過した時間を測ること」を区別します。

```bend
start: Nat <- IO.now()
Unit <- IO.sleep(20)
finish: Nat <- IO.now()
IO.print(Nat.show(Nat.sub(finish, start)))
```

```sh
bend examples/46_elapsed_clock.bend
```

表示は経過ミリ秒を表す整数です。`IO.now()`は暦の日付ではなく
経過時間の測定に使う値を返します。OSのスケジューリングや実行環境で
差が変わるため、結果が毎回`20`になるというテストは書きません。
`scripts/test_examples.py`は二回実行して整数としての妥当性を確認します。
`Nat.sub`による差の計算そのものは純粋であり、
同じ二つの数を与えれば同じ結果です。

**演習：** 待機を`0`、`20`、`100`に変えて各三回実行してみましょう。
「要求した待機時間」と「測った経過時間」を表に分けて記録し、
タイマーの合否判定に等号を使うべきでない理由を説明してみましょう。

## 検証の範囲

Bend本体の型検査・Fileの実IO・時計の実行は
`intermediate/scripts/test_examples.py`をCIで実行して確認します。
Python側で行うのは出力、保存ファイルのバイト列、失敗時終了コードの
**有限な受入検査**です。ファイルシステムの全障害モード、時計の精度、
GUI保存機能を形式的に証明したわけではありません。
