# 第21章：原子的保存への移行に必要な実機検証（2026-11-01）

## なぜ必要か

現行の配布GUIの `File.open("minesweeper_nxn_save.txt", "w")` は既存ファイルを先に切り詰めます。途中で書込みに失敗すると、ライブ盤面は維持できても**前回の保存内容は失われ得ます**。現在の保存成功通知は原子的更新を保証しません。

## Linux限定のBend検証候補

`minesweeper/nxn_gui_atomic_store.bend` は読者配布版へ**未接続**の実験コードです。公開操作履歴の妥当性を検査してから、同じディレクトリの乱数サフィックス付き一時ファイルへ `File.open` → `File.write` → `File.close` で書き、GNU `/usr/bin/mv -fT --` の終了コードが0のときだけ成功を返します。失敗時は一時ファイルを削除し、元の保存先は触らず `False{}` を返します。

`python3 intermediate/scripts/test_nxn_gui_atomic_store.py` はBend型検査と実行に加え、旧ファイルの置換、新規作成、保存先がディレクトリの場合の拒否と元ディレクトリの維持、拒否後の再試行、シンボリックリンクの置換、残存一時ファイルなしを検査します。`--static-only` はBendなしで静的構造とGNU mvのディレクトリ拒否を確認します。

正常実行の最終出力は `1`、保存先がディレクトリなら `0` を期待します。検証PR #142・#143のBend実行とCIは成功済みです（配布GUIの実行保証ではありません）。

## 完成と呼ばない理由

- この試験コードは配布済み `nxn_gui_status_app.bend` / `nxn_gui_feedback_store.bend` / `nxn_gui_store.bend` に未接続。したがって配布GUIの原子的保存は未完成。
- LinuxのGNU mvと同一ディレクトリを前提とする。Windows・macOS・JSターゲットでは未検証。 `mv -T` により保存先ディレクトリを誤って操作することを防ぐ。
- `File.close` は失敗を返さず、fsync（ファイル本体・親ディレクトリ）を呼ばない。電源断後の永続性は保証しない。
- 一時ファイルは `File.open(...,"x")` で排他的に作成し、既存ファイル・symlink衝突を拒否します。ただし32bit乱数名の衝突は再試行せず失敗し、書込み後の同一UIDプロセス競合は未対策です。
- 次の統合ゲートはGUI本体への接続、X11の保存/失敗通知・盤面維持、異常終了・競合・権限拒否、PDF/ZIP再生成と表紙不変の一括検証。第7章Byte/File 56条件と第8章時計3試行を維持する。

## 2026-11-01：一時ファイルの排他的生成（検証候補）

Bend 2 のネイティブ実装は `File.open(path, "x")` を `O_WRONLY|O_CREAT|O_EXCL` に変換し、既存ファイル・既存シンボリックリンクでは失敗します。これを従来の `"w"` と置換し、**既存一時ファイルを切り詰めない**候補に改めます。根拠は [Bend公式 `file_open.c`](https://github.com/bendlang/bend/blob/main/bend2/effs/file_open.c) と [モード実行テスト](https://github.com/bendlang/bend/blob/main/tests/io/file_open_mode.bend) です。

`test_nxn_gui_atomic_store.py` では固定名のBendテスト入口を一時生成し、既存の通常ファイルとシンボリックリンクの双方で `0` を返し、保存先・一時ファイル・参照先を変更しないことを検査します。未存在の固定名では `1` と保存先置換を期待します。実際の乱数名による通常実行、ディレクトリ拒否、保存先symlinkの置換、後片付けも維持します。検証PR #143 のBend型検査・実行・Reader・Tests・X11・Intermediate CIは成功し、正本 `b7dc3027` に統合しました。

**残る境界：** 32bit乱数の衝突時は安全側に失敗し、再試行は未実装。書込み後の一時パスを同一UIDの別プロセスが操作できる場合の競合、close失敗の検出、fsyncと電源断耐性、保存先パスの外部改変、権限、他OS、配布GUIへの接続は未解決です。

## 2026-11-02：公開済み盤面の原子的保存・復元を追加検証する

非配布の実験GUIで、初期状態だけでなく左クリックで実際に公開した盤面を対象にします。最初のS/L往復で空の操作履歴 `BEND2-GUI-1|20261029|END` を確認した後、左クリックした履歴 `BEND2-GUI-1|20261029|0|END` を保存します。保存先inodeが再度変わること、一時ファイルが残らないこと、Rで初期化してLで同じ公開済み画面へ戻ることをX11画素で照合します。

続いて保存先をディレクトリに置き換え、**公開済み盤面のまま**S失敗（赤3マス）とL失敗（琥珀4マス）を確認します。ディレクトリ内の番兵ファイルと盤面画素を保ち、障害を取り除いた後にSが成功することも確かめます。これは保存失敗でライブ盤面が消えないことと、旧保存先を直接切り詰めないことを別々に検査するためです。

`scripts/test_nxn_gui_desktop.py` の追加試験は、検証用CIの成功までは**未検証**として扱います。配布GUI、TeX、PDF、読者ZIPは変更せず、採用表紙も不変更です。第7章Byte/File 56条件と第8章時計3試行は既存の回帰対象です。Linux/X11での有限試験は電源断後の永続性、同一UID競合、他OS、スクリーンリーダー対応の証明ではありません。


## 2026-11-02：プロセス再起動と破損履歴の全体拒否（追加受入候補）

**必要性：** 同一プロセスでのS→R→L成功だけでは、保存された公開履歴がGUI終了後にも復元できることは確かめられません。また、合法な操作に続く不正な操作があるとき、途中までの履歴をライブ盤面へ適用してはいけません。

**具体的な実行：** 非配布の `nxn_gui_atomic_status_app.bend` をコンパイルしてX11上で盤面を公開・原子的保存した後、Escで終了し、**同じバイナリを別プロセスで起動**します。新しいウィンドウはFreshで始まり、Lを押すと保存した公開済み盤面へ戻るはずです。続いて保存ファイルを `BEND2-GUI-1|20261029|0|200|END` に差し替えます。合法な0の後の200は範囲外なので、Lは琥珀4マスの失敗通知を出し、公開済み盤面を変更しないはずです。正しい履歴へ戻して再度Lを押すと青2マスで復元します。

```sh
# Linux/X11仮想ディスプレイ・Bend・clang・xdotool・ImageMagick・Pillowが必要
xvfb-run -a python3 intermediate/scripts/test_nxn_gui_desktop.py
```

**期待結果：** `PASS experimental X11 atomic S/L: ... process restart, corrupt replay rejection and board preservation`。判定は画素・通知形状・保存ファイルのバイト列・一時ファイル残存・プロセス終了コードを独立に照合します。新しいCIでの実行成功までは**未検証**です。配布GUI・TeX・PDF・読者ZIPは変更しません。

**仕組みと限界：** 公開操作履歴を再生するのであって地雷の真値を保存するわけではありません。X11仮想環境の有限操作であり、電源断後の永続性、複数プロセス同時書込み、物理GPU・他OS、スクリーンリーダー対応の証明にはなりません。

**演習：** 破損履歴の末尾を `0|200|END` から `0|END|END` に変えてみましょう。どちらも復元を拒否し、失敗直前の盤面を保つかを確認してみましょう。
