## なぜ公開数字をそのまま六ビット推論器へ渡せないのでしょうか

公開数字は、その周囲の**すべての地雷**を数えます。しかし、別の推論で地雷だと確定したマスは、これから列挙する未知マスには含めません。そのまま元の数字を使うと、確定済みの地雷を二重に数えてしまいます。

4×4の公開マス0・1・7が、それぞれ数字1・2・2だったとします。さらに、**別の正しい推論によって**2番が地雷と証明済みだと仮定します。プレイヤーが旗を置いただけでは、この前提は満たしません。

## 公開数字から残りの地雷数を計算しましょう

`intermediate/solutions/nxn_three_clue_adapter.py` の `from_public_clues` に `certified_mines=(2,)` を渡すと、2番を未知集合から外し、各数字から隣接する確定地雷の数を引きます。

```python
from nxn_three_clue_adapter import from_public_clues
request = from_public_clues(
    4, ((0, 1), (1, 2), (7, 2)), 3, certified_mines=(2,))
print(request.cells)
print(request.bend_arguments())
```

```text
(3, 4, 5, 6, 10, 11)
(6, 14, 57, 1, 1, 1, 0, False)
```

元の数字は1・2・2ですが、確定地雷2番は公開マス1・7の隣にあるので、**残りの数字は1・1・1**になります。六つの未知マスを昇順に並べると、近傍マスクは6・14・57です。地雷総数3のうち1個は確定していますが、盤面には六マス以外にも未公開マスがあります。そのため `use_total=False` とし、残り2個を六マスへ強制しません。

## Bendの既存の六変数推論器へ渡しましょう

```bend
import Base
import ./nxn_public_three_small.bend as Three

def main() -> U32:
  Three.score(Three.infer(6, 14, 57, 1, 1, 1, 0, False{}))
```

```text
680
```

この教材用スコアは、整合候補6通り・安全ビット8・確定地雷ビット0を表します。ビット3は六つの未知マスの4番目、すなわち**盤面の6番**なので、2番が地雷だという前提のもとで6番を安全と結論できます。

`intermediate/scripts/test_nxn_public_three_bridge.py` は、Pythonが作った入力を既存Bend推論器へ渡して型検査・実行照合します。独立した `test_nxn_certified_three_clue_adapter.py` は、4×4の未知12マスから2地雷を選ぶ**66配置**について、全盤面列挙による候補を局所推論が落としていないことを確認します。

## 仕組みと検証範囲

`from_public_board` も最大24公開数字から三つ組を選ぶ際、同じ残数計算を利用します。未公開マスが確定地雷を除いてちょうど六つなら、局所推論へ渡す総数も `mine_count - len(certified_mines)` にします。負の残数、不正な番号、重複、公開済みマスとの重複は拒否します。

**これはPython参照側の入力変換です。** Bend側で確定地雷の証拠を自動取得する処理、一般N×Nの完全ソルバー、運ゲー無し生成器、10×10 GUI実機は未完成です。既存Bendの六変数カーネルは有限実行で照合しますが、任意入力の全称証明ではありません。特に `certified_mines` に未検証の旗を入れてはならず、旗を立てた事実だけでは安全な推論を保証できません。

## 演習

まず、2番が確定地雷でない場合は六マスの入力が作れないことを確かめてみましょう。次に、公開マス1の数字を1へ変えた場合に残数が0になる理由を考えてみましょう。最後に、`certified_mines=(2, 2)` や `certified_mines=(0,)` を指定し、重複や公開済みマスを拒否する理由を説明してみましょう。
