# 第22章補稿：包含しない二つの数字からも確定手を見つける（TeX・PDF未統合）

## なぜ集合の差だけでは足りないのでしょうか

前節では、二つの公開数字が制約する未知マスの集合について、片方がもう片方を含む場合を扱いました。しかし実際の盤面では、二つの集合が**一部だけ重なる**こともあります。

たとえば、公開された数字から得られた未知マス集合を `A={1,2,3}`、`B={2,3,4}` とし、Aに地雷が1個、Bに地雷が2個あると分かっているとします。集合は包含関係にないため、前節の `nxn_public_subset.bend` は確定手を返しません。それでも **1番は安全、4番は地雷** と推論できます。

## Bendの実行例

`intermediate/minesweeper/nxn_public_overlap.bend` は、二つの集合と残り地雷数から、確定安全マスと確定地雷マスを同時に返します。

```bend
def main() -> U32:
  tag(infer([1, 2, 3], [2, 3, 4], 1, 2))
```

`bend intermediate/minesweeper/nxn_public_overlap.bend --check-only` で型を調べ、続けて `bend intermediate/minesweeper/nxn_public_overlap.bend` を実行してみましょう。期待される出力は `1` です。これは `Deduced` を示すタグで、結果の安全リストは `[1]`、地雷リストは `[4]` です。タグだけでなく両方のリストも `python3 intermediate/scripts/test_nxn_public_overlap.py` で照合します。

## 仕組み：共通部分の地雷数を挟み撃ちする

AとBを、Aにしかない部分X、共通部分I、Bにしかない部分Yに分けます。共通部分の地雷数を `t`、AとBに必要な地雷数をそれぞれ `ra`、`rb` とすると、次の二式が成り立ちます。

- `Xの地雷数 + t = ra`
- `Yの地雷数 + t = rb`

Xに置ける地雷数は0から`|X|`、Yは0から`|Y|`、Iは0から`|I|`です。したがって、`t` の下限と上限は次のようになります。

```text
lower = max(0, ra - |X|, rb - |Y|)
upper = min(|I|, ra, rb)
```

`lower > upper` なら二つの数字は矛盾します。そうでなければ、Iの地雷数は`lower`以上`upper`以下です。Xの地雷数は`ra-upper`以上`ra-lower`以下、Yの地雷数は`rb-upper`以上`rb-lower`以下と分かります。**ある部分の地雷数の上限が0なら全部安全、下限がその部分のマス数なら全部地雷**です。

先ほどの例ではXとYが1マスずつ、Iが2マスです。`lower=upper=1`なので、Xの地雷数は0、Yの地雷数は1です。Bendの`infer`は両方を一度に返します。

この上下限は、二つの制約だけについては厳密です。ただし、**三つ以上の公開数字の連立条件や盤面全体の残り地雷数はまだ組み合わせていません**。入力集合は公開済み数字の隣接する未確定マスを重複なく昇順に並べたもので、`ra`と`rb`は別途論理的に確定した地雷だけを差し引いた値です。プレイヤーが置いた旗を確定地雷として扱ってはいけません。

## 実行結果と検証範囲

独立したPythonオラクルは、二集合の和集合にある最大7マスの地雷配置をすべて列挙し、両方の数字を満たす配置に共通する安全・地雷を調べます。Bend側と**安全リスト・地雷リストの順序まで**125ケースで比較します。加えてPython側の上下限の導出は、4マスの全ての集合対と残数の組合せで全候補列挙と照合します。これは有限テストであり、Bendの全称証明やGUIの実機検収ではありません。

## 実際の3×3公開盤面で、単独規則と包含規則を越える

今度は抽象的な集合ではなく、3×3盤面の公開数字 `(0,1)` と `(2,2)` から始めます。番号0・2はすでに公開された安全マスです。未知近傍は `A={1,3,4}`、`B={1,4,5}` となり、どちらも相手を含みません。単独数字の固定点反復では確定安全は0・2の2マスだけで、包含専用の差集合規則も適用できません。

`intermediate/minesweeper/nxn_public_overlap_gap.bend` は、実際の公開数字を可変個数の単独規則に渡し、次に二数字の重なりを既存 `Overlap.infer` へ渡します。次を実行してみましょう。

```sh
bend intermediate/minesweeper/nxn_public_overlap_gap.bend --check-only
bend intermediate/minesweeper/nxn_public_overlap_gap.bend
# 211
```

`211` は教材専用の符号です。百の位の2は既知安全0・2の2マス、十の位の1は追加で安全と確定した3番、一の位の1は追加で地雷と確定した5番を表します。盤面番号211ではありません。集合の共通部分 `I={1,4}` にある地雷数を `t` とすると、`t + x = 1`、`t + y = 2`（`x` は3番、`y` は5番の地雷有無）です。`x,y∈{0,1}` なので `t=1, x=0, y=1` と決まります。

独立Python監査 `python3 intermediate/scripts/test_nxn_public_overlap_gap.py --model-only` は、真の地雷配置512通りから二つの安全な公開数字を選んで得る**560種類の公開状態**を調べます。単独数字規則では増分なし、未知近傍が非包含、かつ二数字の重なり推論では確定が増える状態は**40種類**です（各状態で安全・地雷の両方が確定）。各結論をその公開数字と矛盾しない全真相配置に照らして検査します。通常実行ではこの40入力をBendの`Overlap.infer`でも照合し、実例の出力211を確認します。これは有限の3×3監査であり、一般N×Nの全称証明ではありません。

**演習**：公開数字 `(0,2)` と `(2,1)` に変えてみましょう。今度は3番が地雷、5番が安全になる理由を上下限から説明してみましょう。さらに、三つ以上の公開数字を組み合わせないと進まない局面を考えてみましょう。
