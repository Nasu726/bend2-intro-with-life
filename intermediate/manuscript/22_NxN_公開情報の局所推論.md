# 第22章補稿：N×Nの公開数字から確定手を一つ見つける

## なぜ局所推論から始めるのでしょうか

地雷の位置を内部に保持したゲームなら、安全なマスを直接調べられます。しかし、その答えを推論器に渡してしまうと、プレイヤーには見えない情報で「運ゲー無し」を判定したことになります。そこで、盤面の真値とは切り離し、**公開された数字と、すでに論理的に確定したマス**だけで次の一手を考えましょう。旗を立てただけのマスは、確定した地雷とは限りません。

## Bendのコードを動かしてみましょう

`minesweeper/nxn_public_local.bend` の `infer(n, index, clue, known_mines, known_safe)` を使います。例えば3×3盤面で左上0番の数字が1、右隣1番が**確定した地雷**だとします。左下3番と右下4番は、これ以上地雷を置けないため安全です。

```bend
def main() -> U32:
  tag(infer(3, 0, 1, [1], Nil{}))
```

```sh
bend intermediate/minesweeper/nxn_public_local.bend --check-only
bend intermediate/minesweeper/nxn_public_local.bend
# 1
python3 intermediate/scripts/test_nxn_public_local.py
# PASS 163 independent N x N public local deductions
```

ここで`1`は`Safe{indices}`という判定のタグです。返されるリストは`[3, 4]`で、`nxn_neighbors.bend`と同じ添字の昇順です。タグ`2`は全て地雷、`3`は確定手なし、`4`は矛盾・不正な入力を表します。最後のテスト件数は、検証スクリプトが生成した有限ケースの件数です。

## 仕組みを確かめましょう

数字`clue`から、隣接する**確定地雷**の個数`known`を引きます。残りを`remaining`とすると、未知の隣接マスの個数`unknown_count`について、`remaining == 0`なら未知マスは全て安全、`remaining == unknown_count`なら全て地雷です。それ以外は`NoMove`を返します。

負の残数、未知マス数を超える残数、同じ隣接マスを安全と地雷の両方に認定した入力、盤外・不正サイズ・不可能な数字は`Inconsistent`として拒否します。リストの重複は集合として扱い、近傍外の既知情報はこの一つの数字に影響させません。**この部品は地雷真値をimportしません。** ただし、入力の「確定地雷」「確定安全」が正しいという前提に依存します。

## 演習

3×3の中央4番の数字が1で、近傍のうち8番以外の7マスがすでに安全だと分かっているとします。8番の判定を予想し、`infer`で確かめてみましょう。次に、1番を確定地雷と確定安全の両方に入れて、矛盾がどのように扱われるか確認してみましょう。
