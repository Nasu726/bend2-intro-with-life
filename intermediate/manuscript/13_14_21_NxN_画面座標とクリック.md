# 第12・14・21章補稿：画面の座標をN×Nゲームの操作へつなぎましょう

> **TeX本編・PDFには未統合**。ここでは画面を開かない純粋な入力変換を扱います。10×10 GUIの描画・実機操作・保存はまだ未完成です。

## なぜ座標変換が必要なのでしょうか

4×4 GUIでは256×256画面を64ピクセルのマスに分けていました。10×10に拡張する際、同じ画面幅をそのまま使うとマスの境界が整数で割り切れません。まず1マス32×32ピクセル、10×10なら320×320ピクセルという約束を決めましょう。ゲーム本体は画素を知らず、マス番号だけを受け取るようにします。

## Bendコードを動かしましょう

`minesweeper/nxn_pointer.bend`の中心部分は次のとおりです。

```bend
def cell_if_valid(valid: Bool, n: U32, x: U32, y: U32) -> Maybe<&2, U32>:
  match valid:
    case True{}:
      Some{(U32.div(y, 32) * n + U32.div(x, 32) : U32)}
    case False{}:
      None{}

def cell_at(+n: U32, +x: U32, +y: U32) -> Maybe<&2, U32>:
  valid = Bool.and(
    Bool.and(U32.is_ge(n, 2), U32.is_lt(n, 101)),
    Bool.and(U32.is_lt(x, (n * 32 : U32)),
             U32.is_lt(y, (n * 32 : U32))))
  cell_if_valid(valid, n, x, y)
```

```sh
bend intermediate/minesweeper/nxn_pointer.bend
# 110
```

地雷のない10×10盤面で左上をクリックし、全マスが0連鎖で開いて勝利した結果です。110は勝利状態100と公開済み数字0のコード10の和であり、GUI画面の出力ではありません。

## 仕組みを確かめましょう

`x=319,y=319`は`(9,9)`、マス番号99です。対して`x=320`や`y=320`は画面の外なので`None`を返します。画面外の座標を`U32.div`で丸めてから操作してはいけません。右クリック（ボタン1）は旗、左クリック（0）は公開、それ以外のボタンは無視します。旗はゲーム開始前や終局後にはゲーム本体によって無効化されます。

`scripts/test_nxn_pointer.py`では、Pythonの整数除算による座標計算と、集合・BFSによる独立ゲームモデルを使って、Bend本体の型検査・実行結果を照合します。対象は有限個の座標と操作列です。Appのウィンドウやマウス入力を実機で試したことにはなりません。

## 演習

1. 10×10で`(31,31)`、`(32,31)`、`(319,319)`がどのマスになるか予想してみましょう。
2. 320ピクセルの境界をクリックしても旗や公開状態が変わらないことを確かめてみましょう。
3. 旗を置いたマスを左クリックしても開かない理由を、入力変換とゲーム本体の二段階で説明してみましょう。
4. 実際のGUIへつなぐとき、`n`とゲーム盤面サイズを必ず一致させる仕組みを考えてみましょう。
