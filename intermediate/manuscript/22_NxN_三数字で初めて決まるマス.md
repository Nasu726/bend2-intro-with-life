## 二数字の規則だけで十分でしょうか

ここまで、公開数字が0なら近傍は安全、未知集合が包含関係にあれば差を取れる、二つの集合が重なる場合は共通部分の地雷数に上下限を付けられる、と学びました。では、**どの二数字を組み合わせても確定手がない**場合は、もう推測するしかないのでしょうか。

3×3のマスを左上から0〜8番とし、0・2・7番を公開したところ、どれも数字が1だったとします。地雷の総数は2個です。公開済みの三マスには地雷がありません。公開盤面を行ごとに書くと次のようになります。

```text
 1  ?  1       番号: 0  1  2
 ?  ?  ?             3  4  5
 ?  1  ?             6  7  8
```

ここで `?` は未公開のマスです。実際の地雷位置を推論器へ渡さずに、番号1が地雷かどうか考えてみましょう。

## まずBendで二数字の規則を確認する

`intermediate/minesweeper/nxn_public_overlap.bend` は、**二つの**未知隣接集合と、それぞれに必要な地雷数を受け取ります。今回の公開数字から作る集合は、次の三つです。

```text
A（0番の数字1） = {1, 3, 4}       地雷1個
B（2番の数字1） = {1, 4, 5}       地雷1個
C（7番の数字1） = {3, 4, 5, 6, 8} 地雷1個
```

Bendの既存の実行可能な例では、例えば次のように**二集合だけ**を渡します。`tag` は結果の種類を表すため、`1` と表示されても「必ず確定手がある」という意味ではありません。安全・地雷のリストを確認する必要があります。

```bend
def main() -> U32:
  tag(infer([1, 3, 4], [1, 4, 5], 1, 1))
```

この入力を既存の `main` と入れ替えて試す場合は、元のコードを別に保存してから実行してみましょう。実行ファイルの型検査は `bend intermediate/minesweeper/nxn_public_overlap.bend --check-only` です。**この補稿の三数字連立をBendで実装・検証したわけではありません。** 現行のBend二数字推論器には、三つの制約を同時に受け取る入口がまだありません。

## 実行結果を独立した全列挙で確かめる

`intermediate/solutions/nxn_three_clue_oracle.py` は、3×3の未公開マスから地雷2個を選ぶ組合せをすべて調べ、公開数字に矛盾しない候補だけを残すPythonの**独立した検査用コード**です。読者用ZIPには入れず、リポジトリ側に置いています。

```sh
python3 intermediate/solutions/nxn_three_clue_oracle.py
```

```text

two (0, 7): ('ok', (), (), 5)
two (2, 7): ('ok', (), (), 5)
three: ('ok', (3, 4, 5), (1,), 2)
models: ((1, 6), (1, 8))
```

`('ok', safe, mines, 候補数)` の順に表示しています。**二数字のどの組も、安全・地雷のどちらも確定できません。** ところが三数字を合わせると、番号3・4・5が安全、番号1が地雷と確定します。残った候補は地雷集合 `{1,6}` と `{1,8}` の二つだけです。番号6と8のどちらに地雷があるかは、まだ分かりません。

## 総地雷数を知らなかったら、同じ結論でしょうか

ここまでの結論は、三つの公開数字だけでなく「地雷が全部で2個」という情報も使っています。条件を一つ外し、**地雷の総数を知らない**場合を比較してみましょう。Pythonの独立列挙器では、地雷数に `None` を渡すと、未公開6マスの地雷数0〜6をすべて調べます。

```python
from intermediate.solutions.nxn_three_clue_oracle import CLUES, deductions
print(deductions(3, None, CLUES))
```

```text
('ok', (3, 5), (), 3)
```

整合する配置は `{4}`、`{1,6}`、`{1,8}` の**3通り**です。3番と5番はどの配置でも安全ですが、1番は地雷と断定できず、4番も安全とは言えません。ここで総地雷数が2個だと分かると、地雷が1個しかない `{4}` を除外できます。残る2通りでは1番が地雷、3・4・5番が安全です。

**公開数字だけからの局所制約**と、**盤面全体の地雷総数による制約**は別の情報です。どちらを推論器に与えたかを明示しておけば、推論の保証を過大に説明せずに済みます。なお `None` は「地雷数0」という意味ではありません。

## なぜ三つで決まるのでしょうか

0番の数字は `x1+x3+x4=1`、2番は `x1+x4+x5=1`、7番は `x3+x4+x5+x6+x8=1` と表せます。`xi` はそのマスに地雷があれば1、なければ0です。さらに盤面全体の地雷数から `x1+x3+x4+x5+x6+x8=2` です。

最初の二式を引くと `x3=x5`。7番の式は `2*x3+x4+x6+x8=1` なので、`x3` は0でなければなりません。よって `x5=0`。0番と2番の式はともに `x1+x4=1` になります。7番の式は `x4+x6+x8=1`、総地雷数は `x1+x4+x6+x8=2` です。二式の差から `x1=1`、したがって `x4=0` と分かります。

これは**三数字と総地雷数を同時に使う推論**です。どの二数字だけを見ても、番号1は確定しません。二数字の推論器を一度呼んだ結果を、一般の連立制約ソルバーの結果と混同しないようにしましょう。
