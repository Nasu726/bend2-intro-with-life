# 第13〜14・21章補稿：初手で地雷を踏んでも安全にする

> **TeX本編・PDFには未統合**。ここでは N=2〜100 の盤面に対する、初手用の地雷移動だけを実装します。実際のゲームの Fresh→Playing 遷移、0連鎖、勝利判定、GUIへの接続は次の工程です。

## なぜ最初のクリックだけ特別扱いするのでしょうか

すでに地雷を配置した盤面では、最初のクリックが地雷に当たることがあります。ゲームを始める前に、地雷の総数を変えず、クリックしたマスを安全にできれば、初手の理不尽な敗北を避けられます。ただし、全マスが地雷なら移動先は存在しません。無理に成功させず、開始を拒否する必要があります。

## Bendで実行してみましょう

`minesweeper/nxn_relocate.bend` は、地雷がクリック位置にあれば、**添字の小さい順に最初の空きマス**を探して移します。

```bend
def main() -> U32:
  inspect(relocate(Words.set_checked(Words.new(10), 0, True{}), 0), 1)
```

```sh
bend intermediate/minesweeper/nxn_relocate.bend
# 1
```

10×10盤面の0番にある地雷は、空いている1番へ移ります。結果の`1`は検査用の符号で、移動後の1番に地雷が存在することを示します。`FirstClickSafe`は0または1、`FirstClickRejected`は2または3を返します。ゲーム画面で使う表示形式ではありません。

## 仕組みを確認しましょう

`first_free`は`Nat`の燃料を1ずつ減らして、`0`から`n*n-1`までだけを調べます。空きが見つかればクリック位置の地雷を消し、その空きに置きます。初手がもともと安全なら何も移しません。範囲外のクリックは`FirstClickRejected`とし、10×10の配列の余剰添字100〜127も読みません。盤面が全地雷の場合も`FirstClickRejected`にします。

`scripts/test_nxn_relocate.py`では、Bendの`U32`語列を使わないPython集合モデルと有限個の盤面・クリック・観測マスを照合します。**この有限テストは、任意の盤面に対する形式的証明ではありません。** また、まだ`nxn_step.bend`のクリック処理に接続していないため、通常ゲームで初手安全が自動適用されるわけではありません。

## 演習

1. 10×10の0番と1番に地雷を置いて0番を初手にしたとき、移動先が2番になることを予想して、実行してみましょう。
2. 2×2の4マスすべてに地雷がある場合の`FirstClickRejected`を確かめてみましょう。
3. 10×10で100番を初手に指定した場合、配列の余剰領域を読まずに拒否される理由を説明してみましょう。
4. 地雷移動後の盤面を`Step.new`へ渡すには、開始前と開始後をどのような型で分けるとよいか考えてみましょう。
