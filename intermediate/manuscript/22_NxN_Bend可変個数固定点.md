# 第22章補稿：任意個数の公開数字を反復する（入力検査の追補）

## なぜ三数字版と四数字版を統合するのでしょうか

これまでは公開数字が一つ増えるたびに、Bendの関数の引数と処理を増やしていました。実際のN×N盤面では公開数字の個数が変わるため、`Clue{index,value}`のリストを受け取る形に改善します。元の「残り地雷数0なら安全、未知マス数と等しければ地雷」の規則は変更しません。

## Bendのコードと出力

`intermediate/minesweeper/nxn_public_many_fixpoint.bend` を使います。

```bend
type Clue is Data:
  Clue{index: U32, value: U32}

def main() -> U32:
  Fix.score(infer_many(3, [Clue{1, 1}, Clue{2, 0},
                           Clue{4, 1}, Clue{5, 0}],
                       10n, Nil{}, [1, 2, 4, 5]))
```

```sh
bend intermediate/minesweeper/nxn_public_many_fixpoint.bend --check-only
bend intermediate/minesweeper/nxn_public_many_fixpoint.bend
# 6
```

期待値`6`は教材専用の符号`100×地雷確定数＋安全確定数`です。公開済みの1・2・4・5番に加え、7・8番が安全と確定します。隠された正解配置は推論器へ渡しません。

## 反復の仕組みと停止条件

公開数字は`List<&2, Clue>`に保存します。`Clue`は実行時の値なので`type Clue is Data:`と宣言します。`Type`と宣言すると、Bendの型検査では`List`が要求する`Data`と一致せず拒否されます。`one_round`はリストを再帰的に走査して既存の`Rule.infer`を各数字に適用し、地雷・安全の確定集合を引き継ぎます。`iterate`は一巡して集合に増分がなければその場で終了します。Bendでは計算結果を直接`match`できず、後方の未定義関数も参照できません。そこで初期状態の`changed=True`を「最初の周回を行う」という印に使い、`iterate`内で引数`state`を`match`して、次の周回が必要か判断します。

N×N盤面では新しく確定できるマスは最大N²個であり、変化する周回には必ず新しいマスが一つ以上あります。したがって`N²+1`回の燃料は収束の十分条件です。指定燃料が足りなければ`Limit`を返し、成功と誤認しません。

公開数字の位置は初期安全集合に含める必要があり、同じ公開マスの重複・盤外・不可能な値を拒否します。追加した**リポジトリ専用の検査ラッパー** `nxn_public_many_checked.bend` では、初期確定地雷・安全のリストが**範囲内・厳密昇順（重複なし）・互いに交わらない**ことを検査します。読者ZIP内の従来サンプル `nxn_public_many_fixpoint.bend` は、この追補を含まないため、初期集合の構造的妥当性は引き続き呼び出し元が確認してください。公開数字が0個でもこの検査を省略しません。ただし、公開済み以外の確定情報が**実際に正しいこと**は呼び出し元の契約です。プレイヤーの旗は地雷確定の根拠ではありません。

これは**公開数字の個数を一般化した単独制約の固定点**であり、複数制約を連立して得る結論、全盤面の充足可能性、一般N×Nの運ゲー無し生成は保証しません。

## 入力検査を強化する理由と実装

局所推論は公開数字の近傍しか調べません。公開数字が空のとき、初期集合に同じマスを地雷・安全の両方として渡しても、近傍の検査だけでは矛盾を発見できません。例えば `infer_many(3, Nil{}, 1n, [0], [0])` を成功扱いしてはいけません。

今回のBend追補では、読者ZIPの元のサンプルを変更せず、`nxn_public_many_checked.bend` に初期集合を走査する `valid_initial_list` と、両集合の検査を組み合わせる `valid_initial` を追加します。`infer_many_checked` は構造検査に成功した場合だけ元の `Many.infer_many` を呼び出します。

```bend
# 厳密昇順かつ盤面内、反対側の集合に同じ番号がないことを確認
# 前の番号は Maybe<&2,U32> で表す
def after_previous(previous: Maybe<&2, U32>, +item: U32) -> Bool:
  match previous:
    case None{}:
      True{}
    case Some{old}:
      U32.is_lt(old, item)
```

最初の番号には比較対象がないので `None{}` から始めます。次の番号が前より大きくなければ、重複や逆順を拒否します。各要素が `Geo.valid_index` を満たすか、反対側の集合に含まれないかも確認します。**検査ラッパーを使う場合は、公開数字0個でも同じ検査を先に行う**ため、矛盾を「固定点」と誤認しません。これは入力の**構造的な検査**であり、別の証拠なしに地雷位置の真偽を証明するものではありません。

検証用テストは、重複・逆順・範囲外・重複所属の7拒否例と、公開数字なしで初期情報だけを持つ2正常例を追加します。これによりBendとPythonの照合条件は19から28へ増えます。型検査と実行が通ったら、`[0]`を地雷・安全の両方に指定した例、初期安全リスト`[2,1]`を渡した例、正常な空公開リストの例を自分で試してみましょう。

## テストと演習

`python3 intermediate/scripts/test_nxn_public_many_fixpoint.py`では、公開数字0〜9個の局面、既知地雷、入力拒否、燃料不足を含む**28条件**について独立PythonモデルとBendの確定集合を照合します。追加の9条件は、公開数字が空でも矛盾・重複・範囲外・順序違反を拒否し、正常な初期集合なら終了することを確かめます。`python3 -m unittest intermediate.tests.test_nxn_public_many_reference -v`では、3×3の160有限局面について全候補列挙の健全性検査を行い、三・四数字版との一致も調べます。いずれも任意Nの形式的証明ではありません。

## 3×3の全公開状態を調べ、完全性の限界を確認する

「公開数字の個数に依存しない」というのは、あらゆる公開状態を完全に解けるという意味ではありません。3×3盤面の各マスを「地雷・未公開の安全・公開済みの安全」の3状態に分けると、真の地雷配置と公開位置の組は\(3^9=19,683\)通りです。同じ公開数字が得られる状態をまとめると**8,631種類**になります。

独立した全候補配置の列挙を正解とし、Python参照モデルの単独数字規則の固定点を比較しました。**誤確定は0状態**でしたが、全候補から得られる結論と一致したのは**6,959状態**、推論が不足したのは**1,672状態**です。公開数字が3個のときは2,176状態のうち676状態、4個のときは3,088状態のうち728状態で結論を取りこぼしました。これは**Python参照モデルに対する3×3有限監査**であり、Bendの全8,631状態を実行したものでも、一般N×Nの全称証明でもありません。

具体例として、3×3の公開数字が `(1,1)` と `(4,1)` だけのとき、単独数字規則は1・4番の既知安全から進みません。しかし候補は4通りしかなく、どれでも6・7・8番は安全です。二つの数字の近傍集合を差し引けば、この安全性を導けます。

`python3 -m unittest intermediate.tests.test_nxn_public_many_exhaustive -v` でこの全列挙監査を再実行できます。二つの近傍集合を図示し、差集合が安全になる理由を説明してみましょう。

まず公開数字を空リストにして何も確定しないことを確かめてみましょう。次に公開数字`(0,0),(2,1),(6,1)`の三つへ変えて期待値`206`を得てみましょう。最後に反復燃料を`1n`へ減らし、`Limit`になる局面とならない局面を比較してみましょう。
