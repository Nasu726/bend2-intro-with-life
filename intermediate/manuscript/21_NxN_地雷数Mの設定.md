# 第21章補稿：盤面サイズNと地雷数Mを別々に設定しましょう

> 編集用補稿（PDF未収録）。以下のBend例はN×Nゲームの公開状態を扱う途中段階です。クリック処理、旗、勝敗、GUIの完成を意味しません。

## なぜ二つの値が必要なのでしょうか

10×10の盤面に地雷を10個置くのは、これまでの**検証用の一例**です。同じ10×10でも、地雷が7個なら易しく、20個なら難しくなります。盤面の幅を表す`N`と地雷の個数を表す`M`を一緒に固定してしまうと、難易度や演習条件を変えられません。

ここでは`2 <= N <= 100`、`0 <= M < N*N`とします。少なくとも一つ安全なマスを残す設定です。運ゲー無し候補生成で初手と周囲8マスを必ず安全にしたい場合は、その保護領域を除いた個数までしか地雷を置けません。

## Bendのコードで確かめましょう

`intermediate/minesweeper/nxn_public_state.bend`には、設定の検査と公開情報だけを保持する関数があります。

```bend
def valid_config(+n: U32, +m: U32) -> Bool:
  Bool.and(Geo.valid_size(n), U32.is_lt(m, (n * n : U32)))

# valid_config(n, m) が True のときに生成します。
def new(+n: U32, +m: U32) -> PublicState:
  PublicState{n, m, Bits.new(n),
    Array.new(U32,
      Bits.depth_loop(15n, U32.is_lt(1, (n * n : U32)), 1, 0n, (n * n : U32)), 0)}
```

例えば、別の学習用ファイルから`Public.new(10, 7)`と書けば、10×10・地雷7個という設定を渡せます。総地雷数を取り出す`total_mines`は公開状態と数値を一緒に返すため、Bendの所有権を失いません。

```bend
import Base
import ./nxn_public_state.bend as Public

def main() -> U32:
  Public.read_value(Public.total_mines(Public.new(10, 7)))
```

**期待する出力は`7`です。** 実際のBend実行照合は検証ゲートで確認します。

## なぜ地雷位置を入れないのでしょうか

プレイヤーは地雷の**総数M**を知っていても、どのマスが地雷かは知りません。推論器に必要な入力は、盤面サイズ、M、公開済みマスと数字です。内部の地雷位置は、クリックを処理するゲーム側で別に持ちます。

`PublicState`の読み取りと公開操作では、Mを変更しません。BendではArrayやビット集合を戻しながら処理する必要があるため、`read_opened`などの短い補助関数が存在します。意味のある処理単位に分けたもので、単に行数を減らすためには統合しません。

現在のN×N版は公開状態までの実装です。実際に地雷をM個配置したか、勝利時に安全マスを`N*N-M`個開いたかは、今後ゲーム状態遷移に組み込んで検証します。

## 演習

1. `valid_config(10, 7)`、`valid_config(10, 99)`、`valid_config(10, 100)`の結果を予想して確かめてみましょう。
2. `N=4, M=2`のとき、勝つために開く必要のある安全マス数を求めてみましょう。
3. 同じ`N=10`で`M=0`と`M=10`を比べ、0領域の公開がどのように変わるか考えてみましょう。
4. Python参照実装の`generate_no_guess_frontier(width, height, mine_count, ...)`でMを変え、採用できない候補や探索上限不足と「不可能である証明」を区別してみましょう。
