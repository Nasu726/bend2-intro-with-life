# 第13〜14・21章補稿：0のマスから広がる公開処理

> **TeX本編・配布PDFには未統合**。この節はN=2〜100の配置済み盤面に対する0連鎖部品です。初手の地雷移動・勝利状態・GUI・運ゲー無し生成器との統合は別工程です。

## なぜ一つのマスだけでは足りないのでしょうか

マインスイーパーでは、地雷が隣接しない「0」のマスをクリックすると、周囲の安全なマスが自動的に開きます。さらに開いたマスも0なら、その周囲を調べます。前節で作った `nxn_neighbors.bend` の近傍リストを、次の探索候補として使いましょう。

## Bendコードと実行結果

`minesweeper/nxn_flood.bend` は、配置済み盤面の `Step.Session` を受け取り、`Step.click` の後に0領域を展開します。実行例では4×4の15番だけが地雷です。

```bend
def main() -> U32:
  board = Words.set_checked(Words.new(4), 15, True{})
  Step.snapshot(click(Step.new(board), 0), 14)
```

```sh
bend intermediate/minesweeper/nxn_flood.bend
# 11
```

14番は地雷15番に隣接するため数字1のマスです。`Step.snapshot` の「10＋数字」という符号化により、出力は11になります。0番からの連鎖によって、14番を直接クリックしなくても公開されます。

## どのように停止するのでしょうか

探索待ちの `List<U32>` から一つ取り出し、**まだ隠れている安全マス**だけを開きます。数字が0のときに限り、その近傍を待ちリストへ追加します。旗付きマス・公開済みマスは変更せず、地雷は防御的に再確認します。

一つの0マスが近傍を追加するのは最初に開かれたときだけです。最大 `n*n` 個の0マスが各8個以下の候補を追加するため、最初のクリックを含めて `8*n*n+1` 回の探索で待ちリストは空になります。`explore` はこの上限を `Nat` の燃料に変換し、各再帰で必ず1減らします。これは**停止性の上界**であり、100×100の空盤面の速度・メモリ消費を実機で保証するものではありません。

`scripts/test_nxn_flood.py` はPythonの独立した座標BFSと有限のクリック・旗操作列を照合します。4×4の地雷15番、10×10の行境界、17×17の空盤面、100×100の局所クリック、範囲外添字を区別します。これは全入力に対する形式的証明ではありません。

## 演習

1. 4×4で15番だけが地雷のとき、0番からの公開で14番が数字1になる理由を、近傍の添字から確かめてみましょう。
2. 1番に旗を立ててから0番をクリックし、旗のマスだけは公開されないことを確かめてみましょう。
3. 10×10で地雷を9番に置き、10番をクリックしてみましょう。9番と10番が行境界を越えて隣接していない理由を説明してみましょう。
