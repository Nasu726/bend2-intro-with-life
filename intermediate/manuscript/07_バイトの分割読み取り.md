# 第7章補稿：バイト列を分割して読み込む

## 必要性
`File.read_bytes(file, 16)` の `16` は「16バイトを必ず返す」という約束ではなく、1回の読み込み量の上限です。保存ファイルを読み込むときに「要求した長さ」と「実際に返った長さ」を区別する必要があります。特にファイル終端を越えて読み込もうとした場合を確かめます。

## 実行できるBendコード
`intermediate/scripts/fixtures/binary_chunks.bend` は、`sample_bytes.bin` を読み込み用に開き、`File.read_bytes(file, 2)` を3回呼びます。各回の `List.length` を表示し、返されたハンドルを次の読み込みへ渡して、最後に閉じます。読み込みが `Fail` ならハンドルを閉じて失敗を伝えます。

```bash
python3 intermediate/scripts/test_byte_file_chunks.py
```

このテストは独立したPython 3から長さ0〜5のバイナリファイルを用意し、Bend本体を型検査・実行して、ファイルが書き換わらないことまで確かめます。

## 実行結果
ローカルの通常ファイルについて、期待する3回の読み込み長は以下の通りです。検証用PR #81では、Bendの型検査・実行照合と通常ファイル0〜5バイトの検査がCIで成功しました。以下はその有限な検証範囲での期待値です。

| 元の長さ | 1回目 | 2回目 | 3回目 |
| ---: | ---: | ---: | ---: |
| 0 | 0 | 0 | 0 |
| 1 | 1 | 0 | 0 |
| 2 | 2 | 0 | 0 |
| 3 | 2 | 1 | 0 |
| 4 | 2 | 2 | 0 |
| 5 | 2 | 2 | 1 |

## 仕組みと限界
`File.read_bytes` は `File & Result<..., List<...,U32>>` を返します。1回目の返り値に含まれるハンドルを2回目に渡すため、読み取り位置が進みます。`Done` で長さ0のリストが返ると、今回の通常ファイルでは終端に達したことを確認できます。ただし、この有限テストは通常ファイルの0〜5バイトだけを対象とし、パイプ・ソケット・途中の短い読み取り・全OSに対する保証ではありません。長さだけでは内容の一致を証明できないため、既存の `45_binary_file.bend` と実ファイルのバイト照合も必要です。

## 演習
`File.read_bytes(file, 2)` を `File.read_bytes(file, 3)` に変え、長さ0〜5の各ファイルで何が表示されるか予想してから試してみましょう。次に読み取り上限より長いファイルで、終端まで読むにはどのような反復が必要か考えてみましょう。
