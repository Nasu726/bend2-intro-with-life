## 一つずつ数字を調べても、動けないときがあります

マインスイーパーでは、一つの公開数字だけでは安全なマスを特定できなくても、**二つの数字が共有する未知マス**を比べると手が決まることがあります。さらに、その結果を別の公開数字に伝えれば、追加の確定手を得られます。

3×3盤面のセル番号を上段から `0 1 2 / 3 4 5 / 6 7 8` とします。公開数字は `(1, 1)` と `(4, 1)` だけです。数字を一つずつ調べる参照実装では、どのマスも確定しません。

## Bendの二数字カーネルを使ってみましょう

既存の `intermediate/minesweeper/nxn_public_subset.bend` には、二つの未知近傍集合の包含関係を使う `infer` があります。公開済みの1番と4番を除いた未知近傍は次の通りです。

- 1番の近傍：`[0, 2, 3, 5]`、残り地雷数1。
- 4番の近傍：`[0, 2, 3, 5, 6, 7, 8]`、残り地雷数1。

この二つの集合と数字を、既存Bendコードの `infer` に渡せます。

```bend
# nxn_public_subset.bend の infer / tag を使う呼び出し例
# 1番の未知近傍は4番の未知近傍に含まれる。
def main() -> U32:
  tag(infer([0, 2, 3, 5], [0, 2, 3, 5, 6, 7, 8], 1, 1))
```

返る判定は `Safe{indices: [6, 7, 8]}`、タグに変換すると `1` です。これは**二数字の一回分**の推論であり、複数の数字を自動的に繰り返し調べる機能ではありません。

## Python参照実装で反復させましょう

`intermediate/solutions/nxn_pairwise_propagation.py` は、既存の一数字規則と、二数字の共通部分に対する地雷数の上下限を交互に適用します。次のコードは `intermediate/solutions/` で実行します。

```python
from nxn_single_clue_propagation import infer_single_clue_certainties
from nxn_pairwise_propagation import infer_pairwise_clue_certainties

opened = ((1, 1), (4, 1))
print(infer_single_clue_certainties(3, opened))
print(infer_pairwise_clue_certainties(3, opened))
```

```text
((), ())
((), (6, 7, 8))
```

二数字の共通部分に含まれない `6, 7, 8` は、追加の地雷を含めません。どちらの公開数字も1で、1番の未知近傍が4番の未知近傍にすべて含まれるためです。

## なぜ正しいのでしょうか

二数字の未知近傍を `A`, `B`、残り地雷数を `rA`, `rB` とします。共通部分 `I=A∩B`、片方だけの部分 `X=A\\B`, `Y=B\\A` に分けると、共通部分の地雷数 `t` は次を満たします。

```text
max(0, rA-|X|, rB-|Y|) <= t <= min(|I|, rA, rB)
```

各領域の地雷数の上限が0なら全マス安全、下限がその領域のマス数と等しければ全マス地雷です。新たな確定情報を一数字推論へ戻し、集合が増えなくなるまで反復します。共通部分があり得る数字の組だけを調べるので、離れた数字同士を総当たりしません。

**保証の境界**：入力する数字は実際に公開済みの値、初期の確定集合は別途証明済みのものに限ります。旗や隠された地雷配置を証拠にしません。3×3の独立した240局面について、全候補配置の列挙で確定結果の健全性を検査しました。これは一般N×Nの全称証明ではありません。また、局所矛盾がないことは盤面全体の充足可能性を保証しません。**反復の実装はPython参照であり、Bendの二数字カーネルを反復ソルバーへ接続したわけではありません。**
