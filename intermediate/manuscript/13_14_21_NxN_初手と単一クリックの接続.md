# 第13〜14・21章補稿：初手の地雷移動をゲームのクリックへ接続

> **TeX本編・PDFには未統合**。N=2〜100で初手安全と単一マスのクリックを接続します。0連鎖・勝利判定・GUI・運ゲー無し生成は対象外です。

## なぜ地雷移動だけではゲームにならないのでしょうか

前節の `nxn_relocate.bend` は地雷を安全な位置へ移せますが、その結果をクリック処理へ渡していません。初手で地雷を移しただけでは、マスはまだ閉じたままです。そこで「開始前」と「開始後」を型で区別し、移動に成功したときだけ盤面を開くようにしましょう。

## Bendで実行してみましょう

`minesweeper/nxn_start.bend` の入口は次のとおりです。10×10の0番に地雷を置いてから、最初のクリックで0番を開きます。

```bend
def main() -> U32:
  snapshot(click(new(Words.set_checked(Words.new(10), 0, True{})), 0), 0)
```

```sh
bend intermediate/minesweeper/nxn_start.bend
# 11
```

初手の0番の地雷が最小の空き添字1へ移るので、0番には近傍地雷数1が表示されます。検査用の `11` は `Open{1}` を表し、画面の表示コードではありません。

## 仕組みを確かめましょう

`Stage` は `Fresh{board}` と `Active{session}` の二つです。`Fresh` へのクリックは `Relocate.relocate` を通し、`FirstClickSafe` なら `Step.new` と `Step.click` で最初の一マスを開きます。盤外クリックや全マス地雷なら `Fresh` のままなので、次の有効なクリックを受け付けられます。開始前の旗操作は無視する設計です。

開始後のクリックと旗は `nxn_step.bend` に委譲します。したがって、開始後に地雷を踏めば敗北し、敗北後の入力は無効です。**初手の安全は、二手目以降の安全を意味しません。** また、0の周辺を連鎖公開したり、全安全マス公開後に勝利と判定したりする機能はまだありません。

`scripts/test_nxn_start.py` は Python の集合と座標計算を独立の期待値として使い、Bendの型検査と実行結果を有限ケースで照合します。配列の余剰添字、全マス地雷、初手後の敗北も検査します。ただし任意の盤面についての全称証明やGUI実機検証ではありません。

## 演習

1. 10×10の0番と1番に地雷を置き、0番を初手にしたときの移動先と数字を予想し、実行してみましょう。
2. 最初に100番をクリックし、次に0番をクリックしたとき、二回目が最初の有効クリックになることを確かめてみましょう。
3. 初手0番の後に1番をクリックして敗北する場合と、初手の前に1番へ旗を付けようとする場合を比べてみましょう。
4. `Step.click` が0連鎖を実装したとき、この `Stage` をどのように再利用できるか考えてみましょう。
