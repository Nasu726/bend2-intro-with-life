# 第3章補稿：ListとArrayを選ぶ

> 編集状態：本文へ統合するための原稿。現行プレビューPDFにはまだ収録していません。
> 対応する既存サンプル：`03_list.bend`、`17_list_pipeline.bend`、`18_array_mutations.bend`、`30_array_clone.bend`。いずれも学習用ZIPの `examples/` にあります。

## この章でできるようになること

前巻では、複数の値を並べる方法を学びました。しかし実際のプログラムでは、「値を順番に調べたいだけなのか」「番号を指定して書き換えるのか」によって選ぶ構造が変わります。本章では `List` と `Array` のどちらを選ぶべきか、**何をしたいか**から判断する方法を学びます。

まず、二つの小さな課題を考えます。

一つ目は、並んだ数字のうち3未満の値だけを取り出し、その合計を求めることです。二つ目は、4×4の盤面でクリックされた7番目のマスの状態を更新することです。前者は並びを一度ずつたどれば十分です。後者では、決まった番号の位置を書き換えたいので、`Array` が自然です。

ただし、`List` が常に読み取り専用、`Array` が常に高速、と決めつけるのは正確ではありません。使用するAPIの入力と返り値、要素の取り出し方、値の所有権を確認して選びましょう。

## 1. Listで「選んで集計する」

まず `examples/17_list_pipeline.bend` を実行します。

```sh
bend examples/17_list_pipeline.bend
```

結果は `3n` です。計算の出発点は、次のコードです。

```bend
def small(n: Nat) -> Bool:
  Nat.is_lt(n, 3n)

def sum(acc: Nat, n: Nat) -> Nat:
  Nat.add(acc, n)

def main() -> Nat:
  xs = List.range(4n)
  ys = List.filter(~Nat, ~small, xs)
  List.foldl(~&2, ~Nat, ~Nat, ~sum, ys, 0n)
```

`List.range(4n)` が作るのは、`0n`、`1n`、`2n`、`3n` という列です。`small` は3未満かどうかを返します。したがって `List.filter` を通過するのは `0n`、`1n`、`2n` の三つです。それらを `List.foldl` が左から順に足すので、最終的な値は `3n` となります。

`filter` と `foldl` は**高階関数**です。別の関数を引数として受け取るため、抽出の基準や集計の内容を差し替えられます。ここでは `small` が抽出の基準、`sum` が集計の規則を表します。

`foldl` の最後の `0n` は、合計の**初期値**です。例えば初期値を `10n` に変えると、計算は10から始まり、結果も10だけ増えます。「列をどの順序で処理するか」「初期値は何か」を変えると、同じ高階関数でも意味が変わることに注意してください。

### なぜ自分で再帰を書かないのか

ここで `List` の先頭を `match` で取り出し、残りに対して再帰する関数を自分で書くこともできます。しかし今回必要なのは「条件で絞る」と「集計する」という一般的な操作です。標準ライブラリがその処理を直接提供しているので、`filter` と `foldl` を使う方が、読み手も計算の目的をつかみやすくなります。

反対に、独自の再帰の方が状態の遷移や停止条件を明快に書ける場合もあります。高階関数を使うこと自体が目的なのではなく、意図が読み取りやすい形を選ぶことが大切です。

### `~Nat` や `~&2` は何を指定しているのか

Bend 2の `List` は、要素の型だけでなく、要素を何回扱えるかという**数量**も型の一部として持ちます。実装が扱う型・数量を明示する箇所では、`~` を付けた消去引数が現れます。`~&2` はこの例の `List` の数量の指定です。まずはコードを実行し、次に `bend base List.filter` や `bend base List.foldl` を使って正しい引数順序を確認しましょう。

```sh
bend base List.filter
bend base List.foldl
```

前巻のアフィン性と結び付けて考えてみてください。引数を無制限に複製できる言語のつもりで値を使い回すと、型検査で止められることがあります。

## 2. Arrayで「番号を指定して書き換える」

次は `examples/18_array_mutations.bend` を読みます。

```bend
def main() -> U32:
  a = Array.new(U32, 3n, 0)
  b = Array.set(U32, a, 2, 17)
  c = Array.set(U32, b, 7, 25)
  x = read_and_sum(Array.get(U32, c, 2))
  x
```

これは、8個の `U32` のうち、添字2の値を17、添字7の値を25へ更新するプログラムです。実行結果は17になります。

ここには、初めて読むと誤解しやすい点が三つあります。

**第一に、`Array.new` の第2引数は要素数そのものではありません。** この例の `3n` は二分木の深さで、要素数は `2^3 = 8` です。もし4×4の盤面を一つの配列に格納するなら、`Array.new(Game.Square, 4n, Game.Hidden{})` で16マス分を作れます。

**第二に、`Array.set` は更新後の配列を返します。** `a` を更新してからも当然使えると考えるのではなく、戻ってきた `b`、続いて `c` を次の操作へ渡します。Bendのアフィンな値の取り扱いでは、この受け渡しが重要です。

**第三に、`Array.get` は値だけを返すとは限りません。** この例で呼び出している `Array.get(U32, c, 2)` の結果は、配列と読み出した値の組です。サンプルの `read_and_sum` はその組を受け取って読み出した値だけを返します。続けて同じ配列を使うなら、組の中から返された配列を取り出して次の処理へ渡す必要があります。

### 盤面外の番号に注意する

ゲームでは座標の入力元がマウスです。画面端の外側をクリックしたときの値を、そのまま `Array.get` に渡してはいけません。`Array` の低水準APIが盤面の意味での範囲外を拒否してくれるとは限らないからです。

4×4のゲームなら、まず `index < 16` を確認し、有効な位置だけを更新します。実際の [`board4.bend`](../minesweeper/board4.bend) では `toggle_checked` と `reveal_checked` がこの確認を行います。配列の挙動をゲームの規則と混同しないことが大切です。

## 3. Arrayを調べた後にも保持したい

最後に `examples/30_array_clone.bend` を実行します。結果は `22` です。なぜ22なのでしょうか。

このサンプルでは、4要素すべてが5の配列を作り、`Array.clone` で二つに分けます。片方の添字0だけを17に変更し、もう片方の添字0を読みます。変更した方の17と、変更していない方の5を足すので `22` になります。

ここで重要なのは、**どちらの配列を変えてもよいのか**です。`Array.clone` は独立した複製を作るため、一方の更新がもう一方へ及ばないことを期待して使います。`Array.fork` も配列を二つの経路へ渡すためのAPIですが、独立コピーを作る `clone` と同一視してはいけません。共有された実体の変更が関係する場面では、競合や操作順序を別途考える必要があります。

完成途中のマインスイーパーでも、勝利判定で似た問題が起こります。安全なマスがすべて開いているか確認したい一方で、判定後も盤面を保持しなければなりません。[`board4.bend`](../minesweeper/board4.bend) は `Array.clone` で保持用と検査用へ分け、検査用の方を `Array.to_list` で `List` に変換して調べます。この目的で標準APIを使うのは自然な設計です。

ここで無理に抽象的な配列走査フレームワークを作る必要はありません。すでにある `clone`、`to_list` と、短い再帰で意味を表せています。もし後で多くの箇所に同じ走査が現れたら、そのときに共通化を検討すればよいのです。

## 4. どの構造を選ぶか

| 目的 | まず検討する機能 | 判断の理由 |
| --- | --- | --- |
| 並んだ値を条件で絞り込む | `List.filter` | 何を残すかを関数で表せる |
| 並んだ値を一つの値へ集計する | `List.foldl` | 初期値と更新規則を分けられる |
| 盤面の番号を指定して更新する | `Array.get`・`Array.set` | 添字による位置の指定が必要 |
| 独立した状態を二つ持つ | `Array.clone` | 一方の更新を他方へ伝えない |
| 配列を順番に検査する | `Array.to_list` など | 配列の意味を保ちながら列の処理を使える |
| ある位置が集合に含まれるか知る | `Set.has` | 重複のない要素の存在を扱う |
| キーに対応する値を保存する | `Map.get`・`Map.set` | 名前と値の対応を扱う |

この表は「いつでもその構造が最適」という決まりではありません。処理に必要な操作を、読みやすく正しく書けるかどうかが判断基準です。

## 5. 自分で確認する

次の順で試してみましょう。予想を立て、Bendを実行し、最後にその理由を説明することが目的です。

1. `17_list_pipeline.bend` の `small` を「2未満」に変えたとき、`main` は何を返すでしょうか。さらに `foldl` の初期値を `5n` にするとどうなるでしょうか。
2. `18_array_mutations.bend` の `Array.new(U32, 3n, 0)` を深さ `2n` へ変更した場合、どの添字が有効でなくなるでしょうか。書き換える前に確認してください。
3. `30_array_clone.bend` で、複製した二つの配列の双方の添字0に異なる値を設定したら、どちらの値が読み出されるでしょうか。
4. 4×4マインスイーパーの公開状態を `Array` から `List` へ替えたと仮定します。クリックされた添字を更新するコードは簡単になるでしょうか。何を探し直す必要があるか説明してください。

どの課題でも、**「実行結果が正しい」だけでなく、どのAPIのどの性質に依存しているか**まで説明できたら、この章の目的を達成できています。

### 補足：検証の範囲

この章で示した四つの既存コードはCIで型検査され、出力を照合しています。ただし、`Array.fork` の共有ハンドルに関する実機並列テストや、あらゆる添字での安全性まで検証したことにはなりません。機能名を知ることと、失敗条件を理解して使えることは分けて考えます。
