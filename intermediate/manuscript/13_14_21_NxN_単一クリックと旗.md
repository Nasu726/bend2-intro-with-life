# 第13〜14・21章補稿：N×Nのクリックを一段ずつ実装する

> **TeX本編・PDFには未統合**。ここで実装するのは、すでに地雷が置かれた盤面の「一マスだけを開く」遷移です。初手安全、0の連鎖公開、勝利判定、GUI、一般サイズの運ゲー無し生成はまだ実装していません。

## なぜ数字を数えるだけでは足りないのでしょうか

地雷の位置と周囲の数字を計算できても、プレイヤーが押したマスを記録しなければゲームにはなりません。まずは公開状態を `Hidden`・`Flag`・`Open{clue}` に分け、旗のあるマスを開かず、地雷を踏んだら敗北する、という最小の状態遷移から確かめましょう。

## Bendで実行してみましょう

`minesweeper/nxn_step.bend` は、すでに検査済みの `nxn_mine_words.bend` と `nxn_clues.bend` を組み合わせます。

```bend
def main() -> U32:
  snapshot(click(new(Words.set_checked(Words.new(10), 1, True{})), 0), 0)
```

```sh
bend intermediate/minesweeper/nxn_step.bend
# 11
```

10×10盤面の添字1に地雷があり、添字0をクリックすると、数字1の公開状態になります。検査用の `snapshot` は、`Playing=0`、`Lost=200` に公開状態コード（`Hidden=0`、`Flag=1`、`Open{clue}=10+clue`）を足した値です。通常のUIにこの符号化を使う必要はありません。

## なぜ範囲外のマスを先に拒否するのでしょうか

Bendの`Array`は2の累乗の容量を持つため、10×10盤面では100〜127が余剰スロットになります。`Geo.valid_index`で`index < n*n`を確かめてから`Array.get`を呼ぶことで、範囲外クリックが有効マスに折り返すことを防ぎます。旗を付けたマス・既に開いたマスへのクリックは状態を変えず、`Lost`後の入力も無効です。

`scripts/test_nxn_step.py` は、Pythonの集合・座標計算で独立に求めた有限な期待値と、Bendの型検査・実行結果を照合します。**このテストの成功は、まだN×Nゲーム全体の完成や全称証明を意味しません。**

## 演習

1. 10×10で地雷を添字9に置き、添字10を開いたときの数字を予想して、実行してみましょう。
2. 添字99に旗を付けてクリックし、旗を外してから同じマスを開く場合を比べてみましょう。
3. 添字100や127への操作が無視される理由を、論理サイズと配列容量に分けて説明してみましょう。
4. 次の工程として、初手安全・0の連鎖・勝利判定をどの順番で接続するか考えてみましょう。
