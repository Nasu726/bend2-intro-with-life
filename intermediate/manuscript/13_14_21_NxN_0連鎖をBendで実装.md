# 第13〜14・21章補稿：0のマスから連鎖して公開しましょう

> **TeX本編・PDFには未統合**。N=2〜100のアクティブな盤面に対する0連鎖の独立部品です。初手安全移動、勝利状態、GUIはまだこの部品と接続していません。

## どうして一マスのクリックだけでは足りないのでしょうか

マインスイーパーで数字が0のマスを開くと、周囲のマスも自動で開きます。周囲に新たな0があれば、さらにその隣を調べます。一方、数字が1以上のマスでは連鎖を止め、旗の立ったマスを勝手に開いてはいけません。既存の`nxn_step.bend`は一マスだけ開くので、この連鎖を担当する小さな処理を追加しましょう。

## Bendコードと実行結果

`minesweeper/nxn_flood.bend`の入口は、既存の`Step.Session`を受け取って返します。

```bend
def reveal(session: Step.Session, +index: U32) -> Step.Session:
  match session:
    case Step.Session{+n, mines, cells, phase}:
      explore(U32.to_nat((8 * n * n + 1 : U32)),
              Task{Step.Session{n, mines, cells, phase}, [index]})

def main() -> U32:
  session = reveal(Step.new(Words.new(3)), 0)
  Step.snapshot(session, 8)
```

```sh
bend intermediate/minesweeper/nxn_flood.bend
# 10
```

地雷のない3×3盤面で左上を開くと、右下（添字8）まで0の連鎖が届きます。出力の`10`は「公開済みで数字0」を表す検査用コードです。

## 仕組みを追いましょう

`Task`は盤面と作業待ちの`List<U32>`を保持します。取り出したマスが`Hidden`なら、既存の`Step.click`で一マス公開します。結果が`Open{clue=0}`なら、`nxn_neighbors.bend`で列挙した隣を作業リストへ追加します。`Flag`と既に`Open`のマスはそのまま通過するため、旗の保護と重複公開の防止ができます。地雷を直接クリックしたときは`Lost`になり、連鎖を止めます。

一つの0マスは初めて開いたときにしか近傍を追加しません。したがって作業は最大でも`1 + 8 × N × N`件です。`Nat`の燃料を毎回減らすので、同じ添字が作業リストに重複しても探索は必ず停止します。これは**有限の作業量上界**であり、全盤面での実行時間を測定したという意味ではありません。

`scripts/test_nxn_flood.py`ではPythonの独立した座標計算とBFSを使い、0領域・数字の境界・旗・地雷クリック・再クリック・盤外を照合します。N=100については局所的なケースのみを対象とし、100×100全面連鎖の性能や全称的な正しさは未検証です。

## 演習

1. 3×3の地雷なし盤面で中央に旗を立ててから左上を開き、中央だけが開かないことを確かめてみましょう。
2. 10×10の2行目に地雷を横一列に並べ、左上からの連鎖が数字の境界で止まることを確かめてみましょう。
3. `1 + 8 × N × N`が作業回数の上界になる理由を、同じ0マスが二度展開されないことから説明してみましょう。

**次工程**：`nxn_terminal.bend`のクリック入口へ連鎖を接続し、連鎖完了後に`nxn_victory.inspect`を一度呼んで勝利を確定させます。初手安全との統合後は、独立BFSで操作列を照合します。
