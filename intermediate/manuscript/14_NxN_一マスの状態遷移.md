# 第13〜14章補稿：N×Nの旗とクリックを一マスずつ動かす（PDF未統合）

## 盤面の数字が計算できても、まだゲームではありません

`nxn_mine_words.bend` は地雷の位置を保存し、`nxn_clues.bend` は周囲の地雷数を計算できます。しかし、プレイヤーが旗を立てたマスをクリックしても開かないこと、一度開いたマスを旗に戻せないこと、盤外の番号を受け取っても別のマスを誤操作しないことは、別に実装しなければなりません。10×10の盤面では100番以降は無効です。Arrayの容量が128になっていても、100〜127番をゲームのマスとみなしてはいけません。

## 実際のBendコード

`intermediate/minesweeper/nxn_actions.bend` では、地雷・開いたマス・旗をそれぞれ`MineWords`で保持します。地雷情報を表示用の関数へ直接渡さず、`public_at`からは公開済みの数字だけを返します。ファイル末尾の例を実行してみましょう。

```bend
import Base
import ./nxn_mine_words.bend as Words

# nxn_actions.bend の main（抜粋）
def main() -> U32:
  board = Words.set_checked(Words.new(10), 1, True{})
  public_value(public_at(click(new(board), 0), 0))
```

```sh
bend intermediate/minesweeper/nxn_actions.bend
# 1
```

0番の右隣にある1番が地雷なので、0番を開くと数字1が表示されます。これは「安全な一マスを開く」最小例です。**0の連鎖公開、初手の地雷移動、勝利判定はまだありません**。

## 仕組みを追ってみましょう

`checked`はまず`Geo.valid_index`で論理的な添字を検査します。`mark`は、開いていないマスだけで旗を切り替えます。`click`は旗や既に開いたマスを変更せず、地雷なら敗北状態に移り、安全なら一マスを開きます。敗北後の操作は無視します。`public_at`の戻り値は0〜8が公開数字、10が未公開、11が旗、12が無効添字です。**10と11から地雷の真値は分かりません**。

地雷の語列も旗の語列もBendでは資源として扱われます。`Words.has`が返す「読み取り後の語列とBool」を次の処理へ受け渡すのは、読み取りのために資源を勝手に複製しないためです。ゲーム内部の地雷情報と公開情報を区別する考え方は、後で運ゲー無し推論器を接続するときにも必要になります。

## 実行結果と検証範囲

`python3 intermediate/scripts/test_nxn_actions.py` は、Bendの型検査と実行結果を、語列を使わないPythonの座標集合モデルと照合します。N=2、3、4、10、17、100の盤面について、旗の切替、旗保護、二度クリック、地雷による敗北、敗北後の操作停止、盤外・語境界の番号、公開数字を有限個検査します。検査成功はこれらのケースの一致を意味し、任意の盤面での全称証明ではありません。

## 演習

まず、0番を開く前に1番へ旗を立て、そのまま1番をクリックしてみましょう。次に旗を外してからクリックし、敗北状態がどのように変わるか確認してみましょう。10×10盤面で99番と100番を操作し、どちらが有効か予想してから実行してみましょう。最後に、0のマスを開いても周囲が自動的には開かない理由を考え、次の実装で必要になる「訪問済みマス」と「作業キュー」を整理してみましょう。
