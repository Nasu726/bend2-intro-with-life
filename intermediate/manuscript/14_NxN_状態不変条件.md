## 100マスでも、配列の容量は100とは限りません

4×4の盤面だけなら、16マスの添字を手で確認できます。しかし、
10×10に広げると、クリック位置の検査や勝利判定で盤面外を
誤って数える危険があります。まず座標だけを独立した関数で扱いましょう。

`intermediate/minesweeper/nxn_geometry.bend` の `main` は
`index(10, 5, 5)` を計算します。

```bend
def index(+n: U32, +x: U32, +y: U32) -> U32:
  (y * n + x : U32)

def main() -> U32:
  index(10, 5, 5)
```

`bend intermediate/minesweeper/nxn_geometry.bend` の出力は `55` です。
左上を(0,0)、xを列、yを行とし、行優先で `i=y*N+x` を計算します。
この `index` は有効な座標を受け取ることが前提です。外部のクリックには
`checked_index` を使い、無効なら `None` にします。

Bendの `Array.new` の深さ `d` は `2^d` 個の格納領域を表します。
10×10では `d=7` なので物理的に128スロットありますが、
100..127はマスではありません。盤外クリックも勝利判定も、
必ず `0<=i<N*N` を確認してから処理しましょう。

## 座標の正しさとゲーム全体の正しさは別です

座標を正しく変換できても、地雷を開いてしまう0連鎖や、
旗だけで勝利する誤実装を防げるとは限りません。
そこで次の状態不変条件を独立に確認します。地雷数の保存、
開いたマスが安全であること、数字が近傍地雷数と一致すること、
公開済みマスが閉じないこと、勝敗確定後に操作できないことです。

`python3 -m unittest discover -s intermediate/tests -p 'test_nxn_game_invariants.py' -v`
で、2×2の全60初手と10×10の固定乱数6,000操作を検査できます。
ただしこれは**Python参照モデルの有限テスト**です。
BendのN×Nゲームエンジンが完成したことも、すべての入力について
`law` が証明されたことも意味しません。

## 演習

N=10で座標(9,9)の添字を計算し、添字100がなぜ無効なのか説明してみましょう。
また、開いたマスと旗付きマスが重ならないことを、
クリック・旗操作のどちらでも確認してみましょう。
最後に、初手で地雷を移す場合にも地雷数が変わらないことを
小さな2×2の例で確かめてみましょう。
