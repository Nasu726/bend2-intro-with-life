## なぜ数字の計算だけでは遊べないのでしょうか

10×10盤面の近傍地雷数を計算できても、クリックを受け取るゲームにはまだなりません。初手の地雷を安全な場所へ移すこと、公開済みマスや旗を保護すること、数字0の周囲を開くこと、勝敗が決まったら入力を無視することが必要です。まず、すでに動くBendの地雷格納・数字計算と、これから実装する状態遷移の境界を確かめましょう。

## 既存のBendコードを実行する

`minesweeper/nxn_clues.bend` の `main` は次の計算を行います。

```bend
def main() -> U32:
  read_count(count_checked(Words.set_checked(Words.new(10), 1, True{}), 0))
```

```sh
bend intermediate/minesweeper/nxn_clues.bend
# 1
```

10×10盤面の添字1（上段の左から2マス目）に地雷を置くと、左上の添字0の数字は1です。Bend 2.0.39の実行・独立座標計算との有限510件照合は既存CIで検証済みです。ここで呼んだのは**数字を読む純粋な内部処理**であり、まだクリック処理ではありません。

## 初手・旗・勝敗の期待値を固定する

次はN×NゲームのPython参照モデル `solutions/nxn_board_oracle.py` を用いて、Bendへ移植する仕様を先に固定します。10×10で地雷を添字0と99に置き、最初に0をクリックします。

```python
from nxn_board_oracle import new_game, click, mark

s = click(new_game(10, frozenset({0, 99})), 0)
print(s.phase, sorted(s.mines), s.opened)
f = mark(s, 99)
print(f.flags, click(f, 99).phase)
print(click(mark(f, 99), 99).phase)
```

```text
Playing [1, 99] ((0, 1),)
frozenset({99}) Playing
Lost
```

初手の地雷0は最小の空きマス1へ移ります。地雷数2は保存され、0が開いて数字1になります。99に旗を立てるとクリックしても進行せず、旗を外してから地雷99を開くと敗北します。敗北後はクリックも旗も無効です。

10×10の論理添字は0〜99です。Bendの配列が128スロットを確保しても、100〜127はマスではありません。`Array.get` が折り返しアクセスできるため、**配列に触れる前に論理範囲を検査**します。N=100でも論理添字10000以降は無効です。

## 0の連鎖と保証範囲

地雷0個の盤面で初手を開くと、0の連鎖によって10×10なら100マス、100×100なら10000マスが公開され、`Won` になります。右上の地雷9と次の行の左端10は隣接しません。これらを `tests/test_nxn_large_game_contract.py` の5テストで確認します。

```sh
python3 -m unittest discover -s intermediate/tests -p 'test_nxn_large_game_contract.py' -v
```

この5テストはPython参照モデルの期待値を固定する**有限な受け入れ条件**です。BendのN×N状態遷移が同じ結果を返すかは、実装後に独立した実行照合が必要です。現段階でBend版N×Nゲーム、10×10 GUI、一般サイズの運ゲー無し版を完成扱いにはしません。
