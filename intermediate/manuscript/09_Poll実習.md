# 第9章補稿：Pollで「まだ届かない」と「もう届かない」を区別する

この補稿の要点は教科書第9章と読者ZIPへ統合済みです。補足確認用の資料として残します。採用済み表紙は変更しません。

## 必要性

入力がまだない場合に、チャネルから値を受け取るまで待ち続けると、画面の更新など他の仕事へ戻れません。一方、チャネルが閉じて今後値が来ない場合は、単に待つのではなく処理を終了する必要があります。

## 動く最小例

読者ZIPの `examples/53_chan_poll.bend`（リポジトリでは `intermediate/src/53_chan_poll.bend`）を使います。

```sh
bend examples/53_chan_poll.bend
```

期待する出力は二行です。

```text
0
9
```

## 仕組み

容量1のチャネルを作り、空の状態で `Chan.try_recv(U32, chan, 0)` を呼ぶと `Wait` です。その後、値9を送ってから再度呼ぶと `Ready{Some{9}}` になります。プログラム中の `poll_number` は表示のために `Wait` を0へ、受信成功をその数値へ対応させています。0はBendの返り値そのものではありません。

`Ready{None{}}` は閉鎖して受信できる値がない状態です。この例ではその分岐を実行していません。受信値0と待機状態を区別するには、実際の処理では `match` の分岐を保ちましょう。

## 演習

送信する値9を17に変えてみましょう。最初の行が変わらない理由を説明してください。次に、`Wait` と `Ready{None{}}` が意味する状態の違いを言葉で説明してみましょう。

検証済みなのはBendの型検査と0・9の二行の実行照合です。時間制限の競合、送信側の待機、閉鎖後の受信は別のテストが必要です。
