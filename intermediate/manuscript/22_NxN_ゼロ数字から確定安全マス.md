# 第22章補稿：公開された0から安全なマスを求める（Bend実装・PDF未統合）

## 0を見たら、どのマスを開けられるでしょうか

10×10盤面の左上（添字0）に数字0が表示されたとします。0は「隣接する8方向に地雷が一つもない」という意味なので、隣接する1・10・11番は必ず安全です。ここで必要なのは**公開された数字**と**座標**だけです。ゲーム内部の地雷集合をソルバーに渡してはいけません。

既存の`nxn_neighbors.bend`は、盤面端をまたがない隣接マスを添字の昇順で返します。新しい`nxn_zero_inference.bend`は、そこから既公開マスと旗付きマスを取り除きます。旗は地雷の証拠ではありませんが、プレイヤーが旗を外すまでクリック候補から除外します。

## Bendコードを動かしてみましょう

`intermediate/minesweeper/nxn_zero_inference.bend`の中心は次の呼び出しです。

```bend
# n=10、0番の表示数字が0、公開済みは[0]、旗なし。
Neighbors.count(safe_from_clue(10, 0, 0, [0], Nil{}))
```

```sh
bend intermediate/minesweeper/nxn_zero_inference.bend --check-only
bend intermediate/minesweeper/nxn_zero_inference.bend
# 3
python3 intermediate/scripts/test_nxn_zero_inference.py
# PASS 268 public zero-clue Bend/Python checks
```

`safe_from_clue(10, 0, 0, [0], Nil{})`の結果は`[1, 10, 11]`です。1番をすでに開き、10番に旗がある場合は`safe_from_clue(10, 0, 0, [0, 1], [10])`が`[11]`を返します。表示数字を1に変えた場合や、0番が未公開の場合は`Nil{}`です。

## どの条件を確かめているのでしょうか

`safe_from_clue`は、サイズが2〜100、添字が盤内、表示数字が0、そのマスが公開済みであることを確かめます。続いて`Neighbors.neighbors`の各要素を、`contains`で公開済み・旗付きリストと比較します。隣接リストの順序を保つため、結果は昇順で重複しません。

**重要な前提**は、渡した`clue`が実際に画面に表示された数字であることです。この関数はその数字を地雷真値から再計算しません。入力を偽れば安全性は保証されません。また、数字1以上の制約、総地雷数、複数の数字を組み合わせる推論、矛盾判定はまだ実装していません。**これはN×N公開情報ソルバーの最初の一規則であり、運ゲー無し生成器の完成ではありません。**

`test_nxn_zero_inference.py`は、Bendを型検査・実行して、独立したPython座標計算による268ケースの期待リストと**要素・順序を完全一致**で照合します。N=2/3/4/10/17/32/100、盤面端、公開・旗の組合せ、無効サイズ、無効添字、数字0以外を含みます。有限なテストであり、すべての入力についての形式的証明やGUI実機検収ではありません。
