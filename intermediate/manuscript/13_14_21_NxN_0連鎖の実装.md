## なぜ一マスだけ開く処理では足りないのでしょうか

マインスイーパーでは、近傍に地雷がない0のマスを開くと、その周囲の安全なマスも自動的に開きます。数字が付いた境界マスまで公開し、旗を立てたマスと地雷は開きません。大きな盤面では、隣を順番にたどる処理が必要です。

## Bendコードと実行結果

`minesweeper/nxn_flood.bend` は、未処理のマスを `List<U32>` に入れて探索します。0のマスを初めて開いたときだけ `nxn_neighbors.bend` の8近傍を追加します。

```bend
def next_work(zero: Bool, +n: U32, +index: U32, rest: List<U32>) -> List<U32>:
  match zero:
    case True{}:
      prepend_all(Neighbors.neighbors(n, index), rest)
    case False{}:
      rest
```

3×3盤面の右下（添字8）に地雷を置き、左上（添字0）から公開します。7番のマスは地雷に隣接する数字1として開きます。

```sh
bend intermediate/minesweeper/nxn_flood.bend
# 11
```

これは表示コード `10 + 1` で、ゲーム画面そのものではありません。

## なぜ探索が止まるのでしょうか

一度開いたマスは再び展開しません。したがって0のマスは最大 `N*N` 個、各マスが追加する仕事は最大8個です。最初の1件を含め、処理する仕事の上限は `1+8*N*N` 件です。`explore` は `Nat` の燃料を一つずつ減らし、仕事が空なら早く終了します。実際の配列容量が2の累乗へ切り上げられても、盤外の論理添字は拒否します。

旗は公開しません。既に開いた数字マスから再度近傍を追加しないので、循環する隣接関係でも探索は停止します。地雷の真値はゲーム内部でのみ読み、公開情報ソルバーへ渡しません。

`scripts/test_nxn_flood.py` はPythonの独立した座標BFSとBendの有限ケースを照合します。これはN=2〜100の全盤面・全操作列の証明ではありません。
