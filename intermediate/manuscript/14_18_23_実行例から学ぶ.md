## 第14章：境界の一画素を調べてみましょう

第12章でマウスの位置を盤面の添字へ変換しました。しかし、(31,31)と(32,0)は同じマスでしょうか。8×8盤面で一マス32画素なら、前者は0番、後者は1番です。盤面の右端(255,255)と、その一画素外(256,0)も区別する必要があります。

学習用ZIPの`examples/23_cell_hit_test.bend`にある次の関数を見てみましょう。

```bend
def pixel_to_cell(+x: U32, +y: U32) -> Maybe<&2, U32>:
  cell_if_valid(x, y, Bool.and(U32.is_lt(x, 256), U32.is_lt(y, 256)))
```

入力が256未満の範囲内にあるかを調べ、範囲外なら`None{}`を返します。範囲内では横方向に`x / 32`、縦方向に`y / 32`を使い、`8 × 行 + 列`で添字を計算します。

| 入力 | 期待する結果 |
| --- | --- |
| (0,0) | `Some{0}` |
| (31,31) | `Some{0}` |
| (32,0) | `Some{1}` |
| (255,255) | `Some{63}` |
| (256,0) | `None{}` |
| (0,256) | `None{}` |

```text
bend examples/23_cell_hit_test.bend
10
```

この`10`は、**既存のmainが試す(64,32)と(256,32)の二例**について、10番と0を足した結果です。上の六例すべてを実行した結果ではありません。六例はこれから追加して確かめるテストの期待値です。

`cell_or_zero`は教材の数値表示のために`None{}`を0へ変えていますが、実際のゲームではその値をクリック先として使ってはいけません。画面外のクリックが0番マスのクリックになってしまいます。`Maybe`を分岐し、`None{}`なら盤面を変更しないようにしましょう。

**演習：** `main`の入力を(31,31)、(32,0)、(255,255)へ変え、表の値と一致するか確かめてみましょう。さらに(256,0)を試し、画面外で盤面を変更しない処理を考えてみましょう。ここで検査できるのは純粋な座標計算であり、実機のマウス操作ではありません。

## 第18章：証明が通ることと、要件が十分なことは違います

`24_bool_proofs.bend`を実行すると、`True{}`を二回反転した結果の`1`が返ります。

```text
bend examples/24_bool_proofs.bend
1
bend examples/24_bool_proofs.bend --verdict
```

同じファイルの法則は次のとおりです。

```bend
law not_twice:
  for b: Bool
  {Bool.not(Bool.not(b)) == b : Bool}
```

`main`の実行は一つの入力に対する確認ですが、`--verdict`は宣言された法則について`Bool`のすべての値を対象にした証明を検査します。それでも「ゲームの旗操作が正しい」ことまでは示せません。

「旗を二回切り替えると元に戻る」という法則だけなら、何もしない関数でも満たしてしまいます。第17章の`34_mine_mask_law.bend`が「地雷配置は変わらない」と「旗ビットは変わる」の二つを別々に証明するのは、そのためです。**正しく証明された弱い法則は、必要な機能の保証にはなりません。**

**演習：** `04_flag_laws.bend`の`toggle_twice`だけでは、何もしない実装を排除できない理由を説明してみましょう。`34_mine_mask_law.bend`の二つの法則のうち、一つだけを残した場合に何が保証できなくなるか考えてみましょう。

GUIの型検査、純粋な入力ロジックのテスト、ウィンドウの実機操作も別の検証です。現在のGUIはBendの型検査・ネイティブビルド・ヘッドレス入力検査済みですが、実機操作とGUI保存は未検収です。

## 第23章：知らないAPIを小さな例で試す

「0から3までの自然数のうち、3未満の数を合計したい」とします。再帰を自作する前に`List.range`、`List.filter`、`List.foldl`を探してみましょう。関数の型は`bend base List.filter`で確認できます。

```text
bend base List.filter
bend examples/17_list_pipeline.bend
3n
```

`17_list_pipeline.bend`では`List.range(4n)`で0、1、2、3を作り、`List.filter`で3未満の0、1、2だけを残します。`List.foldl`でそれらを足すと`3n`です。条件関数の引数と返り値、`List`の要素型、`Nat`の結果を読み取ってください。

**演習：** `small`の条件を2未満へ変更し、出力を予想してから実行してみましょう。さらに`List.range(5n)`へ変更した場合を考えてみましょう。最後に別の公開APIを一つ選び、型・小さな入力・実行結果・失敗条件を記録してみましょう。

標準APIの実行例が通っても、GPU性能、ネットワークの切断、GUIの表示まで保証されたわけではありません。型検査・実行・証明・実機検証のどれを行ったのかを区別しましょう。
