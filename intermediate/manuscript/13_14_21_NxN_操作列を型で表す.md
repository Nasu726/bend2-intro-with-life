# 第21章補稿：N×Nの操作列をBendの型で表しましょう

> **TeX本文・PDFには未統合**。ここでは純粋なゲーム操作の再生だけを扱います。対話CLI、GUIの実機入力、ファイル保存、運ゲー無し版は別工程です。以下の照合は有限ケースであり、全称証明ではありません。

## なぜ操作を列にするのでしょうか

クリックや旗の切り替えをその場で呼び出すだけでは、同じ操作をもう一度試したり、不具合の起きた手順を共有したりしづらくなります。そこで、**操作をデータとして記録してから順番に実行**します。地雷配置は操作列に入れず、ゲームエンジンの内部に残します。

## Bendコードと実行結果

`minesweeper/nxn_trace.bend`は、クリックと旗を`Action`として区別します。

```bend
type Action is Data:
  Click{index: U32}
  Mark{index: U32}

def apply(game: Full.Game, action: Action) -> Full.Game:
  match action:
    case Click{index}:
      Full.click(game, index)
    case Mark{index}:
      Full.mark(game, index)

def replay(actions: List<Action>, game: Full.Game) -> Full.Game:
  match actions:
    case Nil{}:
      game
    case action <> rest:
      replay(rest, apply(game, action))
```

```sh
bend intermediate/minesweeper/nxn_trace.bend
# 11
```

サンプルは2×2盤面の右下（添字3）に地雷を置き、`Click{0}`の後で`Mark{1}`を実行します。左上は数字1で公開されるので、検査用の値は`11`です。まだ安全マスが残っているため勝利ではありません。

## 仕組みを追いましょう

`List<Action>`の先頭を取り出し、`apply`で既存の`nxn_full_game.bend`に渡します。残りのリストが必ず短くなるため、`replay`は停止します。Bendでは再帰の構造的に減少する引数を**先頭**に置くことが重要です。ゲーム状態は各手で消費・返却し、初手安全、0連鎖、勝利・敗北後の操作停止は既存のエンジンに任せます。

`test_nxn_trace.py`では、N=2・3・4・10・17・100の操作列をPythonの集合・幅優先探索モデルと比較します。**GUIの入力イベントや100×100全面0連鎖の性能は未検証**です。
