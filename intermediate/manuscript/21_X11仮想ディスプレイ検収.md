# 第21章補稿：X11のウィンドウでGUIを検査してみましょう

## 必要性

`nxn_gui_app.bend` の `App.run` が型検査に成功しても、本当にウィンドウが開くか、マウスの押下が描画に反映されるかは分かりません。そこで、**仮想X11ディスプレイ上でネイティブのBendプログラムを実際に起動**して確認します。これはheadlessな関数の照合より一段進んだ検証ですが、実モニターやGPUでのユーザー操作検収とは異なります。

## 実際に動かすBendコード

既存の `minesweeper/nxn_gui_app.bend` をそのまま使用します。ゲーム開始前の `Fresh{n,count,seed}` は地雷配置を保持しません。

```bend
def main() -> IO(Unit):
  App.run(~Lazy.Game, ~App{view, tick},
    "Minesweeper 10x10: left/right click, R reset, Esc close",
    512, 512, GUI.reset_gui(20261029))
```

Linux（X11）ではネイティブビルド後に実行できます。

```sh
bend intermediate/minesweeper/nxn_gui_app.bend -o ./nxn_minesweeper
./nxn_minesweeper
```

仮想ディスプレイの自動試験は、依存する`Xvfb`・`xdotool`・ImageMagick・Pillowのある環境で次を実行します。

```sh
xvfb-run -a -s '-screen 0 1280x960x24' \
  python3 intermediate/scripts/test_nxn_gui_desktop.py
```

## 期待される観察結果と仕組み

`test_nxn_gui_desktop.py` は実際のウィンドウを探し、各操作の前後で画面画像を保存・比較します。

1. 開始時には未公開の10×10盤面が見えます。右側と下側の余白をクリックしても変わらず、初手前の旗操作も無視します。
2. 左上のマスを最初に開くと、盤面が初めて生成され、画面が変化します。このマスに地雷を配置しないことは別の有限テストで検証済みです。
3. 独立Pythonオラクルで未公開と確認した別のマスを右クリックすると、画面が変化します。
4. `r`キーでリセットすると、最初の未公開盤面に戻ります。`Escape`キーでプロセスが正常終了します。

画面画像の差分だけでは、その画像の数字や旗が**すべて正しい**とは証明できません。公開セル画像の17条件は既存のBend検証、盤面の状態はN×Nの独立Python検査で補完します。全ピクセル・全イベント列の検証や本物のデスクトップでの目視操作は、別の検収工程です。

## 演習

- 余白をクリックしたときのスクリーンショットが変わらないことを調べてみましょう。
- 右クリックの対象を別の未公開マスに変え、旗の表示がどう変わるか試してみましょう。
- `r`と`Escape`で、画面の変化とプログラム終了の違いを確かめてみましょう。

**検証上の注意**：旧検証PR #91のLinux Xvfb試験（CI #40847446993）では、ネイティブGUIの起動・クリック・リセット・終了・画像差分が成功しました。その後、正本 `bb3b255b` のX11・Bend総合・Tests・Reader・PDF layoutの5ワークフローもすべて成功し、第21章の保存・読込成否通知サンプル2本を含む101エントリの読者ZIPが配布候補になっています。これは仮想X11上の有限操作列の検査であり、物理モニター・GPU・全イベント列の検収ではありません。採用済み表紙、第7章Byte/File、第8章IO.now/IO.sleepは変更しません。

## 追加の受入試験：色の意味と盤面の不変性

GUIの四つの通知が「互いに違う色」だけでは、例えば成功と失敗の色を取り違えてもテストが通ってしまいます。そこで、`nxn_gui_status_app.bend` の右側余白（x=400, y=16）のRGB値を、**保存成功=緑(0,255,0)、読込成功=青(0,0,255)、保存失敗=赤(255,0,0)、読込失敗=琥珀色(255,165,0)** と照合します。

検査の操作順は「保存ファイル不在でL→初手前の右クリックで通知消去→S→L→R→保存先をディレクトリにしてS→Escape」です。保存成功後のファイルは公開入力履歴 `BEND2-GUI-1|20261029|1|END` であることを確認し、各段階で盤面領域320×320ピクセルが初期画像から変わらないことも確認します。成功・失敗表示のために盤面が勝手に開かれない、という性質の**有限回帰テスト**です。

正本では上記の初期盤面に対する4色の検証が成功しています。次の検証段階では、**実際に左上を開いて盤面が変化した後**にも、保存先をディレクトリにした読込失敗（琥珀色）・保存失敗（赤色）で公開済みセルの画像が不変であることを確認します。さらに、正常保存で公開操作履歴 `BEND2-GUI-1|20261029|0|END` を記録し、Rで初期化した後にLで同じ公開済み盤面を復元できるか検査します。先にRを実行しているため、初手前の右クリック履歴`1`は消去され、今回の保存には左クリック`0`だけが残ることも検査します。初期盤面が空白のままの検査だけでは見落とす「失敗時に盤面を誤ってリセットする」退行を検出するためです。X11の描画は非同期なので、クリックで通知が消えたことを確認してから、次のS/L操作の**期待RGB値そのもの**を待機します。色が「直前の古い値から変わった」だけでは成功扱いしません。この公開済み盤面の追加試験は検証PR #117の全CIと正本先端 `70278f0a` の5ワークフローで成功しました。表示は依然として色だけであり、文字や形による通知、原子的な保存、物理GPU・他OSでの動作は未検証です。


## 追加の受入試験：壊れた保存データを途中まで適用しない

**必要性：** 保存データの先頭に正しいクリック履歴があっても、末尾に不正な操作コードや余分な終端記号があれば、読み込み全体を拒否しなければなりません。途中まで履歴を再生してから失敗すると、プレイ中の公開盤面が意図せず変わります。

**Bendコード：** 通知版 `nxn_gui_status_app.bend` は、`Store.load()` の結果を次のように分岐します。

```bend
def after_load(model: History.Model, result: History.Recovery) -> State:
  match result:
    case History.Corrupt{}:
      State{model, 4}
    case History.Restored{restored}:
      State{restored, 2}
```

**期待する実行結果：** 左上のセルを開いて保存・復元した後、`BEND2-GUI-1|20261029|0|200|END`、`...|0|END|END`、終端 `END` の欠落、4096バイト超の四種類を保存ファイルに書き込み、`L` を押します。いずれも琥珀色の失敗通知になり、公開済み320×320ピクセルの盤面、保存ファイルの内容、実行中プロセスが保たれることをX11上で照合します。最後に元の正常な保存データを戻して再読込できることも確かめます。純粋なBendデシリアライズ検査には、有効な接頭辞の後に不正な値が続く3条件を追加します。

**仕組み：** `deserialize` が完全に検査した後にだけ `History.Restored` を返し、不正な入力は `History.Corrupt` になります。上の分岐は失敗時に現在の `model` を保持します。これは**読み込み時の全体拒否**であり、書き込み途中の停電・異常終了に備える**原子的保存**とは異なります。

**演習：** 正しい保存データの `END` の後に `|0` を追加し、読み込みが拒否されるか確かめてみましょう。次に保存先をディレクトリに変え、ファイルを開けない場合と内容が不正な場合で、ゲーム画面が変わらない理由を説明してみましょう。

> この四種類の追加X11試験と純粋Bend 3条件は、検証CIが成功するまで**検証候補**です。採用表紙、配布済みTeX/PDF/ZIP、読者用Bendコードには変更を加えません。物理GPU・他OS・原子的保存は引き続き未検証です。
