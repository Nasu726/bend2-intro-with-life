## 第7章：表示された「4」は何を保証するでしょうか

ゲームの設定は文字列で保存できますが、画像や独自形式では文字に変換せずにバイトを扱う必要があります。たとえば `0`、`10`、`13`、`255` は、文字4個ではなく1バイトずつの値です。

`45_binary_file.bend` は `File.write_bytes(file, [0, 10, 13, 255])` で書き込み、`File.read_bytes(input, 16)` で読み取ります。成功時の出力は **`4`** です。ただし、この値は読み込んだリストの**長さ**であり、要素の内容と順序までは示しません。

まず読者ZIPを展開したフォルダーで、次のように実行してみましょう。リポジトリ内で実行する場合は `bend intermediate/src/45_binary_file.bend` としてください。

```sh
bend examples/45_binary_file.bend
python3 -c 'from pathlib import Path; print(Path("sample_bytes.bin").read_bytes().hex(" "))'
```

期待される表示は順に `4` と `00 0a 0d ff` です。後者は実ファイルの4バイトを16進数で表示します。次のコマンドなら、期待した値と完全一致するかを機械的に確認できます。

```sh
python3 -c 'from pathlib import Path; assert Path("sample_bytes.bin").read_bytes() == bytes([0,10,13,255]); print("byte content OK")'
```

成功時の表示は `byte content OK` です。これも**Bendの実行でファイルが生成された後**に行う検査です。文字列として開いて表示した場合、`00`（NUL）や `ff` を正しく確認できないことがあります。

**仕組み：** `File.read_bytes` の第2引数 `16` は最大読込量であって、常に16要素を返す指定ではありません。`after_read` は `Done` と `Fail` の両分岐で返された `File` を閉じます。CIの `scripts/test_examples.py` では、出力 `4` とファイルの内容 `[0,10,13,255]` を別々に照合し、開けない場合も検査しています。ただし、Bend側で全要素の値・順序を再比較したことは保証しません。ファイル内容の確認とBendが返したリスト長の確認を区別しましょう。

**演習：** 書き込む値を `[255, 13, 10, 0]` に変更してみましょう。表示される長さは変わるでしょうか。16進数表示の順序と比較して説明してみましょう。

## 第8章：20ミリ秒待てば、表示は必ず20でしょうか

プレイ時間を扱うとき、実行環境に依存する時計の読み取りと、数値から差を求める純粋計算を分離します。

`46_elapsed_clock.bend` は `IO.now()` で開始・終了の時計値を取得し、間で `IO.sleep(20)` を呼びます。差は純粋関数 `elapsed(first, last) = Nat.sub(last, first)` で求めています。

```bend
def elapsed(first: Nat, last: Nat) -> Nat:
  Nat.sub(last, first)

def main() -> IO(Unit):
  do IO<Unit>:
    start: Nat <- IO.now()
    Unit <- IO.sleep(20)
    finish: Nat <- IO.now()
    IO.print(Nat.show(elapsed(start, finish)))
```

このコードは `46_elapsed_clock.bend` の主要部分です。単独の貼り付け用ではなく、実習ファイル全体を動かしましょう。

```sh
bend examples/46_elapsed_clock.bend
```

リポジトリからは `bend intermediate/src/46_elapsed_clock.bend` で実行します。

表示はミリ秒単位の数値ですが、**固定値 `20` は期待しません**。たとえば `21` と表示されても、それは固定された期待値ではありません。OSのスケジューリングなどで実際の経過時間は変わります。`IO.now()` は年月日を返す関数でもありません。

**仕組み：** 時計を読む操作と待機は `IO` に属し、受け取った2個の `Nat` の差は純粋な計算です。CIでは数値形式と広い異常値範囲を確認し、厳密な20との一致を要求しません。実機の待機精度を保証するテストではありません。

**演習：** `IO.sleep(20)` を `IO.sleep(0)` と `IO.sleep(100)` に変えて各3回実行してみましょう。実測値が揺れる理由と、`elapsed(100n,130n)` の結果が必ず `30n` になる理由を説明してみましょう。

## どこまで検証しているのでしょうか

| 項目 | 現在の確認 | この検査では保証しないこと |
| --- | --- | --- |
| バイト保存 | Bend実行結果 `4` と実ファイル `00 0a 0d ff` を別々に照合 | 任意長のバイナリ保存やすべての障害 |
| バイト読込 | `File.read_bytes` の戻り値の要素数を取得 | Bend内部での全バイト値・順序の再照合 |
| ファイル失敗 | 同名ディレクトリを置いた `File.open` 失敗系 | すべてのOS・権限・途中障害 |
| 時刻と待機 | 数値形式と広い異常値範囲を確認 | 毎回20ミリ秒ちょうどの測定 |
| ゲーム統合 | IOと純粋関数を分離する設計を学ぶ | GUIでの保存、復元、プレイ時間の実機検収 |
