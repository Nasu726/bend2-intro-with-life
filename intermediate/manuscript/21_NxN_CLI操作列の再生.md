# 第21章補稿：N×Nの操作列をCLIから再生してみましょう

> **TeX本編・PDF・読者ZIPには未統合**。ここでは固定した10×10盤面の非対話式CLIを扱います。GUI実機、任意の盤面生成、保存・復元、全称証明は別の工程です。

## なぜ操作列を引数にするのでしょうか

これまではBendコード内にクリック位置を直接書いて、初手安全・0連鎖・勝利を確認しました。しかし、クリックのたびにソースを書き換えると、同じ盤面で操作順だけを変えて試しにくくなります。そこで、**盤面は固定したまま、操作列だけをコマンドラインから渡す**ことにします。

## Bendコードと実行結果

`minesweeper/nxn_cli_replay.bend`は、`nxn_full_game.bend`を呼び出します。最初の引数は**観測するマス番号**、残りは`c番号`（クリック）、`f番号`（旗の切替）、`r`（最初の盤面に戻す）です。

```bend
def replay(commands: List<String>, game: Game.Game) -> Game.Game:
  match commands:
    case Nil{}:
      game
    case command <> rest:
      replay(rest, choose_action(game, command))
```

```sh
bend intermediate/minesweeper/nxn_cli_replay.bend 49 c0
# 12
bend intermediate/minesweeper/nxn_cli_replay.bend 99 c0 f99 c99
# 1
bend intermediate/minesweeper/nxn_cli_replay.bend 99 c0 f99 c99 f99 c99
# 110
bend intermediate/minesweeper/nxn_cli_replay.bend 99 c0 r
# 300
```

数字`12`は進行中の公開数字2、`1`は旗、`110`は勝利状態で数字0が公開済み、`300`は開始前です。これらは**検証用の状態コード**であり、通常のゲーム画面ではありません。

## 仕組みを追いましょう

`IO.args()`で引数のリストを受け取り、プログラム名を除きます。最初の引数を`U32.read`で観測位置に変換し、残りを`replay`に渡します。`replay`はリストの先頭を一つ処理して残りへ進むため、操作の順序が保たれます。ゲーム状態は毎回新しい値として受け渡し、途中の状態を勝手に複製しません。

クリックと旗の番号が整数に変換できない場合は操作を無視し、盤外番号はエンジン側が拒否します。`r`では**最初の地雷配置から**やり直します。観測番号が盤外なら`99`、観測番号が欠落・不正なら`999`を返します。開始前の観測結果は`300`です。CLIは公開状態だけを表示し、地雷位置そのものを出力しません。

`scripts/test_nxn_cli_replay.py`は固定盤面について、Bendを型検査・実行し、Pythonの独立した集合・幅優先探索モデルと**19操作列**を照合します。リセット、旗、勝利後の入力無効化、不正な番号も含みます。有限テストなので、任意の操作列が正しいと証明したわけではありません。

## 演習

1. `99 c0 f99 c99`の末尾に`f99 c99`を追加し、いつ勝利するか予想してから実行してみましょう。
2. `99 c0 r c99`を実行し、`r`が「一手戻る」ではなく「盤面を初期化する」操作であることを確かめてみましょう。
3. `100 c0`と`abc c0`の出力を比較し、**盤外の観測**と**観測番号の解析失敗**を分けて扱う理由を考えてみましょう。
