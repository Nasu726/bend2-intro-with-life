# 第14・21章補稿：公開された0から安全マスを推論してみましょう

> **TeX本編・PDFには未統合**。これはN×N公開情報ソルバーの最初の推論規則です。任意の盤面を解く完全なソルバーや運ゲー無し生成器ではありません。

## 地雷を知らずに次の一手を決められるでしょうか

ゲーム本体は地雷の位置を知っています。しかし、プレイヤーが使えるのは公開された数字だけです。地雷配列をソルバーへ渡してしまうと、運ゲー無しかどうかを検証できません。そこで、まず「**公開された数字0の周囲8マスには地雷がない**」という、盤面の真値を見ずに使える規則を実装しましょう。

## Bendコードと実行結果

`minesweeper/nxn_public_zero.bend`の入口は、盤面サイズと**公開済みの0マスの添字だけ**を受け取ります。

```bend
def proven_safe(+n: U32, zeros: List<U32>) -> List<U32>:
  collect(n, zeros, Nil{})
```

`proven_safe`は各0マスの非トーラス近傍を`nxn_neighbors.bend`から受け取り、`append`で順番に連結します。重複は残ります。たとえば10×10盤面の左上0番が公開された場合、安全と推論できる添字は`[1, 10, 11]`です。これは地雷の真値を参照しない結果です。

```sh
bend intermediate/minesweeper/nxn_public_zero.bend
# 8
python3 intermediate/scripts/test_nxn_public_zero.py
# PASS 56 N x N public-zero Bend/Python checks
```

上の`8`は0番と1番の両方が公開済みの0だった場合の、**安全と分かる近傍を連結したリストの要素数（重複を含む）**です。実際にクリックする候補を得るには、このリストから重複、公開済みマス、旗のマスを除外する必要があります。

## どうして正しいのでしょうか

数字0は「隣接する地雷が0個」を意味します。したがって、**実際に公開された0**の近傍はすべて安全です。複数の0から得た安全マスのリストを連結しても、各要素の安全性は変わりません。`append`は入力順に連結するだけで、重複の除去はしません。無効なサイズや添字は`Neighbors.neighbors`が空リストにします。

テストではN=2・3・4・10・17・100について、Pythonが地雷を0の近傍以外に配置して真に0である観測を作り、Bendの結果を独立した座標計算と照合します。**Pythonだけが検査用の地雷集合を知り、Bendの推論関数には渡しません**。ただし有限56ケースであり、全称証明ではありません。また、入力された0が本当に公開済みかは呼び出し側の責任です。

## 演習

1. 10×10盤面で0番と1番が0だと分かったとき、安全と推論できる添字を紙に書いてから実行してみましょう。
2. 同じ0を二度入力すると同じ近傍が二度現れることを確認し、`List.sort`などの標準APIも調べながら重複を除く方法を考えてみましょう。
3. 公開済みの添字を引き算して「まだクリックできる安全マス」だけを返す関数を作ってみましょう。
4. 数字1以上を使うには、地雷候補の制約をどのように表せばよいか考えてみましょう。0の規則だけでは一般の運ゲー無し盤面を生成できないことにも注意しましょう。
