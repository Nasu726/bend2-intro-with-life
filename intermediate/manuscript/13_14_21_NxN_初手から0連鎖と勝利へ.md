# 第13〜14・21章補稿：初手安全・0連鎖・勝敗を一つにしましょう

> **TeX本編・PDFには未統合**。ここで扱うのは純粋なN×Nゲームエンジンです。GUI、保存、公開情報ソルバー、運ゲー無し生成器は別工程です。検証は有限ケースであり、全称証明ではありません。

## なぜ部品を接続する必要があるのでしょうか

前節では、初手の地雷移動、0連鎖、勝利判定を別々に試しました。しかし、0のマスを開いて安全マスがすべて公開されたのに、ゲームがまだ`Playing`なら、次のクリックで負けてしまいます。実際のゲームでは、**初手を安全にする→連鎖公開する→勝利を判定する**順序が必要です。

## Bendコードと実行結果

`minesweeper/nxn_full_game.bend`では、部品の順序を短い関数で表現します。

```bend
def finish(session: Step.Session) -> Terminal.State:
  Terminal.from_check(Victory.inspect(session))

def after_relocation(result: Relocate.Relocation, +index: U32) -> Game:
  match result:
    case Relocate.FirstClickRejected{board}:
      Fresh{board}
    case Relocate.FirstClickSafe{board}:
      Active{finish(Flood.reveal(Step.new(board), index))}
```

```sh
bend intermediate/minesweeper/nxn_full_game.bend
# 110
```

地雷のない2×2盤面で左上をクリックすると、数字0の連鎖で全マスが開き、その一手で勝利します。`110`は勝利の`100`と、右下の公開済み数字0のコード`10`を足した**テスト用の表示**です。

## 仕組みを追いましょう

`Fresh`では最初のクリックが有効か調べ、必要なら地雷を空きマスへ移動します。次に`Flood.reveal`が数字0の周囲を広げ、数字1以上の境界で止まります。**連鎖が終わった後**に`Victory.inspect`を呼び、すべての安全マスが公開済みなら`Won`へ進みます。`Won`と`Lost`ではクリック・旗操作を受け付けません。

`scripts/test_nxn_full_game.py`は、Bendとは異なるPythonの集合と幅優先探索を使い、初手の移動、0連鎖、旗、勝敗、無効添字を照合します。大きな盤面では0連鎖を全面に広げるケースを避けているため、100×100全面展開の速度やメモリ使用量は**未検証**です。

## 演習

1. 地雷がない3×3盤面で0をクリックしたら、どのマスが開き、いつ`Won`になるか予想してみましょう。
2. 初手に地雷をクリックした場合、地雷数が変わらないことを確認してみましょう。
3. 数字0の近くに旗を立てるとき、旗が保護される理由を`Flood.reveal`の分岐から説明してみましょう。
4. 0連鎖の**前**に勝利判定を行うと、どのような誤判定が起こり得るか考えてみましょう。

## 10×10盤面で二つの0領域を開いてみましょう

小さな2×2盤面だけでは、数字の境界で連鎖が止まることを実感しにくいかもしれません。そこで、10×10盤面の**6行目（行番号5）**に地雷を横一列、添字50〜59へ置いてみましょう。上側50マスと下側40マスは地雷の列で隔てられます。

`minesweeper/nxn_playthrough.bend`では、まず左上の0番を開き、次に右下の99番を開きます。必要な呼び出しは次の部分です。

```bend
def main() -> U32:
  game = Game.new(mine_wall(Words.new(10)))
  game = Game.click(game, 0)
  game = Game.click(game, 99)
  Game.snapshot(game, 99)
```

```sh
bend intermediate/minesweeper/nxn_playthrough.bend
# 110
```

最初のクリックでは上側の50マスが開きます。地雷の直上にある数字マスは公開されますが、その先へは進みません。この時点で下側40マスは隠れているので、まだ勝利ではありません。次の99番クリックで下側40マスが公開され、安全な90マスがすべて開いたため`Won`になります。出力`110`は勝利状態の100と、99番が公開済み数字0であることを表す10の合計です。

`scripts/test_nxn_playthrough.py`は独立したPython集合・BFSモデルで、上側の数字2、未公開の下側、2クリック後の勝利、勝利後の地雷クリック無効、旗による公開阻止を確認し、Bend本体の型検査と実行出力も照合します。これは**固定した10×10盤面の有限検査**であり、10×10 GUIの動作や100×100全面連鎖の速度を保証するものではありません。

**演習**：最初のクリック後に99番へ旗を置いてから99番をクリックすると、勝利しない理由を説明してみましょう。続いて、旗を外してからクリックするとどうなるか予想してみましょう。

## 途中の状態もBend本体と照合してみましょう

最終結果が`110`で一致するだけでは、途中で旗を無視していないか、地雷を開いた後も操作できてしまわないかは分かりません。そこで、`scripts/test_nxn_playthrough.py`では、**Bendのゲーム本体を実際に呼ぶ**7本の操作列を、独立したPython集合・幅優先探索の結果と比較します。

| 操作と観測位置 | 期待する状態コード |
| --- | ---: |
| 0番を開き、49番を見る | `12`（進行中、数字2） |
| 0番を開き、99番に旗を置いてクリック | `1`（旗が残る） |
| 旗を外して99番を開く | `110`（勝利） |
| 0番の後で地雷50番を開き、99番をクリック | `200`（敗北後も99番は未公開） |
| 最初に地雷50番を開く | `11`（初手移動後の数字1） |
| 99番から先に開き、0番を開く | `110`（逆順でも勝利） |
| 勝利後に地雷50番をクリック | `100`（勝利状態を維持） |

```sh
python3 intermediate/scripts/test_nxn_playthrough.py
# PASS 7 N=10 Bend/Python boundary traces
# PASS N=10 mine-wall playthrough: 50+40 safe cells, victory 110
```

ここではPythonの期待値を確認するだけでなく、生成したBend検査プログラムを`--check-only`で型検査し、その実行結果が7件すべて一致することを検査します。これは**固定した10×10盤面の有限な操作列**についての検査です。任意の地雷配置、100×100の全面連鎖性能、GUI上のクリックは保証しません。

**演習：** 0番を開いた後に99番へ旗を置き、クリックしてから旗を外す操作列を追加してみましょう。勝利になるのはどの操作の直後でしょうか。次に勝利後の旗操作が無効になることを確かめてみましょう。

## 10×10画面のクリックをゲームの添字へ変えてみましょう

ここまでの実習では `Game.click(game, 99)` のようにマス番号を直接指定しました。実際の画面では、マウスから届くのはピクセル座標です。**座標の変換とゲームの状態遷移を分ける**と、画面を描く前にクリックの正しさを検査できます。

`minesweeper/nxn_pointer.bend` は、1マスを64×64ピクセルとする純粋な入力アダプターです。盤面サイズはゲームを作るときの `MineWords` から取得し、呼び出し側が異なるサイズを渡せないようにしています。

```bend
def cell_at(+n: U32, +x: U32, +y: U32) -> Maybe<&2, U32>:
  Geo.checked_index(n, U32.div(x, 64), U32.div(y, 64))

def mouse_mode(left: Bool, right: Bool, game: Game.Game, index: U32) -> Game.Game:
  match left right:
    case True{} _:
      Game.click(game, index)
    case False{} True{}:
      Game.mark(game, index)
    case False{} False{}:
      game
```

10×10盤面では `(0,0)` と `(63,63)` が0番、`(64,0)` が1番、`(639,639)` が99番です。`(640,0)` や `(0,640)` は盤外として無視します。左ボタン0は公開、右ボタン1は旗の切り替え、それ以外のボタンは何もしません。最初の右クリックも `Fresh` のままで、ゲーム側の仕様と一致します。

```sh
bend intermediate/minesweeper/nxn_pointer.bend
# 11
python3 intermediate/scripts/test_nxn_pointer.py
# PASS 19 pixel mappings and 28 N x N pointer traces
```

最初の出力 `11` は、10×10盤面の1番に地雷を置き、画面左上をクリックしたときの進行中の数字1です。テストでは、Bendの入力アダプターを実際に型検査・実行し、独立したPython座標変換と集合・BFSゲームモデルを照合します。旗、勝利後の入力凍結、盤外、未知のボタン、100×100の右下座標も有限ケースで確認します。

この部品は**画面を開きません**。`App.run` による描画、マウスイベントの実機受信、ウィンドウサイズ変更、GUI保存はまだ未検証です。入力の変換テストだけで「10×10 GUIが完成した」とは判断しません。

**演習：** 10×10盤面で `(639,0)` と `(0,639)` がそれぞれ何番になるか予想してみましょう。続いて、右下99番に旗を立ててクリックし、旗を外してからクリックした場合の勝敗を調べてみましょう。
