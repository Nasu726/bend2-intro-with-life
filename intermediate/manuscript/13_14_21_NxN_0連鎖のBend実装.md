# 第13・14・21章補稿：N×Nの0連鎖をBendで実装する

## なぜ1マスの公開だけでは足りないのでしょうか

マインスイーパーでは、周囲に地雷がないマス（数字0）を開くと、その周囲も公開されます。隣も0なら、さらに公開が広がります。単一マスしか開かない実装では、この操作感を再現できません。

先に作った nxn_step.bend はクリック・旗・敗北を扱い、nxn_neighbors.bend は盤面の端で回り込まない8近傍を列挙します。これらを組み合わせ、配置済みのN×N盤面に0連鎖を追加します。

## 具体的なBendコード

intermediate/minesweeper/nxn_flood.bend の中心は、処理待ちのマスを表す List<U32> と、残りの反復回数を表す Nat です。

~~~bend
def explore(fuel: Nat, +n: U32, task: Task) -> Task:
  match fuel:
    case 0n:
      task
    case 1n+k:
      match task:
        case Task{board, cells, pending}:
          match pending:
            case Nil{}:
              Task{board, cells, Nil{}}
            case index <> rest:
              explore(k, n, visit(n, index, rest, board, cells))
~~~

最初のクリックは Step.click に渡します。地雷なら Lost、旗のあるマスや盤外なら公開しません。安全な0が開かれたときだけ、Neighbors.neighbors のリストを追加します。探索中に見つけた旗・公開済みマス・地雷は開きません。Bendでは計算式をそのまま match の対象にできないため、U32.is_eq の結果を seed_zero の Bool 引数に渡して分岐します。

## 実行結果を予想して確かめましょう

~~~sh
bend intermediate/minesweeper/nxn_flood.bend --check-only
bend intermediate/minesweeper/nxn_flood.bend
python3 intermediate/scripts/test_nxn_flood.py
~~~

main は4×4盤面の15番に地雷を置き、0番をクリックしたあと、14番の表示を数値化します。期待値は11（地雷に隣接する公開済み数字1）です。独立照合スクリプトは、Pythonの座標ベースの近傍計算と幅優先探索を使い、Bendの公開結果と比較します。検証CIが成功する前は、期待値を実測結果と混同しません。

## 仕組み：なぜ止まるのでしょうか

新しく開いた0マスから追加する隣接マスは高々8個です。盤面の論理セル数は n*n 個なので、作業リストから取り出す回数は高々 1+8*n*n 回で抑えられます。Nat の燃料は毎回 1n+k から k へ減るため、再帰が停止します。

これは停止するための設計と有限ケースの実行検査です。全盤面での振る舞いを定理として証明したわけではありません。また、Wonへの状態遷移、Freshからの初手安全、GUIの実機操作、一般N×N運ゲー無し生成器は、この部品だけでは完成しません。
