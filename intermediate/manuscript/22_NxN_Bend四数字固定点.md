# 第22章補稿：四つ目の数字で確定情報を増やす（TeX・PDF未統合）

## なぜ三つの公開数字だけでは足りないのでしょうか

すでに三つの数字を反復するBendプログラムがあります。しかし、盤面には四つ以上の数字が公開されることもあります。既知の数字だけを調べて固定点に達しても、**後から公開された数字を加えれば新しい安全マスが確定する**ことがあります。

3×3のセル番号を上から `0 1 2 / 3 4 5 / 6 7 8` とします。公開数字 `(1,1), (2,0), (4,1)` の三つから、単独制約の反復で分かる安全マスは1・2・4・5番です。そこへ `(5,0)` を追加すると、さらに7・8番も安全だと分かります。

## Bendで四つの数字を反復してみましょう

リポジトリの `intermediate/minesweeper/nxn_public_four_fixpoint.bend` は、既存三数字版の `one_round` と `apply` を再利用します。新しい独立規則を作るのではなく、四つ目の公開数字へ**同じ一数字推論**を適用します。

```bend
import ./nxn_public_four_fixpoint.bend as Four
import ./nxn_public_three_fixpoint.bend as Fix

def main() -> U32:
  Fix.score(Four.infer_four(3, 1, 1, 2, 0, 4, 1, 5, 0,
                            Nil{}, [1, 2, 4, 5]))
```

`nxn_public_four_fixpoint.bend` 本体にも同じ結果を返す `main` があります。Bend 2を導入した環境で、リポジトリのルートから実行しましょう。

```sh
bend intermediate/minesweeper/nxn_public_four_fixpoint.bend --check-only
bend intermediate/minesweeper/nxn_public_four_fixpoint.bend
# 6
```

`6` は教材用の符号 `100 × 確定地雷数 + 確定安全マス数` であり、ゲームのスコアではありません。この例では確定地雷が0、既知安全が6マス（公開数字1・2・4・5番を含む）です。追加で安全と確定するマスは7・8番です。

## 四数字版の仕組みと限界

`one_round` は既存の三数字版の処理に四つ目の `Rule.infer` を接続します。確定した安全・地雷集合は `List<&2, U32>` に保持し、次の数字へ渡します。四数字の近傍から増え得る確定マスは最大32個なので、変化しない走査を含めて33回の燃料を設けます。上限に達してなお変化があれば `Limit` とし、成功扱いしません。

入力は互いに異なる四つの**実際に公開済みの数字**と、独立に正しさを確かめた既知の安全・地雷集合に限ります。公開数字の位置は最初から安全集合へ含めます。旗も未公開の真の地雷位置も根拠にしません。初期集合の重複や盤外要素がないことは呼び出し元の契約です。

これは**四つの単独数字規則の固定点**であり、任意個数の公開数字への対応、二数字・三数字の連立による完全推論、全盤面の充足可能性、一般N×N運ゲー無し生成を保証しません。局所規則で「これ以上進まない」ことと「安全手はもう存在しない」ことは異なります。

## 実装を検査してみましょう

`python3 intermediate/scripts/test_nxn_public_four_fixpoint.py` は、2〜10サイズの正常7局面と、不正入力・不可能な数字などの拒否5件について、独立PythonモデルとBendの返す**安全・地雷集合全体**を比較するための検証プログラムです。別途、`python3 -m unittest intermediate.tests.test_nxn_public_four_reference -v` は3×3の160局面について全候補地雷配置を独立列挙し、推論結果に誤った確定がないことを調べます。いずれも**有限検査**であり、一般N×Nの証明ではありません。

まず四つ目の数字 `(5,0)` を外した三数字版と比較してみましょう。次に四数字版へ初期確定地雷0番を渡し、追加で安全と分かるマスが増える理由を考えてみましょう。最後に、`(5,0)` を別の公開数字へ変え、実行前に推論結果を予想してから確かめてみましょう。

**統合状況**：この補稿とBendコードはリポジトリ内の検証候補です。型検査と実行照合が成功するまで検証済みとは呼びません。現行TeX本編・生成PDF・読者ZIPには未収録で、採用済み表紙と第7・8章は変更しません。
