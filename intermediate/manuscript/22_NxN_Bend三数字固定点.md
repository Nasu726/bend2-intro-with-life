# 第22章補稿：三つの公開数字をBend自身で反復する（TeX・PDF未統合）

## 手で確定集合を渡すだけでは何が不便でしょうか

`nxn_public_three_step.bend`では、0番の数字0から確定した安全マスを、次の2番・6番の推論へ手で渡していました。数字が増えると、確定集合を何度も書き直すのは大変です。今回は**Bend自身**に三つの公開数字を繰り返し調べさせます。

## 実行してみましょう

`intermediate/minesweeper/nxn_public_three_fixpoint.bend`は、公開数字 `(0,0), (2,1), (6,1)` を順に調べ、各手の`Safe`/`Mines`を次の手へ渡します。最初の`safe=[0,2,6]`は**すでに公開されている数字の位置**で、旗や隠し地雷配置ではありません。

```bend
def main() -> U32:
  score(infer_three(3, 0, 0, 2, 1, 6, 1, Nil{}, [0, 2, 6]))
```

```sh
bend intermediate/minesweeper/nxn_public_three_fixpoint.bend --check-only
bend intermediate/minesweeper/nxn_public_three_fixpoint.bend
# 206
```

`206`は地雷2マス・安全6マス（公開済みの3マスを含む）を`100*地雷数+安全数`で表した**この実習だけの符号**です。新たに確定した安全マスは1・3・4番、地雷は5・7番です。結果の集合そのものは`Propagation.Closure`の`mines`と`safe`で保持します。

## なぜ反復が止まるのでしょうか

各回で三つの公開数字を順に`Rule.infer`へ渡します。Bendの`List`はアフィンなので、`duplicate`で推論器に渡すリストと次の状態に残すリストを明示的に分けます。`NoMove`なら集合を変えず、`Safe`/`Mines`なら確定したマスを集合へ追加し、次の数字へ渡します。`Inconsistent`は矛盾・不正な局所入力として扱い、確定結果を返しません。

一つの数字の隣は高々8マスです。三数字から新たに確定できるマスの合計は高々24マスなので、**25回の走査**で必ず変化しない回に到達します。`Nat`の燃料を25として再帰を止め、最後の回にまだ集合が増えたなら`Limit`として失敗させます。探索上限に達した状態を「解けた」と取り違えないためです。

この実装は**三つの公開数字による単独制約の反復**です。三数字を連立して初めて得られる結論、盤面全体の充足可能性、一般のN×N運ゲー無し生成は保証しません。最初の確定地雷・確定安全は別途正しいことが前提で、**旗は証明になりません**。公開数字は互いに異なる位置にあり、初期集合は重複せず、全マスが盤面内であるという入力契約も必要です。

## 検証と演習

`python3 intermediate/scripts/test_nxn_public_three_fixpoint.py`は、公開数字から独立Python参照モデルが計算した確定集合と、Bendの`Closure`の**マス番号集合そのもの**を比較します。2〜10サイズの6局面と、公開位置の欠落・重複・範囲外・不可能な数字などの拒否5件、計11件を型検査・実行照合します。真の地雷配置はテストで公開数字を作るためにだけ使い、Bendの推論器には渡しません。有限テストを一般の証明と混同しないでください。

まず、公開数字を `(0,0), (2,1)` の二つだけにしてみましょう（その場合は別の二数字用関数を作ります）。次に、公開数字を三つのまま初期確定地雷5番を渡し、出力の地雷集合が変わらないことを確かめてみましょう。最後に、三数字のどれにも隣接しないマスを追加し、単独制約の反復だけでは確定できない理由を説明してみましょう。
