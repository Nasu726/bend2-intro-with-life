# 第13〜14・21章補稿：勝利したら入力を止めましょう

> **TeX本編・PDFには未統合**。ここで完成するのは、すでに配置済みのN×N盤面に対する「単一マス操作→勝利判定→終局」の接続です。初手安全移動と0連鎖は、この部品にはまだ接続していません。

## なぜ勝利判定だけでは足りないのでしょうか

前節の`nxn_victory.bend`は、安全なマスがすべて開いているかを判定します。しかし、判定結果が真でもゲーム状態が`Playing`のままなら、勝った後に地雷をクリックして負けてしまいます。判定器を使う側で、操作を受け付けない`Won`状態を明示する必要があります。

## Bendコードと実行結果

`minesweeper/nxn_terminal.bend`では、`Step.Session`を包む三つの状態を使います。

```bend
type State is Type:
  Playing{session: Step.Session}
  Won{session: Step.Session}
  Lost{session: Step.Session}

def click(state: State, +index: U32) -> State:
  match state:
    case Playing{session}:
      from_check(Victory.inspect(Step.click(session, index)))
    case Won{session}:
      Won{session}
    case Lost{session}:
      Lost{session}
```

2×2盤面の右下（添字3）に地雷を置き、0→1→2の順にクリックします。3以外のすべてのマスが開いたので`Won`になります。

```sh
bend intermediate/minesweeper/nxn_terminal.bend
# 111
```

`111`は勝利を示す100と、最後に開いた添字2の表示コード11（数字1）を足した検査用の値です。これは画面の表示形式ではありません。

## 仕組みを追いましょう

`Step.click`は地雷なら`Lost`、安全なら数字を一つ公開します。その直後に`Victory.inspect`がすべての安全マスを調べます。勝利条件を満たしたら`Won`で包み、満たさなければ`Playing`または`Lost`に分けます。次の`click`や`mark`は`Won`と`Lost`をそのまま返すので、終局後の操作は無効です。

判定器はゲーム内部でだけ地雷配置を読みます。公開情報から安全なマスを推論するソルバーへ地雷配置を渡すこととは異なります。実行照合`scripts/test_nxn_terminal.py`ではPythonの集合・座標計算を独立の期待値とし、勝利後の入力、敗北後の入力、旗、盤外操作も調べます。ただし有限ケースのテストであり、任意の操作列の全称証明ではありません。
