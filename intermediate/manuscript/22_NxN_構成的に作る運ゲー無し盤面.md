# 第22章補稿：N×Nで必ず作れる運ゲー無し盤面の一族

> 編集用補稿。配布TeX・PDF・ZIPには未統合です。対象は既存Bend N×Nエンジンの範囲 **10≤N≤100** で、地雷数を **N−1** に固定した構成族です。「任意の地雷数」「一様ランダム」「任意の盤面が必ず解ける」は保証しません。

## 必要性

4×4・地雷2個の全候補探索だけでは、10×10以上の運ゲー無し版を説明できません。しかし探索が重いことと、可解盤面が存在しないことは別問題です。まず任意のサイズで可解な盤面を**実際に作れる**ことを、構成と公開情報の推論で確かめます。

## Bendコード

新しい教材モジュールは \`intermediate/minesweeper/nxn_noguess_constructive.bend\` です。盤面を作る側だけが \`Words.MineWords\` を持ち、ゲームは既存の \`nxn_full_game.bend\` を利用します。

\`\`\`bend
# N×Nの最下段（または最上段）の左N−1マスに地雷を置く
def border(+n: U32, +row: U32) -> Words.MineWords:
  fill(U32.to_nat((n - 1 : U32)), n, row, 0, Words.new(n))

def generate(+n: U32, +first: U32) -> Construction:
  accepted(Bool.and(U32.is_lt(9, n), Geo.valid_index(n, first)), n, first)
\`\`\`

\`first\` の行が上半分なら地雷を最下段へ、下半分なら最上段へ置きます。右端1マスは地雷にせず残します。サイズと初手が範囲外なら \`Unsupported{}\` を返します。地雷数がN−1以外の設定を受け取って黙って置き換えるAPIではありません。

## 実行結果と検証の境界

\`\`\`sh
bend intermediate/minesweeper/nxn_noguess_constructive.bend
python3 intermediate/scripts/test_nxn_noguess_constructive.py --static-only
\`\`\`

最初のBend実行での**期待出力は \`111\`** です。これは10×10・初手0・最後の安全マス99を開いて勝利状態になったことを表すゲームのsnapshot値です。ただし \`demonstration\` は生成器が答えを知って操作する**ゲーム動作テスト**であり、ソルバーが答えを導いた証拠ではありません。

独立Python検査はN=10〜100の全91サイズについて初手637条件をテストし、実際の0連鎖による公開状態から、**真の地雷集合を引数に持たない** \`infer_from_public\` で最後の安全マスを導きます。Bendの型検査・実行・CIについては、実際の検証成功が確認されるまでは未検証です。

## 仕組み：Nがいくつでも成り立つ構成的証明

最下段を選んだ場合を示します。最下段の列0〜N−2に地雷を置き、列N−1だけを安全にします。初手は最下段から十分離れているため0で、0連鎖によって最下段以外の全マスが公開されます。最下段の右端だけが未公開の安全マスとして残ります。

その一つ上の段の公開数字を左から読むと、**2、3、3、…、3、2、1** となります。最初の2は、隣接する最下段の2マスがともに地雷であることを確定します。次の3は、既知の2地雷に加えて、その右の1マスも地雷であることを確定します。これを繰り返すと列N−2まで地雷だと確定します。

最後から2番目の公開数字2には、すでに確定した2地雷が隣接しています。残った右端の未公開マスは、**地雷である余地がないため安全**です。これを開けば全安全マスが公開され、勝利します。最上段の場合も上下を反転して同様です。この推論では真の地雷配置も、プレイヤーが置いた旗も参照しません。Nの上限100は現在のBendゲームエンジンの実装制限であり、この構成の数学的な制限ではありません。

## 演習

N=10で初手を99に変えると、地雷のある段と最後の安全マスはどこになるか考えてみましょう。次にN=11、N=20へ変え、地雷数がN−1であることを確認してみましょう。公開数字の最初の2から順に確定地雷を増やし、最後の安全マスを**真の盤面を見ずに**求めてみましょう。

## まだ必要な一般化

この構成は**任意N・任意初手**の存在証明付き実装候補ですが、地雷数はN−1に固定されています。一般の地雷数Mで可解盤面を探す探索器、公開情報からBend自身が証明書を生成する機能、GUIへの切替、配布TeX/PDF/ZIP統合は引き続き未完成です。探索上限による不採用を数学的な不可能性の証明と取り違えてはいけません。
