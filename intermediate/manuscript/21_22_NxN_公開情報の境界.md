# 第21〜22章補稿：盤面の正解を隠して公開情報だけを取り出す

> **TeX本文・PDFには未統合**。ここではN×Nのゲーム本体から公開情報を作る境界を扱います。Bend版N×Nソルバー・運ゲー無し生成器はまだ実装していません。

## なぜ公開情報の型を分けるのでしょうか

前節の`nxn_full_game.bend`は、初手の地雷移動、0連鎖、勝敗まで動くようになりました。しかし、ゲームの内部状態`Step.Session`をそのままソルバーへ渡すと、`mines`に正解の地雷位置が含まれています。これでは「推測せずに解いた」とは言えません。

そこで、**開いた数字・旗・盤面サイズ・進行状態だけ**を取り出します。旗はプレイヤーの推測であり、真の地雷として扱ってはいけません。

## 小さなBendコードを動かしましょう

`minesweeper/nxn_public_view.bend`では、外部へ返す型を次のように定義します。

```bend
type Seen is Data:
  Open{index: U32, clue: U32}
  Flag{index: U32}

type Observation is Data:
  Observation{n: U32, status: U32, seen: List<&2, Seen>}
```

`Observation`には`MineWords`も`Array`も含まれません。`observe`はゲーム状態を消費して公開情報へ変換し、隠れた地雷位置を返しません。

```sh
bend intermediate/minesweeper/nxn_public_view.bend
# 8
```

3×3盤面の右下に地雷を1個置き、左上を開くと、0の連鎖によって安全な8マスが公開されます。結果の`8`は、`Observation`の公開マス数です。

## 仕組みを追いましょう

`collect`は`Nat`の燃料を1ずつ減らしながら、論理マス`n*n-1`から0までを調べます。配列の余剰領域は読まず、見えない`Hidden`は出力から除外します。逆順に走査してリストの先頭へ追加するので、公開マスは添字の昇順に並びます。

`Fresh`では公開マスは空、`Playing`・`Won`・`Lost`では現在の表示だけを返します。勝敗は公開情報ですが、正解の地雷位置は公開しません。これは**データ型による受渡しの境界**であり、任意のコードが別途ゲーム本体をimportすることまで防ぐセキュリティ機構ではありません。

`scripts/test_nxn_public_view.py`は、Bendの出力を独立Python集合・BFSモデルから計算した表示内容と比較します。小盤面の全表示、旗、開始前、勝敗、大きな盤面の一部を有限49ケースで検査します。100×100の全面走査性能や任意の操作列についての全称保証はまだありません。

## 演習

1. 3×3盤面で右下に地雷を置き、左上を開いた後の`Open`を添字順に書いてみましょう。
2. 開く前に旗を付けたとき、その旗を「確定した地雷」とみなしてはいけない理由を説明してみましょう。
3. `Hidden`を公開情報から省いても、ソルバーが未公開マスを求められる理由を考えてみましょう。
4. 次はこの`Observation`と総地雷数を入力にして、**真の地雷位置を見ずに**確定安全マスを返す関数を作ってみましょう。
