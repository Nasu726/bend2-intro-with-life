# 第13・14・21章補稿：初手のクリック後に盤面を導出する

## なぜ最初に盤面を作らないのでしょうか

初手が必ず安全であるなら、開始前から地雷位置を固定し、クリックが地雷なら移す方式ではなく、**クリック位置が確定したとき初めて地雷を置く**設計にしましょう。開始前の状態は盤面サイズ・地雷数・再現用シードのみです。初手で公開するマスを地雷候補から除外します。初手前の旗や無効なクリックでは盤面を導出しません。

## Bendコードと実行例

新しいリポジトリ内の教材 `minesweeper/nxn_lazy_game.bend` の状態型です。

```bend
type Game is Type:
  Fresh{n: U32, count: U32, seed: U32}
  Active{state: Terminal.State}
  Invalid{}
```

`new(10,10,20261028)` は地雷を生成しません。最初の有効な `click` が `generate` を呼び、選ばれたマスを除いた99マスに地雷10個を置きます。Bendの `main` は `snapshot(click(new(10,10,20261028),0),0)` です。**出力の正確な数値はBend実行照合が完了してから記録します**が、初手は必ず安全で、敗北状態200台にはなりません。

## どのような仕組みでしょうか

`m=n*n-1` 個の候補を `0..m-1` と番号付けし、`m` と互いに素な歩幅 `stride` で `(offset+i*stride) mod m` を順に訪れます。同じ番号を2回訪れず、選んだ番号がクリック位置以上なら1加算すれば、初手以外のマスへ厳密に地雷数だけ配置できます。ゲーム開始後に地雷を移動させることはありません。公開・0連鎖・勝敗は既存のN×Nエンジンを使います。

この方式は**再現可能な配置順序**であり、一様乱数の保証も、運ゲー無しの保証もありません。運ゲー無しは生成済み盤面について公開情報だけで勝利できる証明書を別途必要とします。従来の固定盤面 `nxn_full_game.bend` は内部テスト資産として保持し、正式GUIのプレイ入口は今後置換します。

- シードとクリック位置を変えた場合の盤面の違いを比較してみましょう。
