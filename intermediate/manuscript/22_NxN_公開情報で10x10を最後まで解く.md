# 第22章補稿：10×10の公開情報から安全な二手目を選びましょう（TeX・PDF未統合）

## ゲームが動くことと、推測せずに解けることは違います

第21章の10×10ゲームは、地雷の列で分かれた二つの領域を0番、99番の順に開くと勝利します。しかし、この二手目を**隠れた地雷配置を知っているから選んだ**のなら、運ゲー無しとは言えません。そこで、ゲームから取り出した公開数字だけを推論器へ渡し、二手目が本当に確定安全か調べてみましょう。

## 既存のBendゲームを動かしましょう

`intermediate/minesweeper/nxn_playthrough.bend` の中心部分は次のとおりです。地雷の真値は `mine_wall` とゲーム本体だけが保持します。

```bend
def main() -> U32:
  game = Game.new(mine_wall(Words.new(10)))
  game = Game.click(game, 0)
  game = Game.click(game, 99)
  Game.snapshot(game, 99)
```

```sh
bend intermediate/minesweeper/nxn_playthrough.bend
# 110
```

出力 `110` は、勝利の `100` と99番の公開数字0を表す `10` の合計です。**このBendコード自体は二手目を推論していません。** 次のPython参照実装で、その不足を確かめます。

## 公開情報だけを渡して再生しましょう

`intermediate/solutions/nxn_public_replay_bridge.py` は、既存のPythonゲーム参照モデルと公開情報推論器を接続します。推論器に渡すのは盤面サイズ、総地雷数、公開された `(添字, 数字)` の組、旗だけです。**真の地雷集合は渡しません。** 参照コードとテストはリポジトリに置き、読者用ZIPには解答・検証用コードを混ぜません。

```sh
python3 intermediate/solutions/nxn_public_replay_bridge.py
```

```text
highest: Replay(status='won', clicks=(0, 99), opened_count=90)
certificate: True
lowest: Replay(status='limit', clicks=(0, 60, 61, 62, 63, 64, 65, 66), opened_count=57)
```

0番を開くと、上側50マスが公開されます。行番号4の数字は左端・右端が2、中央8マスが3です。地雷の総数は10個で、未公開の50〜59番だけがこの数字のすぐ下にあります。**この十マスの全 `2^10=1024` 通りを独立に列挙**すると、公開数字に整合する地雷集合は `{50,...,59}` の一つだけです。したがって60〜99番はすべて確定安全です。

確定安全のうち最大番号99を選ぶと、下側の0連鎖が40マスを公開して勝利します。証明書 `(0,99)` を再生する `verify` は、最初のクリックを除く各クリックが、その時点の公開情報から確定安全であることと、最終的に `Won` へ達したことを検査します。

一方、確定安全の**最小番号**を毎回選ぶと、60〜66番を順に開いた段階で、連結した未公開の制約領域が探索上限18マスを超えます。結果は `limit` であり、`contradiction` でも `Won` でもありません。安全な手を選んでも、**次に開くマスの順序で探索の難しさが変わる**ことが分かります。

## 仕組みと保証の境界

ゲーム側の `Game.click` は地雷の真値を使って公開数字と0連鎖を更新します。一方、`infer` が受け取るのは `Game.public_view` の情報だけです。二つを混同すると「正解を知っているソルバー」を作ってしまいます。初手安全はゲームの地雷移動規則であり、二手目以降の確定安全推論とは別です。既存の候補生成器 `nxn_candidate_generator.py` は、候補をそのまま使うため**初手が地雷の配置を拒否**します。一方、この再生例はゲーム側の初手地雷移動も扱います。両者の受理条件は同じではありません。

この例は**固定した10×10・地雷10個の盤面**についてのPython参照統合です。既存のBendゲームのクリック列は実行照合済みですが、**BendのN×N推論器とゲームを自動接続したものではありません**。また `verify` は `solve` と同じPython推論器を使うため、独立した全称証明ではありません。独立性を補うのは10マスの全1,024配置の列挙と、小盤面での有限テストです。一般N×Nの運ゲー無し生成、10×10 GUI実機操作、任意局面の保証は未完成です。

## 演習

1. 0番を開いた直後の数字を使い、50〜59番のどこに地雷があるか紙に書いて確かめてみましょう。
2. `selection="lowest"` と `selection="highest"` の結果を比べ、どちらも**確定安全なマスだけ**をクリックしているのに結果が違う理由を説明してみましょう。
3. `max_frontier=9` に変更し、探索上限を超えた場合に `limit` となり、勝利証明書を受理しないことを確かめてみましょう。
4. `python3 -m unittest discover -s intermediate/tests -p 'test_nxn_public_replay_bridge.py' -v` を実行し、3×3の全4,599初手ケースと10×10の固定例の検査を確かめてみましょう。
