# 第22章補稿：N×Nで確定手を見つける（Python参照実装・PDF未統合）

4×4・地雷2個の候補をすべて列挙する方法は、盤面が大きくなると使えません。
しかし、10×10の盤面でも、公開された数字に隣接する未公開マスは少数のことがあります。
**盤面全体の配置ではなく、数字に接する境界（frontier）だけを列挙**すると、
公開情報から確定手を探せます。ここではBendへ移植する前に、独立した
Python参照実装 `intermediate/solutions/nxn_public_inference.py` で契約を確認します。

## 0の数字を見たとき、どこまで安全でしょうか

10×10の左上0番を開き、表示された数字が0、地雷総数が10個だとします。
周囲の1・10・11番は必ず安全ですが、離れた50番は安全とは限りません。
次の実行例では**真の地雷配置を一切入力しません**。

```python
from nxn_public_inference import infer
print(infer(10, 10, ((0, 0),)))
print(infer(10, 10, ((0, 0),), max_frontier=2))
print(infer(10, 0, ((0, 1),)))
```

`PYTHONPATH=intermediate/solutions python3` を起動して上のコードを入力すると、
次の結果になります。

```text
Inference(status='ok', safe=(1, 10, 11), forced_mines=())
Inference(status='limit', safe=(), forced_mines=())
Inference(status='contradiction', safe=(), forced_mines=())
```

`ok` は公開情報と矛盾しない配置があること、`limit` は探索上限に達したこと、
`contradiction` は整合する配置がないことを表します。`ok` で `safe=()` の場合は
確定手が見つからないだけで、推測クリックを許可する意味ではありません。

## 数字の近くと、それ以外を分けます

公開された数字に隣接する未公開マスを frontier と呼びます。
`infer` は frontier の地雷有無だけを最大18マス（既定値）まで列挙し、
各数字と一致するか、残りの地雷を frontier の外へ置けるかを検査します。
その結果、すべての整合配置で安全なマスだけを `safe` に返します。
frontier の外も、**残りの地雷数が必ず0**ならすべて安全だと確定できます。
反対に残りの地雷数が常にその領域のマス数と等しければ、すべて地雷です。

旗はプレイヤーの推測かもしれないため、**旗があることを地雷の証拠にしません**。
旗付きマスも候補として計算しますが、`safe` にはクリック対象として返しません。
入力は盤面サイズ・総地雷数・公開済みの `(添字, 数字)`・旗だけです。
真の地雷集合、未公開マスの数字、ゲーム内部状態は参照しません。

`python3 -m unittest discover -s intermediate/tests -p 'test_nxn_public_inference.py' -v`
で4つのテストを実行できます。2×2はすべての地雷配置・安全マスの公開部分集合・
旗の部分集合を照合し、3×3は全512配置それぞれから固定乱数で公開状態を抽出します。
期待値は frontier を使わず**盤面全体の候補配置を列挙する別実装**で計算します。
10×10・100×100の境界、矛盾入力、探索上限も検査します。
これは有限なPythonテストであり、BendのN×Nソルバー、盤面生成器、
GUI、全称証明が完成したことを意味しません。

## 演習

10×10で0番が数字0のとき、1・10・11番が安全である理由を
座標を使って説明してみましょう。次に総地雷数が0個なら、
50番まで安全と分かる理由を考えてみましょう。
最後に1番へ誤って旗を置いた場合、旗を真の地雷とみなす推論と、
公開数字だけを根拠にする推論で何が変わるか確かめてみましょう。

**次の工程**は、Bendで公開ビューからfrontier制約を作る部分と、
