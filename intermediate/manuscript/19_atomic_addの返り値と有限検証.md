# 第19章補稿：atomic.addの「戻り値」と「配列の中身」を分けて読む

> 本編第19章にはすでに `51_atomic_counter.bend` と実行結果 `5`、`8`、演習を掲載しています。この補稿は既存の説明を置き換えるものではなく、追加の実行照合と、その保証範囲を記録する編集用資料です。読者ZIPには収録しません。

## 必要性：更新前と更新後を取り違えない

複数の処理で共有配列を更新する前に、まず順次実行で `Array.atomic.add` の返り値を理解しましょう。「3を加えた」という事実と「APIが返した数値が8である」という推測は別です。`Array.atomic.add` が返す数値は**更新前の値**であり、更新後の値を知るには、返された配列を使って `Array.get` で読み直します。

## Bendコードと予想

配布済みの `examples/51_atomic_counter.bend` は次の式を使います。

```bend
show_values(Array.atomic.add(Array.new(U32, 1n, 5), 0, 3))
```

```text
5
8
```

第1行は `Array.atomic.add` が返す旧値、第2行は続く `Array.get` で読み直した値です。`Array.new(U32, 1n, 5)` は要素数が `2^1 = 2` の配列を作り、0番を更新します。元のサンプルは共有配列の並列競合を発生させません。

## 予想を六通りで検査する

編集用テスト `scripts/test_atomic_exercises.py` は学習用ファイルを一切変更せず、一時フォルダーで初期値と加算量だけを置き換え、各プログラムをBendで型検査・実行します。照合する期待出力は次の通りです。

| 初期値 | 加算量 | 1行目：旧値 | 2行目：更新後 |
| ---: | ---: | ---: | ---: |
| 5 | 3 | 5 | 8 |
| 5 | 0 | 5 | 5 |
| 0 | 7 | 0 | 7 |
| 0 | 0 | 0 | 0 |
| 12 | 17 | 12 | 29 |
| 99 | 1 | 99 | 100 |

```sh
python3 intermediate/scripts/test_atomic_exercises.py --static-only
python3 intermediate/scripts/test_atomic_exercises.py
```

最初のコマンドはサンプルの構造と変種の生成条件だけを検査します。二つ目はBend 2が必要で、**型検査と実行結果が成功した場合にのみ**六条件の有限受入検査と呼べます。この6条件は検証PR #129の全CI成功後に正本へ統合済みです（正本コミット \`3827f74a\`）。ただし、有限条件から一般の原子性を推論することはできません。

## 仕組み・限界・演習

`Array.atomic.add` の返り値の組には更新後の配列と更新前の要素値が含まれます。`Array.get` も配列と値を返すので、元のプログラムは組を関数の引数で受け取り、配列を二重消費しないようにしています。六条件の順次実行が成功しても、`Array.fork` で共有した複数ワーカー間の競合が正しいこと、GPUでの原子的更新、`U32` のオーバーフロー境界、あらゆる配列添字の正しさは証明できません。

**演習：** 初期値9・加算量2なら二行はどうなるか予想してから試してみましょう。続いて加算量を0にしたとき、旧値と更新後の値が同じになる理由を説明してみましょう。最後に、なぜこの実験を「並列の原子性を実証した」と呼べないのか考えてみましょう。

## 二つのセルを続けて更新するとどうなるか（追加検証候補）

同じ配列の0番に3を加えた後、1番に7を加えた場合、**二回目の戻り値も更新前の値**です。0番と1番は別のセルなので、初期値がともに5なら次のようになります。

```bend
show_first_old(Array.atomic.add(Array.new(U32, 1n, 5), 0, 3))
# show_first_oldの中で Array.atomic.add(array, 1, 7) を実行
```

```text
5
5
8
12
```

順番に、0番の旧値、1番の旧値、0番の最終値、1番の最終値です。反対に二回目も0番へ7を加えると、`5, 8, 15, 5` になります。二つのセルの読み戻しには、更新後の配列を`Array.get`から次の`Array.get`へ渡す必要があります。

リポジトリ専用の`scripts/fixtures/atomic_two_cells.bend`を`scripts/test_atomic_exercises.py`で六通りに変形し、Pythonで独立に計算した四つの値とBendの出力を照合します。**この追加六条件は検証PRのBend型検査・実行が成功するまで未検証です。** 共有配列への同時書き込みやGPU上の競合は検査していません。

**演習：** 二回目の加算先を0番に変えて、四行の値を予想してから試してみましょう。続いて二回目の加算量を0に変え、なぜ旧値と最終値が一致するか説明してみましょう。
