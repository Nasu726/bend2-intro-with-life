## この節でできるようになること

隠れたマスを適当に開くのと、**絶対に地雷ではないと分かって開く**のは違います。この節では、画面の数字を小さな制約に書き直し、確実に安全なマスを見つける手順を練習します。

最初は一つの数字、次は二つの数字、最後は盤面全体の候補配置を考えます。最初から全列挙の実装を読まなくても構いません。

### 1. 数字の「1」は、どこまで教えてくれるでしょうか

開いたマスに「1」が表示され、その周囲に未確定のマスが三つだけ残ったとします。

```text
    ?  ?  ?
       1
```

この図は隣接関係だけを抜き出した模式図です。「?」が三つとも同じ数字の周囲にあると考えてください。三つのうち地雷はちょうど一つですが、**どれが地雷かは決まりません**。一つを選んで開くことは推理ではなく推測です。

一方、別の数字からそのうち一つが地雷と確定したらどうでしょう。表示数字を `c`、すでに地雷と確定した周囲のマス数を `f`、まだ分からない周囲のマス数を `u` とすると、残りの地雷数は

```text
r = c - f
```

です。たとえば `c=1, f=1, u=2` なら `r=0`。未確定の二つは両方とも安全です。反対に `c=3, f=1, u=2` なら `r=2` で、未確定の二つは両方とも地雷です。

ここでいう「確定」は、**公開情報から論理的に地雷だと導いた**という意味です。プレイヤーが置いた旗を、検証なしに地雷と同一視してはいけません。

### 2. Bendで四つの結果を区別する

本書の `14_local_inference.bend` は、`remaining: U32`（残り地雷数）と `unknown: U32`（未確定の個数）から、次の値を返します。

| 条件 | 結果のコンストラクタ | 意味 |
| --- | --- | --- |
| `remaining=0` かつ `remaining<=unknown` | `AllSafe{}` | 未確定マスはすべて安全 |
| `remaining=unknown`、ただし `remaining>0` | `AllMines{}` | 未確定マスはすべて地雷 |
| `0<remaining<unknown` | `Unknown{}` | この数字だけでは決められない |
| `remaining>unknown` | `Inconsistent{}` | 与えた情報が両立しない |

`unknown=0, remaining=0` では `AllSafe{}` が返りますが、そもそも判定対象のマスがありません。「新しい安全マスを発見した」という意味にはなりません。

まず次を実行してみましょう。

```sh
bend examples/14_local_inference.bend
```

実行前に値を予想してください。このファイルの `main` は四つの推論結果を数値へ変換して足します。`tag` の対応は `AllSafe=1`、`AllMines=2`、`Unknown=3`、`Inconsistent=4` です。

| 呼び出し | 結果 | `tag` |
| --- | --- | ---: |
| `infer(0, 3)` | `AllSafe{}` | 1 |
| `infer(3, 3)` | `AllMines{}` | 2 |
| `infer(1, 3)` | `Unknown{}` | 3 |
| `infer(4, 2)` | `Inconsistent{}` | 4 |

したがって出力は **`10`** です。コードの戻り値が一つの `U32` なのは、テストしやすい数値へ変換しているためです。実際のソルバーでは、この整数ではなく `LocalRule` の四種類を `match` して次の処理を選びます。

この例の `law zero_remaining_is_safe_for_three` は **`infer(0,3)` という特定の入力**を扱います。盤面全体が正しく解けることを証明したわけではありません。

**引き算を始める前の注意：** `c < f` は数字と確定情報が矛盾しています。`r=c-f` を無符号整数の `U32` で計算する前に、必ずこの場合を弾く必要があります。また、同じ未確定マスを二度数えないようにします。`infer` 自体は、すでに計算した `remaining` と `unknown` を受け取るだけなので、この前処理までは担当しません。

### 3. 二つの数字を合わせると、手掛かりが増える

今度は未確定マス `x, y, z` について、二つの公開数字から次の情報が分かったとします。

```text
制約 A:  x と y の中に地雷はちょうど1個
制約 B:  x と y と z の中に地雷はちょうど1個
```

この二つは互いに矛盾していません。どちらも `x` と `y` の地雷位置は決められませんが、集合 `B={x,y,z}` から `A={x,y}` を差し引くと `B\A={z}` です。

```text
Aの地雷数             = 1
Bの地雷数             = 1
Bにだけある z の地雷数 = 1 - 1 = 0
```

よって **`z` は必ず安全**です。`x` と `y` のどちらに地雷があるかは依然として不明ですが、`z` を開くためには知る必要がありません。

同じ `A={x,y}` の地雷数が1で、`B={x,y,z}` の地雷数が2なら、`z` は地雷です。一般には `A ⊆ B` のとき、`B\A` 内の地雷数は **`b-a`** と求まります。ただし、集合に重複がなく、両制約が同じ盤面状態に基づき、地雷数の条件が整合していることが前提です。

こうした差集合の計算に `Set` が使えます。ただし、`Set` を使う目的は集合演算を理解しやすくすることであり、単に三つの番号を比べるだけなら `List` などでも十分です。標準構造は必要な問題に合わせて選びましょう。

### 4. 盤面全体の候補を使って「必ず」を確かめる

数字が複数になると、集合の差だけでは安全なマスを見つけられないことがあります。そこで、**公開情報と矛盾しないすべての地雷配置**を考えます。

手で確かめられる例として、4×4盤面に地雷が合計1個あり、左上のマス（添字0）を開いたら数字1だったとします。残りの15マスは未公開です。左上に隣接する添字は `1,4,5` の三つだけなので、可能な地雷配置は

```text
候補1: {1}
候補2: {4}
候補3: {5}
```

の三つです。どの候補でも添字15は地雷ではありません。したがって、**15は確実に開けます**。反対に1を開くのは推測です。こうして「すべての候補に共通する安全マス」を探します。

もう一つ大切なのは、候補が0個だったときです。それは **入力が矛盾している**という意味です。「すべての候補で安全」という論理式が形式上成り立っても、候補が空のまま安全と認定してはいけません。

参考実装 `intermediate/solutions/noguess_reference.py` の `Visible` には幅・高さ・総地雷数・開いたマスの数字しかありません。`provably_safe(view)` は `consistent_models(view)` で作った候補だけを見ます。**本当の地雷配置を参照して推理していない**ことを、関数の引数から確認できます。

小盤面なら候補をすべて列挙できますが、候補数は盤面の大きさに応じて急増します。探索上限に達したときは「検証不能」とし、「安全」と取り違えません。

### 5. 運ゲー無し盤面を採用するまで

盤面を作る側は本当の地雷位置を知っています。一方、プレイヤーに相当するソルバーは、公開済みの数字と地雷の総数しか知らない状態で進めます。

1. 初手が安全な盤面を一つ作ります。
2. 最初のマスを開き、数字が0なら連鎖公開します。
3. ソルバーが公開情報のみから安全な未公開マスを一つ見つけます。
4. ゲーム本体がそのマスを開き、新しい数字を公開します。
5. 安全なマスをすべて開くまで3〜4を繰り返せたら採用します。確実な手がなくなれば、その候補盤面は不採用です。

ここで保証しているのは「**その初手とそのソルバーで、推測しないで勝てた**」ことです。採用されなかった盤面があらゆる方法で解けないと証明したわけではありません。

参考Python実装は小盤面用の独立検証器です。**Bendで運ゲー無し盤面の生成・プレイ機能が完成したことを意味しません。** 今回はまず、Bendのデータ型と標準の集合・リストを使って、公開情報から確実な一手を選ぶ理由を説明できるようになりましょう。

2. `A={x,y}` に地雷が一つ、`B={x,y,z}` に地雷が二つあるとします。`z` について分かることを、引き算を使って説明してみましょう。
3. 4×4で地雷1個、左上の数字1という例について、添字 `1,4,5,15` のうち確実に安全なものを選び、残りを開けない理由を説明してみましょう。
4. すでに地雷と確定した周囲のマスが2個なのに、表示数字が1だった場合、`infer` を呼ぶ前に何を検査するべきか説明してみましょう。
5. 「旗を置いたマスを確定地雷として数える」「ソルバーに真の地雷配置を渡す」のどちらも避ける理由を、他の人へ説明してみましょう。
