# 第22章補稿：一つの数字から確定した情報を、次の数字へ渡す（TeX・PDF未統合）

## 一度の推論だけでは、なぜ足りないのでしょうか

公開数字が0なら、その隣はすべて安全です。ところが、その安全マスが分かったことで、**別の公開数字**の周囲に残る未知マスが一つになり、地雷が確定することがあります。一つの数字を調べて終わりにせず、確定した情報をほかの数字へ伝えてみましょう。

3×3盤面を行優先で0〜8番とし、**公開済みの数字**を `(0, 0)`, `(2, 1)`, `(6, 1)` とします。地雷の真の配置は推論器に渡しません。

## Bendの一数字推論を確認しましょう

`intermediate/minesweeper/nxn_public_local.bend` の既存の一数字推論は、隣接する確定地雷の数を公開数字から引き、残りの未知マスが全部安全か全部地雷かを判定します。

```bend
# 0番の数字は1。1番が別途証明済みの地雷なら、3・4番は安全。
def main() -> U32:
  tag(infer(3, 0, 1, [1], Nil{}))
```

```sh
bend intermediate/minesweeper/nxn_public_local.bend
# 1
```

`1`は`Safe`という判定のタグです。`1`番に旗を置いただけでは、`[1]`を確定地雷として渡せません。この実装は**一回分**の推論であり、ほかの公開数字へ結果を自動伝播するものではありません。

## Python参照実装で確定情報を伝えてみましょう

複数の数字を反復する参照実装を `intermediate/solutions/nxn_single_clue_propagation.py` に用意しました。次のコードは `intermediate/solutions/` で実行します。

```python
from nxn_single_clue_propagation import infer_single_clue_certainties

opened = ((0, 0), (2, 1), (6, 1))
mines, safe = infer_single_clue_certainties(3, opened)
print(mines)
print(safe)
```

```text
(5, 7)
(1, 3, 4)
```

最初に0番の数字0から、1・3・4番が安全と分かります。続いて2番の数字1を見直すと、周囲の1・4番は安全なので、残る5番が地雷です。同様に6番の数字1から7番が地雷になります。確定集合が増えなくなるまで繰り返すため、同じ入力に同じ確定集合をもう一度与えても結果は変わりません。

## 仕組みと保証の範囲

各数字について、`残りの地雷数 = 表示数字 − 隣接する確定地雷数` と計算します。残りが0なら周囲の未知マスはすべて安全、残りが未知マスの個数と等しければすべて地雷です。それ以外は**推測せず保留**します。新たな確定情報を全数字へ伝え、矛盾があれば`ValueError`とします。

この推論は、**公開数字が真実であり、最初の確定地雷・確定安全マスが別途正しく証明されている**ことを前提とします。旗は証拠ではありません。また、局所矛盾がないことは、盤面全体に整合する配置が存在する証明ではありません。二数字の重なり推論や三数字の連立推論も、ここでは自動的には行いません。

独立したPythonテストでは、3×3盤面の240局面について、初期の証明済み集合を固定した**全候補配置**を別実装で列挙し、伝播した確定地雷が全候補で地雷、確定安全が全候補で安全であることを検査します。これは有限検査であって一般N×Nの全称証明ではありません。Bendの一数字実装は既存の別テストで型検査・実行照合します。**反復部分はPython参照実装であり、Bendの反復推論器を完成させたわけではありません。**

## Bendの局所規則とPython証明書を一手ずつ照合する

Pythonで生成した証明書の各手が、Bendの`nxn_public_local.bend`でも
**同じマス番号**を確定できるか確認してみましょう。判定タグだけの比較では、
`Safe`の中身を取り違えても見逃してしまいます。

たとえば3×3で0番と1番の両方が公開済みの数字0なら、0番の未知の隣接マスは
3・4番だけです。Bendの一数字関数は公開済み一覧を直接受け取らないので、
公開済みのマスも「すでに安全と分かっている集合」に含めて渡します。

```bend
# 0番・1番は公開済み。1番を未知マスとして再発見しない。
Rule.infer(3, 0, 0, Nil{}, [0, 1])
# Safe{indices: [3, 4]}
```

`Rule`は`nxn_public_local.bend`のimport名です。実際の型検査・実行では
`intermediate/scripts/test_nxn_single_clue_witness_bridge.py`が
Bendの比較プログラムを生成します。各証明書の手の直前の確定地雷と確定安全に
公開済みのマスを足して`Rule.infer`を呼び、
`Safe`/`Mines`の**種類と昇順の番号列**をPython証明書と照合します。

```sh
python3 intermediate/scripts/test_nxn_single_clue_witness_bridge.py
# PASS 14 Python witness steps reproduced by Bend local inference
```

2×2・3×3・4×4・5×5・10×10の6局面、計14手を照合します。
局面の真の地雷は**テスト用の公開数字を計算するためだけ**に使い、
BendやPythonの推論器には渡しません。型検査と実行の両方を通します。
ただし、このテストはBendが**反復処理を実装した証明**ではありません。
反復と証明書の組立ては引き続きPython参照実装が担当しています。
