# 第15・16章補稿：法則・証明と実行の違いを試す

## 必要性
第15章の「二度旗を切り替えると元へ戻る」は、何もしない実装を排除できません。別の法則を追加し、本当に意図した振る舞いになっているか調べる必要があります。第16章では、単にプログラムの出力が変わったことと、全自然数に対する法則が証明されたことを区別します。

## 実コード・試す順番
配布済みの `04_flag_laws.bend` と `33_nat_induction.bend` は書き換えず、一時コピーで試します。

1. `04_flag_laws.bend` 末尾に `law hidden_is_marked: {toggle(Hidden{}) == Marked{} : Cover}` と `def hidden_is_marked(): {==}` を通常のBendの行・インデントに展開して追加し、`bend ... --verdict` の結果を確かめます。
2. `toggle` の `Hidden{}` 分岐を意図的に `Hidden{}` のままにして、不正な実装が法則検証を通過しないか確かめます。
3. `33_nat_induction.bend` の `main` の返値を `0` から `1` へ変えます。実行値は1に変わりますが、`times_zero` の証明は変わりません。
4. `%times_zero(p)` の帰納法の仮定を使う行を外し、法則証明が失敗するか確かめます。

各ケースは `scripts/test_proof_exercises.py` がBendの `--check-only`、実行、`--verdict` の該当する組み合わせを検査します。CI成功を確認するまでは全件成功と報告しません。失敗する例では「`ALL PROOFS CHECK` を得られない」ことを要求しますが、どのメッセージを出すかはBendバージョンに依存するため固定しません。

## 仕組み・範囲
`--verdict` が確かめるのは書かれた `law` であり、プログラム全体の仕様が十分であるという保証ではありません。帰納法の例では、`main` の結果が1になることと `Nat.mul(x,0n)==0n` が任意の `Nat` に対して証明済みであることは両立します。

## 演習
`hidden_is_marked` の法則を追加した後、`Marked{}` からの切替も独立に指定する法則を考えてみましょう。次に `main` の戻り値だけを変更したときに `--verdict` の結果が変わらない理由を説明してみましょう。最後に「型検査に成功」「特定入力で実行成功」「法則の証明に成功」を別々の表現で記録してみましょう。
